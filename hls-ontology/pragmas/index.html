HLS Pragmas Reference

Comprehensive reference for Vitis HLS pragmas organized by category.

Quick Reference

Category Pragmas

Task Parallelism DATAFLOW, STREAM
Interface INTERFACE (m_axi, s_axilite, axis, ap_fifo, etc.)

Loop Optimization

PIPELINE

Pipeline a loop or function to improve throughput.

#pragma HLS PIPELINE [II=<N>] [rewind] [off]
Parameter Description
II=<N> Initiation Interval - cycles between loop iterations (default: 1)
rewind Enable continuous execution without pipeline flush
off Disable pipelining

When to use: - Loop body has no/minimal loop-carried dependencies - Want to maximize throughput - Processing streaming data element-by-element

When NOT to use: - Loop has complex dependencies that prevent II=1 - Memory bandwidth is the bottleneck, not compute

Note: The rewind option is best used with autorestart kernels for continuous streaming.

UNROLL

Unroll loop iterations to increase parallelism.

#pragma HLS UNROLL [factor=<N>] [skip_exit_check]
Parameter Description
factor=<N> Number of iterations to unroll (complete if omitted)
skip_exit_check Skip loop exit condition check for partial unroll

When to use: - Loop body is small and independent - Want to parallelize loop iterations

When NOT to use: - Loop has many iterations (resource explosion) - Loop body has dependencies between iterations

Caution: Unrolling multiplies resources by unroll factor! N iterations fully unrolled = N× logic.

LOOP_TRIPCOUNT

Specify expected loop iteration count for analysis/reporting.

#pragma HLS LOOP_TRIPCOUNT min=<N> max=<N> [avg=<N>]
Parameter Description
min=<N> Minimum expected iterations
max=<N> Maximum expected iterations
avg=<N> Average expected iterations

When to use: - Variable loop bounds (data-dependent) - Want accurate latency/throughput reports

Note: This pragma does NOT affect synthesis, only reporting.

LOOP_FLATTEN

Flatten nested loops into single loop.

#pragma HLS LOOP_FLATTEN [off]

When to use: - Perfect nested loops (bounds are constant) - Want to reduce loop overhead

When NOT to use: - Imperfect loops (code between loop levels) - Variable inner loop bounds

LOOP_MERGE

Merge consecutive loops into single loop.

#pragma HLS LOOP_MERGE [force]

When to use: - Consecutive loops with same bounds - Want to reduce loop overhead

Caution: Using force can cause incorrect results if loops have hidden dependencies.

Task Parallelism

DATAFLOW

Enable task-level pipelining for functions/loops.

#pragma HLS DATAFLOW

When to use: - Multiple sequential functions that can run concurrently - Producer-consumer relationships between functions - Want to overlap execution of different stages

When NOT to use: - Functions have feedback loops - Multiple consumers per channel (use split instead)

Requirements: - Single-producer single-consumer for each channel - No feedback loops (unidirectional data flow) - Functions should have #pragma HLS INLINE OFF

STREAM

Specify stream implementation for arrays in dataflow.

#pragma HLS STREAM variable=<name> [depth=<N>] [type=<fifo|pipo>]
Parameter Description
variable=<name> Array variable to stream
depth=<N> FIFO depth (default: 2)
type Channel type: fifo or pipo (default: fifo)

When to use: - Override default PIPO channel type in dataflow - Need specific FIFO depth for buffering

Note: Without this pragma, arrays in dataflow default to PIPO (ping-pong), NOT FIFO.

Interface

INTERFACE

Specify hardware interface protocol for function arguments.

#pragma HLS INTERFACE <mode> port=<name> [options...]

m_axi (AXI4 Master)

Memory-mapped interface, kernel initiates transfers.

#pragma HLS INTERFACE m_axi port=<name> [depth=<N>] [bundle=<id>] [offset=slave]
Parameter Description
depth=<N> Expected array depth for co-simulation
bundle=<id> Bundle name for port grouping
offset Address offset mode: slave, direct, off
max_read_burst_length Maximum burst length for reads (default: 16)
max_write_burst_length Maximum burst length for writes (default: 16)

Use for: Accessing external memory (DDR, HBM), large data transfers

s_axilite (AXI4-Lite Slave)

Register-based interface, host controls.

#pragma HLS INTERFACE s_axilite port=<name> [bundle=<id>] [autorestart]
Parameter Description
bundle=<id> Bundle name for register grouping
autorestart Enable automatic kernel restart after completion

Use for: Scalar arguments, control/status registers, kernel start/done (port=return)

axis (AXI4-Stream)

Streaming interface, no addressing.

#pragma HLS INTERFACE axis port=<name> [register_mode=<mode>]

Use for: Streaming data (video, network), kernel-to-kernel connections

Other Modes

Mode Description Use Case
ap_fifo FIFO with handshake Simple internal streaming
ap_memory BRAM-like interface Local memory access
ap_none Direct wire Combinational inputs
ap_ctrl_chain Block control with chaining Dataflow designs
ap_ctrl_hs Block control with handshake Standard kernels (default)
ap_ctrl_none No block control Free-running kernels

Memory Optimization

ARRAY_PARTITION

Partition array into smaller arrays or individual elements.

#pragma HLS ARRAY_PARTITION variable=<name> [complete|cyclic|block] [factor=<N>] [dim=<N>]
Type Description
complete Fully partition into individual elements (registers)
cyclic Cyclic partitioning (interleaved)
block Block partitioning (contiguous chunks)

When to use: - Need parallel access to array elements - Loop unrolling requires multiple simultaneous accesses

Tip: Match partition factor to loop unroll factor.

ARRAY_RESHAPE

Reshape array to change word width (partition + merge into wider word).

#pragma HLS ARRAY_RESHAPE variable=<name> [complete|cyclic|block] [factor=<N>] [dim=<N>]

When to use: - Want wider memory access without full partition - Optimize memory bandwidth utilization

BIND_STORAGE

Specify storage implementation for arrays.

#pragma HLS BIND_STORAGE variable=<name> type=<type> impl=<impl>
Type Description
RAM_1P, RAM_2P, RAM_S2P, RAM_T2P RAM configurations
ROM_1P, ROM_2P ROM configurations
FIFO FIFO storage
Implementation Description
BRAM Block RAM (18Kb/36Kb blocks)
LUTRAM Distributed RAM (small arrays)
URAM Ultra RAM (288Kb blocks, Versal/UltraScale+)
AUTO Let HLS decide

DEPENDENCE

Override memory dependency analysis.

#pragma HLS DEPENDENCE variable=<name> <class> <type> <direction> <dependent>
Parameter Values
class array, pointer
type inter (between iterations), intra (within iteration)
direction RAW, WAR, WAW
dependent true, false

Caution: Incorrect use can cause functional errors! Only use when you have verified the access pattern is safe.

CACHE

Add local cache for m_axi port.

#pragma HLS CACHE port=<name> lines=<N> depth=<N>

When to use: - Repeated access to same memory locations - Data has temporal locality

Function Optimization

INLINE

Control function inlining.

#pragma HLS INLINE [off|recursive]
Option Description
(default) Let HLS decide
off Prevent inlining (keep as separate module)
recursive Inline all functions in hierarchy

Important: DATAFLOW requires functions to NOT be inlined. Add #pragma HLS INLINE OFF to all dataflow stage functions.

FUNCTION_INSTANTIATE

Create separate hardware instance for each unique parameter value.

#pragma HLS FUNCTION_INSTANTIATE variable=<name>

When to use: - Function called with different constant parameters - Want specialized hardware for each case

TOP

Specify the top-level function for synthesis.

#pragma HLS TOP name=<function_name>

Resource Allocation

ALLOCATION

Limit or control resource allocation.

#pragma HLS ALLOCATION <type>=<name> limit=<N> [instances=<list>]

Example:

#pragma HLS ALLOCATION operation instances=mul limit=1

When to use: - Need to reduce resource usage - Want resource sharing between operations

BIND_OP

Bind operation to specific implementation.

#pragma HLS BIND_OP variable=<name> op=<operation> impl=<impl>
Implementation Description
dsp Use DSP blocks
fabric Use LUTs
auto Let HLS decide

Data Packing

AGGREGATE

Pack struct fields into single wide word.

#pragma HLS AGGREGATE variable=<name> [compact=<mode>]
Mode Description
auto Default packing
byte Byte-aligned
bit Bit-packed
none No packing

DISAGGREGATE

Split struct into separate signals.

#pragma HLS DISAGGREGATE variable=<name>

Performance

PERFORMANCE

Specify performance target for HLS optimizer.

#pragma HLS PERFORMANCE target_ti=<N>

Note: This is a hint, not a guarantee.

LATENCY

Constrain function/loop latency.

#pragma HLS LATENCY min=<N> max=<N>

EXPRESSION_BALANCE

Control expression tree balancing for latency optimization.

#pragma HLS EXPRESSION_BALANCE [off]

Miscellaneous

RESET

Control reset behavior for static/global variables.

#pragma HLS RESET variable=<name> [off]

PROTOCOL

Control protocol region constraints.

#pragma HLS PROTOCOL [mode=<floating|fixed>]

STABLE

Mark variable as stable (doesn't change during kernel execution).

#pragma HLS STABLE variable=<name>

ALIAS

Indicate ports may alias same memory.

#pragma HLS ALIAS ports=<p1>,<p2> distance=<N>

ARRAY_STENCIL

Enable stencil optimization for array access.

#pragma HLS ARRAY_STENCIL variable=<name>

When to use: - Image/signal processing with sliding window - Regular stencil access patterns
