HLS Interface Guide

This guide covers interface selection and configuration for Vitis HLS designs.

Interface Types Overview

Interface Protocol Use Case Bandwidth
m_axi AXI4 Memory-Mapped DDR/HBM access, random access High
axis AXI4-Stream Streaming data, sequential High (sustained)
s_axilite AXI4-Lite Scalars, control registers Low
ap_fifo FIFO handshake Internal streaming Medium
ap_memory BRAM interface On-chip memory High (local)

Quick Decision Guide

What type of data?
├── Large array/buffer
│   ├── Sequential access → axis (streaming)
│   └── Random access → m_axi (memory)
├── Scalar value → s_axilite
└── Control signals → s_axilite port=return

Interface Topics

Aggregation & Disaggregation

How to handle structs in interfaces: - AGGREGATE: Pack struct into single wide word - DISAGGREGATE: Split struct into separate ports - compact modes: bit, byte, auto, none - Alignment pitfalls: M-AXI power-of-2 requirement

Memory Interfaces (M-AXI)

Key concepts: - Burst transfers for efficiency - Auto-burst vs explicit hls::burst_maxi - Port widening for bandwidth - Cache pragma for data reuse - Port aliasing with hls::fence - Power-of-2 struct alignment requirement

Includes: BRAM/URAM storage, shift register optimization, ROM inference

Streaming Interfaces (AXI-Stream)

Key concepts: - ap_axis<> / ap_axiu<> for side channels (TUSER, TID, TDEST) - hls::axis<> for custom data types (structs, complex) - hls::axis_user<> for selective side channels - Array of streams: hls::stream<T> s[N] for parallel channels - TLAST handling for packet boundaries - AXIS to M-AXI conversion with DATAFLOW

Includes: Type comparison, register modes, stream-to-memory patterns

Register Interfaces (AXI-Lite)

Key concepts: - Scalar parameters via s_axilite - Control/status registers (start, done, idle, ready) - Custom register offsets with offset=0xNN - M-AXI address pointers with offset=slave - Autorestart for streaming kernels

Custom Offset Example:

void kernel(char* a, char* b, char* c) {
#pragma HLS INTERFACE s_axilite port=a bundle=BUS_A offset=0x20
#pragma HLS INTERFACE s_axilite port=b bundle=BUS_A offset=0x28
#pragma HLS INTERFACE s_axilite port=c bundle=BUS_A offset=0x30
#pragma HLS INTERFACE s_axilite port=return bundle=BUS_A
}

Reserved Registers (per bundle): | Address | Register | |---------|----------| | 0x00 | Control (start/done/idle/ready) | | 0x04 | Global interrupt enable | | 0x08 | IP interrupt enable | | 0x0C | IP interrupt status |

See: autorestart pattern

Struct Handling in Interfaces

The Alignment Problem

M-AXI interfaces require power-of-2 byte alignment. Non-aligned structs cause II violations.

// BAD: 24 bytes - causes II violations
struct A { int a, b, c, d, e, f; };

// GOOD: Force 32-byte alignment
struct alignas(32) A { int a, b, c, d, e, f; };

See: struct-alignment pattern

AGGREGATE vs DISAGGREGATE

Pragma Result Use When
#pragma HLS aggregate Single wide port All fields accessed together
#pragma HLS disaggregate Separate port per field Fields go to different destinations

compact Modes

Mode Description Best For
compact=bit Exact bit packing Minimum resource
compact=byte Byte-aligned fields Software compatibility
compact=auto HLS decides Default behavior
compact=none Power-of-2 padding M-AXI (forced)
