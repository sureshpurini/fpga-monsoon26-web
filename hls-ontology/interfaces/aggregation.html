Struct Aggregation & Disaggregation

How to handle C++ structs in HLS interfaces.

Overview

When structs are used in HLS interfaces, you control how they map to hardware:

Operation Pragma Result
Aggregate #pragma HLS aggregate Pack all fields into single wide word
Disaggregate #pragma HLS disaggregate Split into separate ports per field

AGGREGATE

Pack struct fields into a single wide word for efficient transfer.

Syntax

#pragma HLS aggregate variable=<name> [compact=<mode>]

compact Modes

Mode Description Resulting Size
bit Pack to exact bit boundaries Minimum bits
byte Align fields to byte boundaries Matches C layout
auto HLS decides based on interface Varies
none Pad to power-of-2 Larger (M-AXI requirement)

Example: Basic Aggregation

struct A {
    int foo[3];      // 96 bits
    ap_int<23> bar;  // 23 bits
};                   // Total: 119 bits

int dut(A arr[N]) {
#pragma HLS interface ap_fifo port=arr
#pragma HLS aggregate variable=arr
    // Single 119-bit read per struct element
    for (unsigned i = 0; i < N; i++) {
        auto tmp = arr[i];
        sum += tmp.foo[0] + tmp.foo[1] + tmp.foo[2] + tmp.bar;
    }
    return sum;
}

Example: Nested Structs with compact Modes

struct T { int m; int n; bool o; };  // 65 bits
struct S { int p; T q; };            // 97 bits total

void top(S a[N], S b[N], S c[N]) {
#pragma HLS interface bram port=c
#pragma HLS interface ap_memory port=a
#pragma HLS aggregate variable=a compact=byte  // 104 bits (bool→8 bits)
#pragma HLS aggregate variable=c compact=byte  // 104 bits
    // b uses default compact=bit: 97 bits
}

HLS Log Messages

INFO: [HLS 214-241] Aggregating fifo variable 'arr' with compact=bit mode in 119-bits
INFO: [HLS 214-241] Aggregating bram variable 'a' with compact=byte mode in 104-bits

DISAGGREGATE

Split struct into separate ports, one per field.

Syntax

#pragma HLS disaggregate variable=<name>

Example: Split AXIS Ports

struct A {
    char c;  // 8 bits
    int i;   // 32 bits
};

void dut(A in[N], A out[N]) {
#pragma HLS interface axis port=in
#pragma HLS interface axis port=out
#pragma HLS disaggregate variable=in
#pragma HLS disaggregate variable=out
    // Creates 4 AXIS ports: in_c, in_i, out_c, out_i
    for (unsigned i = 0; i < N; i++) {
        out[i].c = in[i].c;
        out[i].i = in[i].i;
    }
}

Port Naming

Disaggregated ports are named: <variable>_<field>_*

Original: dut(A in[N], A out[N])
After:    in_c, in_i, out_c, out_i

Automatic Behaviors

M-AXI Auto-Aggregation

M-AXI interfaces automatically aggregate structs and pad to power-of-2 bytes:

struct A { char foo; short bar; };  // 24 bits (3 bytes)

int dut(A* arr) {
#pragma HLS interface m_axi port=arr
    // Automatically padded to 32 bits (4 bytes)
}

No pragma needed - but watch for alignment issues!

Stream Auto-Disaggregation

Structs containing hls::stream are automatically disaggregated:

struct A {
    hls::stream<int> s_in;  // Needs stream interface
    long arr[N];            // Needs memory interface
};

long dut(struct A& d) {
    // No pragma needed - auto-disaggregated
    // Creates: d_s_in_* and d_arr_* ports
}

The Alignment Pitfall

Problem

Non-power-of-2 struct sizes with M-AXI cause II violations.

struct A {  // 192 bits = 24 bytes (NOT power of 2!)
    int s_1, s_2, s_3, s_4, s_5, s_6;
};

void dut(A a_in[NUM], A a_out[NUM]) {
#pragma HLS INTERFACE m_axi port=a_in
#pragma HLS INTERFACE m_axi port=a_out
    // M-AXI pads to 256 bits (32 bytes)
    // Software: 24 bytes, Hardware: 32 bytes
    // Result: Address mismatch → II violations!
}

Solution 1: alignas()

struct alignas(32) A {  // Force 32-byte alignment
    int s_1, s_2, s_3, s_4, s_5, s_6;
    // Compiler pads to 256 bits (32 bytes)
};

Solution 2: Explicit Padding

struct A {
    int s_1, s_2, s_3, s_4, s_5, s_6;  // 192 bits
    int _pad[2];  // +64 bits = 256 bits (32 bytes)
};

Power-of-2 Reference

Original Padded To Fix
12 bytes (96 bits) 16 bytes alignas(16)
24 bytes (192 bits) 32 bytes alignas(32)
48 bytes (384 bits) 64 bytes alignas(64)

Decision Guide

Using struct in interface?
├── M-AXI interface?
│   └── AUTO-AGGREGATED (power-of-2 padded)
│       └── Ensure struct size is power of 2!
├── Want single-transaction transfer?
│   └── Use AGGREGATE
│       ├── compact=bit   (min bits)
│       ├── compact=byte  (matches C layout)
│       └── compact=auto  (let HLS decide)
├── Need separate ports per field?
│   └── Use DISAGGREGATE
└── Struct contains hls::stream?
    └── AUTO-DISAGGREGATED

When to Use Each

Use AGGREGATE When:

  • Want efficient single-transaction transfer
  • All fields are accessed together
  • Reducing interface signal count
  • Struct passed through streaming interface

Use DISAGGREGATE When:

  • Fields connect to different external modules
  • Fields have different timing requirements
  • Want separate AXI-Stream channels per field
  • Fields are accessed independently
