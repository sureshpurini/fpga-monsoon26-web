hls::vector - SIMD Vector Type

hls::vector<T, N> is a SIMD (Single Instruction, Multiple Data) vector type that enables parallel element-wise operations on FPGAs. All N elements are processed simultaneously in hardware, making it ideal for high-throughput data processing.

Header

#include <hls_vector.h>

Syntax

hls::vector<T, N>
Parameter Description
T Element type: integers (uint32_t, int), floating-point (float, double), or arbitrary precision (ap_int, ap_fixed)
N Number of elements (power of 2 recommended for alignment)

Common Configurations

Size (N) Element Type Total Bits Bytes Use Case
16 uint32_t 512 64 Match 512-bit AXI bus width
16 float 512 64 Floating-point SIMD compute
8 uint64_t 512 64 64-bit elements, same bus width
32 uint16_t 512 64 Smaller elements, more parallelism

Operations

Arithmetic (Element-wise)

hls::vector<int, 16> a, b, c;

c = a + b;      // Add corresponding elements
c = a - b;      // Subtract
c = a * b;      // Multiply
c = a / b;      // Divide
c = -a;         // Negate all elements

Scalar Broadcast

c = a + 25;     // Add 25 to all 16 elements
c = a * 3;      // Multiply all 16 elements by 3

Element Access

int x = a[0];   // Read first element
a[5] = 42;      // Write to sixth element
int n = a.size();  // Returns N (compile-time constant)

Stream I/O

hls::stream<hls::vector<uint32_t, 16>> channel;

// Write vector to stream
channel.write(a);

// Read vector from stream
b = channel.read();

Design Patterns

1. Wide Memory Access

Match vector size to AXI bus width for maximum memory throughput:

#include <hls_vector.h>

typedef hls::vector<uint32_t, 16> vec512;  // 512 bits = 64 bytes

void kernel(vec512* input, vec512* output, int n) {
#pragma HLS INTERFACE m_axi port=input depth=1024
#pragma HLS INTERFACE m_axi port=output depth=1024

    for (int i = 0; i < n; i++) {
#pragma HLS PIPELINE II=1
        output[i] = input[i] * 2;  // Full 512-bit transfer per cycle
    }
}

2. Streaming Vectors (Dataflow)

Combine hls::vector with hls::stream for dataflow pipelines:

#include <hls_vector.h>
#include <hls_stream.h>

typedef hls::vector<uint32_t, 16> vecOf16Words;

void producer(vecOf16Words* input, hls::stream<vecOf16Words>& out, int n) {
    for (int i = 0; i < n; i++) {
#pragma HLS PIPELINE II=1
        out.write(input[i]);
    }
}

void consumer(hls::stream<vecOf16Words>& in, vecOf16Words* output, int n) {
    for (int i = 0; i < n; i++) {
#pragma HLS PIPELINE II=1
        output[i] = in.read() * 3;  // Element-wise multiply
    }
}

void top(vecOf16Words* input, vecOf16Words* output, int n) {
#pragma HLS DATAFLOW
    hls::stream<vecOf16Words> channel;
    producer(input, channel, n);
    consumer(channel, output, n);
}

3. Vector-to-Vector Operations

Process multiple vector streams in parallel:

void diamond_merge(hls::stream<vecOf16Words>& in1,
                   hls::stream<vecOf16Words>& in2,
                   hls::stream<vecOf16Words>& out, int n) {
    for (int i = 0; i < n; i++) {
#pragma HLS PIPELINE II=1
        out.write(in1.read() + in2.read());  // Add 16 element pairs
    }
}

4. Load-Compute-Store with Parallel Memory Access

Use separate memory bundles to enable parallel loads:

#include <hls_vector.h>

typedef hls::vector<float, 16> float16;

void vector_add(float16* res, const float16* lhs, const float16* rhs, int n) {
    // Separate bundles allow parallel DDR access
#pragma HLS INTERFACE m_axi port=lhs offset=slave bundle=gmem0 depth=32
#pragma HLS INTERFACE m_axi port=rhs offset=slave bundle=gmem1 depth=32
#pragma HLS INTERFACE m_axi port=res offset=slave bundle=gmem0 depth=32

    float16 lhs_buf[32], rhs_buf[32], res_buf[32];

#pragma HLS DATAFLOW
    // Load from two memory ports simultaneously
    load(lhs_buf, lhs, n);
    load(rhs_buf, rhs, n);
    // Compute
    for (int i = 0; i < n; i++) {
        res_buf[i] = lhs_buf[i] + rhs_buf[i];
    }
    // Store
    store(res, res_buf, n);
}

5. Function Templates for DATAFLOW

When using DATAFLOW with vectors, wrap load/store/compute in separate functions with #pragma HLS INLINE off. This ensures each function becomes a distinct pipeline stage.

Why INLINE off? - DATAFLOW requires function boundaries to identify pipeline stages - Without INLINE off, the compiler may merge functions, breaking the dataflow structure - Each function with INLINE off becomes an independent concurrent process

#include <hls_vector.h>

typedef hls::vector<float, 16> float16;

// Template-based load function - reusable for any vector type
template <int N, typename T>
void load(T (&buf)[N], const T* mem) {
#pragma HLS INLINE off  // Critical: Keep as separate DATAFLOW stage
    for (int i = 0; i < N; ++i) {
#pragma HLS PIPELINE II=1
        buf[i] = mem[i];
    }
}

// Template-based store function
template <int N, typename T>
void store(T* mem, const T (&buf)[N]) {
#pragma HLS INLINE off
    for (int i = 0; i < N; ++i) {
#pragma HLS PIPELINE II=1
        mem[i] = buf[i];
    }
}

// Compute function
template <int N, typename T>
void compute(T (&res)[N], const T (&lhs)[N], const T (&rhs)[N]) {
#pragma HLS INLINE off
    for (int i = 0; i < N; ++i) {
#pragma HLS PIPELINE II=1
        res[i] = lhs[i] + rhs[i];  // All 16 floats added per cycle
    }
}

// Top-level kernel
void vector_add(float16* res, const float16* lhs, const float16* rhs) {
#pragma HLS INTERFACE m_axi port=lhs bundle=gmem0 depth=32
#pragma HLS INTERFACE m_axi port=rhs bundle=gmem1 depth=32
#pragma HLS INTERFACE m_axi port=res bundle=gmem0 depth=32

    float16 lhs_buf[32], rhs_buf[32], res_buf[32];

#pragma HLS DATAFLOW
    load(lhs_buf, lhs);
    load(rhs_buf, rhs);
    compute(res_buf, lhs_buf, rhs_buf);
    store(res, res_buf);
}

Buffer sizing: The array size (32) should match the depth parameter in the INTERFACE pragma. This aligns the internal FIFO adapter with the actual buffering capacity.

When to Use

Scenario Recommendation
Wide memory access (512-bit AXI) Use N=16 with 32-bit elements
SIMD parallelism Process N elements per cycle
Streaming pipelines Pass through hls::stream<vector>
Batch processing Fixed-size data chunks

When NOT to Use

Scenario Why
Variable-length data N is fixed at compile time
Small data sets Overhead exceeds benefit
Non-aligned memory access Vectors assume aligned access
Random element access with variable index Reduces parallelism

Best Practices

  1. Match AXI bus width: N * sizeof(T) * 8 = 512 bits for maximum throughput
  2. Use separate memory bundles: bundle=gmem0, bundle=gmem1 for parallel loads
  3. Combine with DATAFLOW: Pipeline vector operations across functions
  4. Power-of-2 sizes: Better memory alignment
  5. Use typedef: typedef hls::vector<float, 16> float16; for readability
  6. Avoid variable indexing: v[i] with runtime i may serialize access
