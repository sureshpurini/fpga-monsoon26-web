hls::split and hls::merge

Fan-out (split) and fan-in (merge) channel types for parallel data distribution in dataflow designs.

Header

#include <hls_np_channel.h>

hls::split (Fan-Out)

Distributes data from one producer to N parallel consumers.

                    ┌──► consumer0
                    │
Producer ──► SPLIT ─┼──► consumer1
                    │
                    └──► consumer2

Round Robin

hls::split::round_robin<T, N, D, DEPTH> s;
Parameter Description
T Data type (e.g., ap_uint<32>, int)
N Number of output streams
D Elements per output before rotating
DEPTH FIFO depth for each output

Behavior: Sends D elements to out[0], then D to out[1], ..., wraps back to out[0].

hls::split::round_robin<ap_uint<32>, 4, 2, 100> s;
// With D=2, N=4:
// Elements {0,1} → out[0]
// Elements {2,3} → out[1]
// Elements {4,5} → out[2]
// Elements {6,7} → out[3]
// Elements {8,9} → out[0] (wrap)

Load Balance

hls::split::load_balance<T, N, DEPTH> s;
Parameter Description
T Data type
N Number of output streams
DEPTH FIFO depth for each output

Note: No D parameter - distribution is dynamic based on available space.

Behavior: Sends each element to first output that has space in its FIFO.

hls::split::load_balance<ap_uint<32>, 4, 6> s;
// Distribution depends on which consumer is faster

Split Members

Member Type Description
s.in hls::stream<T>& Single input (producer writes here)
s.out[i] hls::stream<T>& Output array (consumers read from these)

hls::merge (Fan-In)

Collects data from N parallel producers into one consumer.

producer0 ──┐
            │
producer1 ──┼──► MERGE ──► Consumer
            │
producer2 ──┘

Round Robin

hls::merge::round_robin<T, N, D, DEPTH> s;

Behavior: Reads D elements from in[0], then D from in[1], ..., wraps back.

hls::merge::round_robin<int, 4, 5, 100> s;
// Reads 5 elements from in[0] → output
// Reads 5 elements from in[1] → output
// ...

Load Balance

hls::merge::load_balance<T, N, DEPTH> s;

Behavior: Reads from first input that has data available.

Merge Members

Member Type Description
s.in[i] hls::stream<T>& Input array (producers write to these)
s.out hls::stream<T>& Single output (consumer reads from here)

Complete Example

Split Round Robin

#include "hls_np_channel.h"
#include "hls_stream.h"

void producer(hls::stream<ap_uint<32>>& out, int n) {
#pragma HLS inline off
    for (int i = 0; i < n; i++) {
        out.write(i);
    }
}

void consumer(hls::stream<ap_uint<32>>& in, hls::stream<ap_uint<32>>& out, int n) {
#pragma HLS inline off
    for (int i = 0; i < n; i++) {
        out.write(in.read());
    }
}

void dut(hls::stream<int>& in,
         hls::stream<ap_uint<32>>& out1,
         hls::stream<ap_uint<32>>& out2,
         hls::stream<ap_uint<32>>& out3,
         hls::stream<ap_uint<32>>& out4) {
#pragma HLS dataflow

    hls::split::round_robin<ap_uint<32>, 4, 2, 100> s;
    //                      T            N  D  DEPTH

    producer(s.in, 16);           // Writes 16 elements total
    consumer(s.out[0], out1, 4);  // Each reads 16/4 = 4 elements
    consumer(s.out[1], out2, 4);
    consumer(s.out[2], out3, 4);
    consumer(s.out[3], out4, 4);
}

Merge Round Robin

void dut(hls::stream<int>& in1, hls::stream<int>& in2,
         hls::stream<int>& in3, hls::stream<int>& in4,
         hls::stream<int>& out) {
#pragma HLS dataflow

    hls::merge::round_robin<int, 4, 5, 100> s;

    producer(s.in[0], in1, 16);  // Each writes 16 elements
    producer(s.in[1], in2, 16);
    producer(s.in[2], in3, 16);
    producer(s.in[3], in4, 16);
    consumer(s.out, out, 64);    // Reads 4 × 16 = 64 total
}

Round Robin vs Load Balance

Aspect Round Robin Load Balance
Distribution Fixed rotation Dynamic (first available)
D parameter Yes No
Deterministic Yes No
Output ordering Predictable Varies by timing
Hardware Simpler More complex (arbitration)

When to Use Round Robin

  • All consumers/producers have equal processing time
  • Predictable ordering required for correctness
  • Testing needs reproducible results

When to Use Load Balance

  • Variable processing times
  • One stage might stall (cache miss, etc.)
  • Maximum throughput is priority
  • Work-stealing style parallelism

Parameter Guidelines

Choosing N (Parallelism)

N = number of parallel units
- Higher N → more parallelism, more resources
- Lower N → less parallelism, fewer resources

Choosing D (Distribution Factor)

D = elements per output before rotating
- D=1 → Fine-grained interleaving
- D>1 → Coarser batches (better memory patterns)

Choosing DEPTH (FIFO Size)

DEPTH = buffer size
- Too small → Deadlock or stalls
- Too large → Wastes BRAM
- Rule: DEPTH >= D * 2 for round_robin
