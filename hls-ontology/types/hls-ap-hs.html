hls::ap_hs

Two-way handshake interface for direct I/O control signals with valid/acknowledge protocol.

Header

#include <hls_directio.h>

Syntax

hls::ap_hs<T>& signal;  // As function parameter
Parameter Description
T Data type (typically int, bool, or small structs)

Handshake Signals

The ap_hs interface generates three hardware signals:

┌─────────────────────────────────────────┐
│           ap_hs Interface               │
├─────────────────────────────────────────┤
│  data  ◄──────────────────────────────► │  Payload
│  valid ────────────────────────────────►│  Data is ready (from writer)
│  ack   ◄────────────────────────────────│  Data consumed (from reader)
└─────────────────────────────────────────┘
Signal Direction Description
data Bidirectional The actual data value
valid From writer Indicates data is valid
ack From reader Acknowledges data was consumed

Methods

Method Return Description
write(T val) void Send value with valid signal asserted
read() T Read value and send acknowledgment
valid() bool Non-blocking check if data is available

Direction Inference

The interface direction (input/output) is inferred from usage:

Methods Used Inferred Direction
.write() only Output
.read() / .valid() only Input
Both Inout (bidirectional) 
void kernel(hls::ap_hs<int>& out_signal,   // Output: only write()
            hls::ap_hs<int>& in_signal) {  // Input: only read()/valid()

    // Output - only write
    out_signal.write(counter);

    // Input - only read/valid
    if (in_signal.valid()) {
        int val = in_signal.read();
    }
}

Blocking vs Non-Blocking Operations

ap_hs supports both blocking and non-blocking patterns:

Blocking Read

int val = signal.read();  // Blocks until data is valid

The read() method waits until the valid signal is asserted, then reads the data and sends acknowledgment.

Non-Blocking Check with valid()

if (signal.valid()) {        // Non-blocking check
    int val = signal.read(); // Read only if data available
}

Use valid() to poll for optional data without stalling the main processing loop.

Example Usage

Control-Driven: Polling with valid()

#include "hls_directio.h"
#include "hls_stream.h"

void kernel(hls::stream<int>& in,
            hls::stream<int>& out,
            hls::ap_hs<int>& status,       // Output: report counter
            hls::ap_hs<int>& reset_cmd) {  // Input: reset command
#pragma HLS interface mode=axis port=in
#pragma HLS interface mode=axis port=out

    static int counter = 0;

    for (int i = 0; i < 1000; i++) {
        int data = in.read();

        // Check for reset command (non-blocking)
        if (reset_cmd.valid()) {
            int cmd = reset_cmd.read();
            if (cmd == 1) {
                counter = 0;
                status.write(counter);
                break;
            }
        }

        counter++;
        status.write(counter);  // Report current count
        out.write(data * 2);
    }
}

Control-Driven Test Bench

#include "kernel.h"

int main() {
    hls::ap_hs<int> status;
    hls::ap_hs<int> reset_cmd;
    hls::stream<int> in, out;

    // Pre-load reset commands
    for (int i = 0; i < 99; i++) {
        reset_cmd.write(0);  // No reset
    }
    reset_cmd.write(1);      // Reset at iteration 100

    // Load input data
    for (int i = 0; i < 100; i++) {
        in.write(i);
    }

    // Execute kernel
    kernel(in, out, status, reset_cmd);

    // Read status values
    for (int i = 0; i < 100; i++) {
        int s = status.read();
        int o = out.read();
    }

    return 0;
}

Usage with Data-Driven Tasks

ap_hs can be used with hls::task for synchronized scalar inputs in data-driven dataflow:

Data-Driven Task with ap_hs

#include "hls_task.h"
#include "hls_directio.h"

void task2(hls::stream<int>& in, hls::stream<int>& out,
           hls::ap_hs<int>& n) {
    int c = in.read();
    int var = n.read();  // Blocks until n has valid data
    out.write(c + var);
}

void sub_task1(hls::stream<int>& in, hls::stream<int>& out) {
    int c = in.read();
    out.write(c + 2);
}

void sub_task2(hls::stream<int>& in, hls::stream<int>& out) {
    int c = in.read();
    out.write(c - 2);
}

void test(hls::stream<int>& in, hls::stream<int>& out,
          hls::ap_hs<int>& n) {
    hls_thread_local hls::stream<int> s1;
    hls_thread_local hls::stream<int> s2;
    hls_thread_local hls::task t(task2, s2, out, n);
    hls_thread_local hls::task t1(sub_task1, in, s1);
    hls_thread_local hls::task t2(sub_task2, s1, s2);
}

Data Flow

in -> [sub_task1: +2] -> s1 -> [sub_task2: -2] -> s2 -> [task2: +n] -> out
                                                            ^
                                                            n (ap_hs)

Test Bench for Data-Driven

int main() {
    hls::stream<int> in, out;
    hls::ap_hs<int> n;
    int golden = 0;

    for (int i = 0; i < N; i++) {
        n.write(i);      // Provide scalar for each element
        in.write(i);
        golden += 2*i;   // Expected: (i+2-2) + i = 2*i
    }

    test(in, out, n);

    int sum = 0;
    for (int i = 0; i < N; i++)
        sum += out.read();

    return (sum == golden) ? 0 : 1;
}

Key advantage: The task automatically synchronizes - it waits for both stream data AND the scalar value before proceeding.

When to Use

Use Case Why ap_hs
Runtime control signals Reset, pause, mode changes
Status reporting Counter values, error flags
Fine-grained synchronization Per-iteration handshaking
External controller interface FPGA-to-FPGA signaling

Comparison with Other Interfaces

Interface Handshaking Use Case
ap_none None Static values, constants
ap_vld 1-way (valid only) Output status signals
ap_ack 1-way (ack only) Input consumption signals
ap_hs 2-way (valid + ack) Bidirectional flow control
hls::stream FIFO-based Data streams with buffering

Key Differences from hls::stream

Aspect hls::ap_hs hls::stream
Buffering None (direct) FIFO buffer
Handshake Valid + Ack signals FIFO full/empty
Use case Control signals Data streams
Blocking Depends on usage Yes (read/write)

Related Types

  • hls::ap_none - Wire-only interface (no handshaking)
  • hls::stream - FIFO-based streaming (for data)
  • hls::task - Data-driven task-level parallelism
  • ap_axiu - AXI-Stream packets
