ap_float / half

Custom and reduced-precision floating-point types for trading accuracy for resources.

Header

#include <ap_float.h>   // For ap_float
#include <hls_half.h>   // For half

ap_float

Custom-width floating-point with configurable mantissa and exponent.

Syntax

ap_float<M, E> var;
Parameter Description
M Mantissa (significand) bits - determines precision
E Exponent bits - determines range

Common Configurations

Configuration Equivalent Use Case
ap_float<10, 5> ~half precision General reduced precision
ap_float<7, 8> ~bfloat16 ML inference
ap_float<18, 5> Custom Accumulation with extra precision

Example

#include <ap_float.h>

// Custom precision for accumulation
using apf_t = ap_float<18, 5>;  // 18-bit mantissa, 5-bit exponent

void accumulate(float* input, float* output, int n) {
    apf_t sum = 0;

    for (int i = 0; i < n; i++) {
#pragma HLS PIPELINE
        sum += apf_t(input[i]);  // Convert and accumulate
    }

    *output = float(sum);  // Convert back
}

Hardware Accumulator (ap_float_acc)

Dedicated accumulator type for accurate summation of ap_float values. Solves the classic floating-point rounding error problem in large summations.

Why Use ap_float_acc?

Summing many floating-point values accumulates rounding errors: - Each addition rounds to nearest representable value - Errors compound over many iterations - Final result can be significantly off

ap_float_acc solves this by: - Using wider internal storage (ap_fixed) - Delaying final conversion until the last element - Preserving precision during intermediate additions

Syntax

ap_float_acc<FloatType, AccumType> acc;
result = acc.accumulate(value, is_last);
Parameter Description
FloatType ap_float type for input/output (e.g., ap_float<18,5>)
AccumType Internal accumulator type for extended precision (e.g., ap_fixed<32,16>)
is_last Set true on final iteration to trigger conversion to FloatType

Streaming Accumulation Example

#include <ap_float.h>
#include <hls_stream.h>

using apf_t = ap_float<18, 5>;           // Input/output type
using acc_t = ap_fixed<32, 16>;          // Wide internal accumulator
using stream_t = hls::stream<float>;

void accurate_sum(stream_t& in, stream_t& out, int n) {
    apf_t res;
    ap_float_acc<apf_t, acc_t> acc;

    for (int i = 0; i < n; i++) {
        apf_t value = in.read();
        res = acc.accumulate(value, i == n-1);  // is_last on final iteration
    }
    out.write((float)res);
}

Choosing AccumType Width

Input Mantissa Recommended AccumType Rationale
10 bits ap_fixed<24, 12> ~2× mantissa width
18 bits ap_fixed<32, 16> Common for DSP
23 bits ap_fixed<48, 24> Near float precision

Rule of thumb: AccumType mantissa ≥ 2× input mantissa for multi-thousand element sums.

half

IEEE 754 half-precision (16-bit) floating-point.

Bit Layout

Field Bits Description
Sign 1 Sign bit
Exponent 5 Exponent field
Mantissa 10 Significand
Total 16 Half the size of float

Range and Precision

Property Value
Min positive ~6.1e-5
Max value ~65504
Precision ~3 decimal digits

Example

#include <hls_half.h>

void scale(half* input, half* output, int n) {
    for (int i = 0; i < n; i++) {
#pragma HLS PIPELINE
        output[i] = input[i] * half(0.5f);
    }
}

// Wide memory access with half
#include <hls_vector.h>
typedef hls::vector<half, 32> half32;  // 512 bits = 32 half values

void wide_scale(half32* input, half32* output, int n) {
#pragma HLS INTERFACE m_axi port=input bundle=gmem
#pragma HLS INTERFACE m_axi port=output bundle=gmem

    for (int i = 0; i < n; i++) {
#pragma HLS PIPELINE
        output[i] = input[i] * half(2.0f);  // Scale all 32 values
    }
}

Conversion

// float to half
half h = half(3.14159f);

// half to float
float f = float(h);
// or
float f = h.to_float();

// ap_float to float
ap_float<18, 5> af = 3.14159f;
float f = float(af);

When to Use

Type Use Case
half ML inference, graphics, bandwidth-limited
ap_float Custom precision, accumulation, resource optimization
float Standard precision, compatibility

When NOT to Use

Avoid Reason Alternative
Scientific computing Need high precision double
Large accumulations Rounding errors ap_float with larger mantissa
Values outside range Overflow/underflow float

Performance Notes

Consideration Details
Conversion latency float ↔ half adds pipeline stages
Native support Depends on target FPGA
Memory bandwidth half = 2× throughput vs float
Vector width 32 half = 512 bits (AXI bus)

Related Types

  • hls::vector - Combine with half for wide memory access
  • ap_fixed - Fixed-point alternative
