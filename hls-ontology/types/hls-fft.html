hls::fft

Vitis HLS FFT IP wrapper for Fast Fourier Transform operations. Provides a highly optimized, pre-built FFT implementation with configurable architecture, scaling, and interface options.

Overview

The hls::fft function wraps the Xilinx FFT IP core for use in Vitis HLS designs. It supports forward and inverse transforms, multiple architectures, and both array and stream interfaces.

Time Domain                    Frequency Domain
   xn[N]     ─────► FFT ─────►    xk[N]
(complex)                       (complex)

Two variants available: - Basic FFT: Single sample per cycle, fixed-point or float, full runtime control (direction, scaling, nfft) - SSR FFT: Super Sample Rate (2x or 4x throughput), native float only, simplified API

Header

#include "hls_fft.h"

Basic FFT (SSR=1)

Syntax

template <typename CONFIG>
void hls::fft(
    TI xn[N],           // Input: time-domain samples (or hls::stream<TI>&)
    TO xk[N],           // Output: frequency-domain bins (or hls::stream<TO>&)
    TDir direction,     // 1=FFT (forward), 0=IFFT (inverse)
    TScale scaling,     // Scaling schedule
    int nfft,           // Runtime FFT size (-1 for fixed)
    bool* status        // Output: overflow flag
);

Configuration

Basic FFT is configured via a struct that inherits from hls::ip_fft::params_t. Use the OVERRIDE() macro to customize parameters.

struct my_fft_config : hls::ip_fft::params_t {
    OVERRIDE(input_width) = 16;
    OVERRIDE(output_width) = 16;
    OVERRIDE(max_nfft) = 10;                          // log2(1024) = 10
    OVERRIDE(arch) = hls::ip_fft::pipelined_streaming_io;
    OVERRIDE(scaling) = hls::ip_fft::scaled;
    OVERRIDE(output_ordering) = hls::ip_fft::natural_order;
    OVERRIDE(config_width) = 16;
};

Configuration Parameters

Parameter Type Range Description
input_width int 8-34 (32 for float) Input data width
output_width int 8-34 Output data width
max_nfft int 3-16 log2(max FFT length)
has_nfft bool true/false Enable runtime FFT size
arch enum See below FFT architecture
scaling enum See below Scaling mode
output_ordering enum See below Output sample order
rounding enum See below Rounding mode

Architecture Options

Architecture Description Throughput Resources
pipelined_streaming_io Continuous streaming (recommended) 1 sample/cycle Higher
radix_4_burst_io Burst I/O, radix-4 Frame-based Lower
radix_2_burst_io Burst I/O, radix-2 Frame-based Medium
radix_2_lite_burst_io Smallest implementation Slowest Lowest

Scaling Options

Mode Description
scaled Divide by 2 at each stage (prevents overflow)
unscaled No scaling (output grows)
block_floating_point Dynamic scaling based on data

Output Ordering

Mode Description
natural_order Output in natural frequency order (0, 1, 2, ...)
bit_reversed_order Output in bit-reversed order (saves reordering logic)

Data Types

Basic FFT supports both fixed-point and floating-point:

// Fixed-Point (Recommended for Basic FFT)
typedef ap_fixed<16,1> data_in_t;              // Q1.15 format
typedef ap_fixed<16,2> data_out_t;             // Extra bit for growth
typedef std::complex<data_in_t> cmpxDataIn;
typedef std::complex<data_out_t> cmpxDataOut;

// Floating-Point
typedef std::complex<float> cmpxDataIn;
typedef std::complex<float> cmpxDataOut;

Interface Options

Array Interface

Use arrays with #pragma HLS stream for internal conversion to streaming:

void fft_top(cmpxDataIn xn[FFT_LENGTH], cmpxDataOut xk[FFT_LENGTH], ...) {
#pragma HLS interface ap_fifo depth=1024 port=xn,xk
#pragma HLS stream variable=xn
#pragma HLS stream variable=xk
#pragma HLS dataflow
    hls::fft<config1>(xn, xk, dir, scaling, -1, &status);
}

Stream Interface

Use native hls::stream for direct streaming:

void fft_top(hls::stream<cmpxDataIn>& xn, hls::stream<cmpxDataOut>& xk, ...) {
#pragma HLS interface ap_fifo depth=1024 port=xn,xk
#pragma HLS dataflow
    hls::fft<config1>(xn, xk, dir, scaling, -1, &status);
}

Runtime Parameters

Parameter Type Description
direction ap_uint<1> 1=FFT (forward), 0=IFFT (inverse)
scaling ap_uint<15> Scaling schedule (e.g., 0x5555 for ÷2 per stage)
nfft int -1 for fixed size, or log2(size) for runtime config

SSR FFT (Super Sample Rate)

SSR FFT processes 2 or 4 samples per clock cycle for higher throughput. It uses a different base class and simplified API.

Syntax

template <typename CONFIG>
void hls::fft(
    TI in[N],           // Input array (or hls::stream<hls::vector<TI, SSR>>&)
    TO out[N]           // Output array (or hls::stream<hls::vector<TO, SSR>>&)
);
// Note: No direction, scaling, nfft, status parameters for SSR

Configuration

SSR FFT uses hls::ip_fft::ssr_params_t as the base class:

struct my_ssr_config : hls::ip_fft::ssr_params_t {
    static const unsigned super_sample_rate = 2;  // 2 or 4 samples/cycle
    static const bool use_native_float = true;    // Required for SSR
    OVERRIDE(systolicfft_inv) = false;            // false=FFT, true=IFFT
    static const unsigned config_width = 16;
    static const unsigned max_nfft = 10;          // log2(1024)
};

SSR Configuration Parameters

Parameter Type Values Description
super_sample_rate unsigned 2 or 4 Samples processed per clock cycle
use_native_float bool true Required - must be true for SSR
systolicfft_inv bool true/false Control FFT/IFFT mode (false=FFT, true=IFFT)
config_width unsigned 16 Configuration width
max_nfft unsigned 3-16 log2(max FFT length)

Data Types

SSR requires native 32-bit float:

typedef std::complex<float> cmpxDataIn;
typedef std::complex<float> cmpxDataOut;

// For stream interface: use hls::vector
const int FFT_SSR = 2;
typedef hls::vector<cmpxDataIn, FFT_SSR> vec_in_t;
typedef hls::vector<cmpxDataOut, FFT_SSR> vec_out_t;

Interface Options

SSR Array Interface

void fft_top(bool direction, cmpxDataIn in[FFT_LENGTH],
             cmpxDataOut out[FFT_LENGTH], bool* ovflo) {
#pragma HLS interface ap_hs port=direction
#pragma HLS dataflow
    hls::fft<ssr_config>(in, out);  // Simplified call
}

SSR Stream Interface

Uses hls::stream<hls::vector<complex, SSR>> for SSR samples per transfer:

void fft_top(bool direction,
             hls::stream<vec_in_t>& in,
             hls::stream<vec_out_t>& out,
             bool* ovflo) {
#pragma HLS interface ap_hs port=direction
#pragma HLS interface ap_fifo depth=1024 port=in,out
#pragma HLS dataflow
    hls::fft<ssr_config>(in, out);  // 2 or 4 samples per cycle
}

SSR Complete Example

Header (fft_top.h)

#include "hls_fft.h"
#include "hls_vector.h"
#include <complex>

const int  FFT_LENGTH = 1024;
const char FFT_NFFT_MAX = 10;
const char FFT_CONFIG_WIDTH = 16;
const int  FFT_SSR = 2;

typedef std::complex<float> cmpxDataIn;
typedef std::complex<float> cmpxDataOut;
typedef hls::vector<cmpxDataIn, FFT_SSR> vec_in_t;
typedef hls::vector<cmpxDataOut, FFT_SSR> vec_out_t;

struct ssr_fft_config : hls::ip_fft::ssr_params_t {
    static const unsigned super_sample_rate = FFT_SSR;
    static const bool use_native_float = true;
    OVERRIDE(systolicfft_inv) = false;
    static const unsigned config_width = FFT_CONFIG_WIDTH;
    static const unsigned max_nfft = FFT_NFFT_MAX;
};

void fft_top(bool direction,
             hls::stream<vec_in_t>& in,
             hls::stream<vec_out_t>& out,
             bool* ovflo);

Implementation (fft_top.cpp)

#include "fft_top.h"

void fft_top(bool direction,
             hls::stream<vec_in_t>& in,
             hls::stream<vec_out_t>& out,
             bool* ovflo) {
#pragma HLS interface ap_hs port=direction
#pragma HLS interface ap_fifo depth=1 port=ovflo
#pragma HLS interface ap_fifo depth=1024 port=in,out
#pragma HLS dataflow

    hls::fft<ssr_fft_config>(in, out);
}

Choosing Between Basic and SSR FFT

Criterion Basic FFT SSR FFT
Throughput 1 sample/cycle 2 or 4 samples/cycle
Data type Fixed-point or float Float only (native)
Runtime control Direction, scaling, size Direction only (via port)
Base class hls::ip_fft::params_t hls::ip_fft::ssr_params_t
Stream type hls::stream<complex> hls::stream<hls::vector<complex, SSR>>
Use when Standard throughput, flexibility needed Need 2x-4x throughput

When to Use

  • Need optimized FFT/IFFT for signal processing
  • OFDM modulation/demodulation
  • Spectrum analysis
  • Convolution via frequency domain
  • Filter design and implementation
  • SSR specifically: High-throughput requirements (e.g., wideband systems)

When Not to Use

  • Very small transforms (< 16 points) - use direct implementation
  • Non-power-of-2 sizes - FFT IP requires power-of-2
  • Need custom FFT algorithm (e.g., split-radix, prime-factor)
  • SSR: When fixed-point precision is required (SSR needs float)

Best Practices

Basic FFT

  1. Use pipelined_streaming_io for continuous throughput
  2. Match input/output width to your precision requirements
  3. Use scaled mode to prevent overflow in fixed-point
  4. Apply #pragma HLS DATAFLOW for streaming operation
  5. Set FIFO depth to FFT_LENGTH for interface ports

SSR FFT

  1. Always set use_native_float = true - required for SSR
  2. Use hls::stream<hls::vector<T, SSR>> for stream interface
  3. Control direction via a port, not function parameter
  4. Remember the simplified API - no scaling/nfft parameters

Common Pitfalls

Pitfall Symptom Solution
Missing DATAFLOW Poor throughput Add #pragma HLS DATAFLOW
FIFO depth too small Deadlock in simulation Set depth=FFT_LENGTH
Unscaled with fixed-point Overflow, wrong results Use scaled mode
Missing STREAM pragma Not streaming Add #pragma HLS stream for arrays
SSR: Wrong base class Compilation error Use ssr_params_t not params_t
SSR: Missing use_native_float Synthesis error Add use_native_float = true
SSR: Wrong stream type Data rate mismatch Use hls::stream<hls::vector<T, SSR>>
SSR: Passing runtime params Function signature error SSR uses simplified call
