hls::burst_maxi

Explicit burst memory interface for optimized DDR/HBM access. Provides fine-grained control over burst transfers.

Header

#include <hls_burst_maxi.h>

Syntax

hls::burst_maxi<T> mem;
Parameter Description
T Data type for memory access

Methods

Method Description
read_request(addr, len) Issue burst read request for len elements at addr
read() Read next element from burst (blocking)
write_request(addr, len) Issue burst write request for len elements at addr
write(T data) Write next element to burst
write_response() Wait for write completion acknowledgment

Basic Example

#include <hls_burst_maxi.h>

void kernel(hls::burst_maxi<int>& mem, int offset, int n) {
#pragma HLS INTERFACE m_axi port=mem

    // Issue read request (non-blocking)
    mem.read_request(offset, n);

    // Process data as it arrives
    int sum = 0;
    for (int i = 0; i < n; i++) {
        sum += mem.read();  // Blocking read from burst
    }

    // Issue write request
    mem.write_request(offset, 1);
    mem.write(sum);
    mem.write_response();  // Wait for completion
}

Overlapping Requests

The main benefit is overlapping memory requests with computation:

void overlap(hls::burst_maxi<int>& in,
             hls::burst_maxi<int>& out,
             int n) {
#pragma HLS INTERFACE m_axi port=in bundle=gmem0
#pragma HLS INTERFACE m_axi port=out bundle=gmem1

    // Issue read request early
    in.read_request(0, n);

    // Start write while reading
    out.write_request(0, n);

    for (int i = 0; i < n; i++) {
#pragma HLS PIPELINE
        int val = in.read();     // Get data from burst
        out.write(val * 2);      // Send to output burst
    }

    out.write_response();  // Finalize writes
}

Multiple Outstanding Bursts

void multi_burst(hls::burst_maxi<int>& mem, int n) {
#pragma HLS INTERFACE m_axi port=mem

    int buffer[256];

    // Issue multiple read requests upfront
    mem.read_request(0, 128);
    mem.read_request(128, 128);

    // Process first burst
    for (int i = 0; i < 128; i++) {
        buffer[i] = mem.read();
    }

    // Process second burst (already in flight)
    for (int i = 0; i < 128; i++) {
        buffer[128 + i] = mem.read();
    }
}

Separate Read/Write Ports

void copy(hls::burst_maxi<int>& src,
          hls::burst_maxi<int>& dst,
          int n) {
    // Separate bundles for parallel access
#pragma HLS INTERFACE m_axi port=src bundle=gmem0
#pragma HLS INTERFACE m_axi port=dst bundle=gmem1

    src.read_request(0, n);
    dst.write_request(0, n);

    for (int i = 0; i < n; i++) {
#pragma HLS PIPELINE
        dst.write(src.read());
    }

    dst.write_response();
}

When to Use

Use Case Recommendation
Maximum memory bandwidth Yes
Overlapping requests with compute Yes
Multiple outstanding bursts Yes
Complex access patterns Yes
Simple sequential access No - auto-burst sufficient
Random access No - bursts don't help

vs Regular m_axi

Aspect hls::burst_maxi Regular m_axi
Burst control Explicit Automatic
Request overlap Manual control Compiler optimized
Complexity Higher Lower
Best for Max bandwidth Simple cases

Regular m_axi (for comparison)

// Auto-burst version - simpler but less control
void simple(int* mem, int n) {
#pragma HLS INTERFACE m_axi port=mem

    for (int i = 0; i < n; i++) {
#pragma HLS PIPELINE
        mem[i] = mem[i] * 2;  // Compiler infers bursts
    }
}

Best Practices

Practice Reason
Issue read_request early Hide memory latency
Use separate bundles Enable parallel access
Match burst to memory controller Optimal transfer size
Always call write_response Ensure completion

Common Pitfalls

Pitfall Solution
Forgetting write_response Always call after writes
Read/write mismatch Request length must match loop count
Single bundle for read/write Use separate bundles
