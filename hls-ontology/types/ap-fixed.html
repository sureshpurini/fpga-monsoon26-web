ap_fixed and ap_ufixed

Fixed-point arithmetic types for DSP applications - efficient alternative to floating-point.

Header

#include <ap_fixed.h>

Syntax

ap_fixed<W, I, Q, O>  signed_fixed;    // Signed fixed-point
ap_ufixed<W, I, Q, O> unsigned_fixed;  // Unsigned fixed-point
Parameter Description Default
W Total bit width Required
I Integer bits (including sign for ap_fixed) Required
Q Quantization mode AP_TRN
O Overflow mode AP_WRAP

Fractional bits = W - I

Understanding Fixed-Point Format

ap_fixed<16, 8> value;
// Total: 16 bits
// Integer: 8 bits (including sign)
// Fractional: 16 - 8 = 8 bits

Binary representation:
┌─────────────────────────────────────────┐
│ S │ I I I I I I I │ F F F F F F F F │
│(1)│   (7 bits)    │    (8 bits)     │
└─────────────────────────────────────────┘
  ↑       ↑                 ↑
 Sign  Integer part    Fractional part

Range: -128.0 to ~127.996
Resolution: 1/256 = 0.00390625

Quantization Modes

How to handle bits lost during operations:

Mode Behavior Use Case
AP_TRN Truncate (toward -∞) Default, fastest
AP_TRN_ZERO Truncate toward zero Symmetric truncation
AP_RND Round to nearest (ties to +∞) Better accuracy
AP_RND_ZERO Round to nearest (ties to zero) Symmetric rounding
AP_RND_INF Round to nearest (ties away from zero) Statistical
AP_RND_MIN_INF Round to nearest (ties to -∞)
AP_RND_CONV Convergent rounding (ties to even) Best for DSP 
// Truncation (default) - fast, biased toward negative
ap_fixed<8, 4, AP_TRN> trunc_val;

// Rounding - slower, more accurate
ap_fixed<8, 4, AP_RND> round_val;

// Convergent rounding - unbiased, best for accumulators
ap_fixed<8, 4, AP_RND_CONV> conv_val;

Overflow Modes

How to handle values exceeding representable range:

Mode Behavior Extra Logic
AP_WRAP Wraparound None (default)
AP_WRAP_SM Sign-magnitude wrap Minimal
AP_SAT Saturate to max/min Comparator
AP_SAT_ZERO Saturate to zero Comparator
AP_SAT_SYM Symmetric saturation Comparator 
// Wraparound (default) - fast, may produce unexpected values
ap_fixed<8, 4, AP_TRN, AP_WRAP> wrap_val;

// Saturation - prevents overflow artifacts
ap_fixed<8, 4, AP_TRN, AP_SAT> sat_val;
// If result > max, set to max
// If result < min, set to min

Basic Operations

ap_fixed<16, 8> a = 10.5;
ap_fixed<16, 8> b = 3.25;

// Arithmetic
ap_fixed<17, 9> sum = a + b;    // 13.75
ap_fixed<17, 9> diff = a - b;   // 7.25
ap_fixed<32, 16> prod = a * b;  // 34.125
ap_fixed<16, 8> quot = a / b;   // ~3.23

// Comparison
bool eq = (a == b);
bool gt = (a > b);

Common Patterns

DSP Accumulator

typedef ap_fixed<16, 8, AP_RND_CONV, AP_SAT> sample_t;
typedef ap_fixed<32, 16, AP_RND_CONV, AP_SAT> accum_t;

accum_t accumulate(sample_t samples[], int n) {
    accum_t sum = 0;
    for (int i = 0; i < n; i++) {
        sum += samples[i];  // Wide accumulator prevents overflow
    }
    return sum;
}

FIR Filter

typedef ap_fixed<16, 2> coeff_t;   // Coefficients: small integer, high precision
typedef ap_fixed<16, 8> data_t;    // Data: larger integer range
typedef ap_fixed<32, 10> accum_t;  // Accumulator: wide for multiply-add

data_t fir_filter(data_t x[], coeff_t h[], int n) {
    accum_t acc = 0;
    for (int i = 0; i < n; i++) {
        acc += x[i] * h[i];
    }
    return (data_t)acc;  // Truncate back to data width
}

Converting from Floating-Point

// Design in float first
float compute_float(float x) {
    return x * 0.75f + 0.5f;
}

// Convert to fixed-point
typedef ap_fixed<16, 4, AP_RND, AP_SAT> fixed_t;
fixed_t compute_fixed(fixed_t x) {
    fixed_t k1 = 0.75;   // Automatically converted
    fixed_t k2 = 0.5;
    return x * k1 + k2;
}

Type Conversion Patterns

Unary Operator Conversion

Use unary + to force type conversion with proper quantization:

typedef ap_ufixed<10, 8, AP_RND, AP_SAT> narrow_t;
typedef ap_fixed<22, 17, AP_TRN, AP_SAT> wide_t;

narrow_t input = 100.5;
static wide_t accum;

// Force conversion to wider type with quantization applied
accum = +input;  // Unary + triggers conversion

This is cleaner than explicit casting when the target type handles quantization.

Mixed Precision Strategy

Use different precisions for different roles in your datapath:

// Input: Narrow, with rounding for precision
typedef ap_ufixed<10, 8, AP_RND, AP_SAT> input_t;

// Accumulator: Wide, truncate for speed, saturate for safety
typedef ap_fixed<22, 17, AP_TRN, AP_SAT> accum_t;

// Output: Widest, defaults OK (final result)
typedef ap_fixed<36, 30> output_t;

output_t process(input_t a, input_t b) {
    static accum_t sum;
    sum = +a;              // Convert to accumulator width
    return sum * b;        // Multiply in wide format
}

Width progression: Input (narrow) → Accumulator (wide) → Output (widest)

Choosing Quantization and Overflow Modes

Practical Mode Selection

Situation Quantization Overflow Why
Precision critical (inputs) AP_RND AP_SAT Best accuracy, safe
Speed critical (intermediates) AP_TRN AP_WRAP Fastest, smallest hardware
Accumulators AP_RND_CONV AP_SAT Unbiased, prevents overflow
Final output AP_TRN AP_SAT Fast but safe

Mode Trade-offs

// SLOW but ACCURATE - use for inputs/outputs
typedef ap_fixed<16, 8, AP_RND, AP_SAT> accurate_t;
// Extra hardware: rounder + saturation comparator

// FAST but RISKY - use for wide intermediates where overflow is impossible
typedef ap_fixed<32, 16, AP_TRN, AP_WRAP> fast_t;
// Minimal hardware: just truncation

// BALANCED - common choice for accumulators
typedef ap_fixed<32, 16, AP_TRN, AP_SAT> balanced_t;
// Truncate for speed, but saturate to prevent catastrophic overflow

Choosing Bit Widths

Integer Bits (I)

I = ceil(log2(max_value)) + 1 (for signed)
I = ceil(log2(max_value))     (for unsigned)

Example: Values range -100 to +100
I = ceil(log2(100)) + 1 = 7 + 1 = 8 bits

Fractional Bits (W - I)

Fractional bits = -log2(required_resolution)

Example: Need resolution of 0.001
F = -log2(0.001) ≈ 10 bits

Total Width (W)

W = I + F

Example: Range ±100 with resolution 0.001
W = 8 + 10 = 18 bits

Width Rules for Common Operations

Operation Output Integer Width Output Fractional Width
Add/Sub max(I1, I2) + 1 max(F1, F2)
Multiply I1 + I2 F1 + F2
Square Root (I + 1) / 2 ≥ F / 2

Square root example:

// Input: 24 bits total, 8 integer bits
typedef ap_ufixed<24, 8> input_t;   // Range: 0 to 255.999...

// Output integer width = (8 + 1) / 2 = 4
// sqrt(255) ≈ 16, which fits in 4 integer bits
typedef ap_ufixed<28, 4> output_t;  // Range: 0 to 15.999...

ap_fixed vs ap_ufixed

Type Sign Range
ap_fixed<W, I> Signed -2^(I-1) to 2^(I-1) - 2^(-(W-I))
ap_ufixed<W, I> Unsigned 0 to 2^I - 2^(-(W-I)) 
ap_fixed<8, 4> signed_val;   // -8.0 to ~7.9375
ap_ufixed<8, 4> unsigned_val; // 0 to ~15.9375

When to Use

Scenario Recommendation
DSP / signal processing Yes - primary use case
Replace floating-point Yes - more efficient in hardware
Need predictable precision Yes - exact bit control
Audio processing Yes - commonly 16/24-bit fixed
Simple integer math No - use ap_int instead
Need very wide dynamic range No - consider floating-point
