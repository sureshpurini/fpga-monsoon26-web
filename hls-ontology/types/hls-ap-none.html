hls::ap_none

Wire-only Direct I/O interface with no handshaking protocol.

Header

#include <hls_directio.h>

Syntax

hls::ap_none<T>& signal;  // As function parameter
Parameter Description
T Data type (typically int, bool, or small structs)

Hardware Signals

The ap_none interface generates only a data wire - no handshaking:

┌─────────────────────────────────────────┐
│         ap_none Interface               │
├─────────────────────────────────────────┤
│  data  ◄──────────────────────────────► │  Payload only
│        (no valid, no ack, no ready)     │
└─────────────────────────────────────────┘
Signal Direction Description
data Input or Output The actual data value (always present)

Methods

Method Return Description
write(T val) void Set wire value (takes effect immediately)
read() T Read current wire value (always returns current value)

Key difference from ap_hs: There is no valid() method - data is always considered present.

Characteristics

  • No flow control: Data is always considered valid
  • Lowest latency: Direct wire connection
  • Non-blocking: read() always returns immediately
  • Requires external sync: If flow control is needed, implement manually

When to Use

Use Case Why ap_none
Static configuration Values set once, don't change during operation
Host-programmable registers Combine with s_axilite pragma
Control signals Enable, mode select, threshold values
Wire-level interfaces Direct FPGA-to-FPGA wires

When NOT to Use

Scenario Use Instead
Need flow control hls::ap_hs (has valid/ack)
Need to know when new data arrives hls::ap_hs (has valid())
High-throughput streaming hls::stream
Variable-rate data hls::stream or hls::ap_hs

Combining with s_axilite

A common pattern is using ap_none with the s_axilite pragma to create host-programmable registers:

void top(hls::stream<int>& in, hls::stream<int>& out,
         hls::ap_none<int>& bias) {
#pragma HLS interface s_axilite port=bias
    // bias.read() returns current register value set by host
}

This allows the host CPU to write configuration values through AXI-Lite memory-mapped registers, while the kernel reads them as static wire values.

Usage with Data-Driven Tasks

With s_axilite (Host-Programmable Bias)

#include "hls_task.h"
#include "hls_directio.h"

void task_func(hls::stream<int>& in, hls::stream<int>& out,
               hls::ap_none<int>& bias) {
    int c = in.read();
    int b = bias.read();  // Read current register value
    out.write(c + b);
}

void top(hls::stream<int>& in, hls::stream<int>& out,
         hls::ap_none<int>& bias) {
#pragma HLS interface s_axilite port=bias
    hls_thread_local hls::stream<int> s1, s2;
    hls_thread_local hls::task t(task_func, s2, out, bias);
    hls_thread_local hls::task t1(stage1, in, s1);
    hls_thread_local hls::task t2(stage2, s1, s2);
}

Use case: Runtime-configurable parameters that the host sets before or during operation.

Manual Validity Pattern

When flow control is needed with ap_none, implement validity signaling manually:

typedef hls::ap_none<int> wire_t;

void addInputs(wire_t& data_in, wire_t& data_in2,
               wire_t& valid_in, wire_t& data_out, wire_t& valid_out) {
    #pragma HLS pipeline II=1
    int vld = valid_in.read();
    if (vld == 0) {
        valid_out.write(0);  // Propagate invalid
        return;
    }
    int val1 = data_in.read();
    int val2 = data_in2.read();
    data_out.write(val1 + val2);
    valid_out.write(1);
}

void top(wire_t& din_A, wire_t& din_B,
         wire_t& dout, wire_t& vldIn, wire_t& vldOut) {
    hls_thread_local hls::task t1(addInputs, din_A, din_B, vldIn, dout, vldOut);
}

Testbench for Manual Validity

int main() {
    wire_t in1, in2, out, vld_in, vld_out;

    // Feed valid data
    for (int i = 0; i < N; i++) {
        in1.write(i);
        in2.write(i);
        vld_in.write(1);  // Mark as valid
    }

    // Send termination signals (multiple for safety)
    vld_in.write(0);
    vld_in.write(0);
    vld_in.write(0);

    top(in1, in2, out, vld_in, vld_out);

    // Verify outputs
    for (int i = 0; i < N; i++) {
        if (vld_out.read() == 1) {
            if (out.read() != 2*i) return 1;
        }
    }
    return 0;
}

Important: Since ap_none has no backpressure, multiple termination signals (vld_in.write(0)) may be needed to ensure the task sees them.

Comparison with Other DirectIO Types

Interface Handshaking Flow Control Use Case
ap_none None Manual if needed Static config, always-valid signals
ap_hs Valid + Ack Automatic Dynamic values, synchronized updates
ap_vld Valid only Output only Status reporting
ap_ack Ack only Input only Consumption signaling

Key Differences from hls::ap_hs

Aspect hls::ap_none hls::ap_hs
Handshake signals None Valid + Ack
read() behavior Always returns current value Blocks until valid
valid() method Not available Checks data availability
Flow control Manual (if needed) Automatic
Latency Lowest Low
Use case Static config Dynamic values
