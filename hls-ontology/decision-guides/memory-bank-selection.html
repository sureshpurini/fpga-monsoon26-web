Memory Bank Selection

Question: How should I assign ports to DDR/HBM banks?

Category: Interface

Key Principles

  1. Separate read and write ports to different banks - Avoid contention
  2. Use multiple banks for parallel access - Maximize bandwidth
  3. Match bank assignment to access patterns - Optimize for your workload
  4. Use group_id() in host code - Match connectivity file

Good Patterns

Parallel Read/Write

Separate input and output to different banks for parallel access:

[connectivity]
sp=kernel.input:DDR[0]
sp=kernel.output:DDR[1]

Result: Reads and writes happen in parallel, no bank contention.

Multiple Inputs

Distribute multiple inputs across banks for full bandwidth:

[connectivity]
sp=kernel.in1:HBM[0]
sp=kernel.in2:HBM[1]
sp=kernel.in3:HBM[2]
sp=kernel.out:HBM[3]

Result: Each input gets dedicated bandwidth.

Read-Modify-Write

For in-place operations, use separate read/write bundles:

void kernel(int* data_in, int* data_out, int size) {
#pragma HLS INTERFACE m_axi port=data_in bundle=gmem0
#pragma HLS INTERFACE m_axi port=data_out bundle=gmem1
    // ...
}

[connectivity]
sp=kernel.gmem0:DDR[0]
sp=kernel.gmem1:DDR[1]

Bad Patterns

Same Bank for Read/Write

Problem: Read and write compete for same bank bandwidth.

[connectivity]
sp=kernel.input:DDR[0]
sp=kernel.output:DDR[0]  # BAD: Same bank as input!

Fix: Use different banks.

All Ports on Single Bank

Problem: All memory access serialized through one bank.

[connectivity]
sp=kernel.in1:DDR[0]
sp=kernel.in2:DDR[0]  # BAD
sp=kernel.in3:DDR[0]  # BAD
sp=kernel.out:DDR[0]  # BAD

Fix: Distribute across banks.

DDR vs HBM

Memory Banks Bandwidth/Bank Total Bandwidth Use Case
DDR 2-4 ~19 GB/s ~38-76 GB/s General purpose
HBM 32 ~14 GB/s ~460 GB/s High bandwidth

DDR Guidelines

  • Typically 2-4 banks available
  • Each bank: ~19 GB/s
  • Use for moderate bandwidth needs

HBM Guidelines

  • 32 banks available (pseudo-channels)
  • Each bank: ~14 GB/s
  • Aggregate: ~460 GB/s
  • Use for memory-bound kernels

Host Code Matching

Ensure host code matches connectivity file using group_id():

// Host code
cl::Buffer buffer_in(context, CL_MEM_READ_ONLY, size);
cl::Buffer buffer_out(context, CL_MEM_WRITE_ONLY, size);

// Set memory bank (must match connectivity file)
buffer_in.setMemoryBank(0);  // DDR[0]
buffer_out.setMemoryBank(1); // DDR[1]

Or use cl_mem_ext_ptr_t:

cl_mem_ext_ptr_t ext_in, ext_out;
ext_in.flags = 0 | XCL_MEM_TOPOLOGY;  // Bank 0
ext_out.flags = 1 | XCL_MEM_TOPOLOGY; // Bank 1

Connectivity File Format

Create connectivity.cfg:

[connectivity]
# Format: sp=<kernel>.<port>:<memory>[bank]

# Single kernel
sp=mykernel.input:DDR[0]
sp=mykernel.output:DDR[1]

# Multiple kernels
sp=kernel1.data:HBM[0]
sp=kernel2.data:HBM[1]

# Kernel-to-kernel streaming (no memory)
stream_connect=kernel1.out:kernel2.in

Use with v++:

v++ --link --config connectivity.cfg ...

Decision Guide

How many memory ports?
├── 1 port (read-only or write-only)
│   └── Any single bank is fine
├── 2 ports (1 read, 1 write)
│   └── Separate to different banks
├── Many ports
│   └── Distribute across available banks
│       ├── DDR: 2-4 banks
│       └── HBM: Up to 32 banks
└── Bandwidth-critical?
    ├── Yes → Use HBM, maximize bank spread
    └── No → DDR is sufficient
