When to Partition

Question: Should I partition this array?

Category: Memory Optimization

Source: decision-guides.yaml → when-to-partition

Quick Decision

Condition Decision
Loop is unrolled Partition (match unroll factor)
Need parallel access Partition
Sequential access only Don't partition
Array is large Don't partition (or partial)

When to Partition

Partition your array when:

  • Loop accessing array is unrolled - Need parallel ports
  • Need parallel read/write access - Multiple elements per cycle
  • Memory ports are the bottleneck - Synthesis reports memory conflicts
int arr[1024];
#pragma HLS ARRAY_PARTITION variable=arr cyclic factor=4

for (int i = 0; i < 1024; i++) {
#pragma HLS UNROLL factor=4  // Matches partition!
    arr[i] = process(arr[i]);
}

When NOT to Partition

Don't partition when:

  • Sequential access only - One element per cycle is enough
  • Array is large - Resource explosion
  • Bandwidth is sufficient - No memory bottleneck
// Sequential access - no partition needed
for (int i = 0; i < N; i++) {
#pragma HLS PIPELINE II=1
    out[i] = in[i] * 2;  // One element per cycle
}

Partition Types

Complete

All elements become individual registers.

int arr[16];
#pragma HLS ARRAY_PARTITION variable=arr complete
Pros Cons
Maximum parallelism Only for small arrays
Any access pattern High register usage

Use for: Small arrays (< 32 elements), full parallel access

Cyclic

Interleaved distribution across banks.

int arr[1024];
#pragma HLS ARRAY_PARTITION variable=arr cyclic factor=4
// arr[0],arr[4],arr[8]... → bank 0
// arr[1],arr[5],arr[9]... → bank 1
// ...
Pros Cons
Good for strided access Fixed interleaving
Scales to large arrays

Use for: Loop unrolling, strided access patterns

Block

Contiguous chunks in separate banks.

int arr[1024];
#pragma HLS ARRAY_PARTITION variable=arr block factor=4
// arr[0-255]   → bank 0
// arr[256-511] → bank 1
// ...
Pros Cons
Good for block access Not for interleaved access
Cache-friendly

Use for: Block processing, contiguous access patterns

Match Partition to Unroll

Critical rule: Partition factor should match unroll factor!

Unroll Partition Result
factor=4 factor=4 ✓ Optimal
factor=4 factor=2 ⚠ Memory bottleneck
factor=4 complete ✓ Works (may be overkill)
factor=4 none ✗ Sequential bottleneck

Example

int data[256];
#pragma HLS ARRAY_PARTITION variable=data cyclic factor=8

for (int i = 0; i < 256; i++) {
#pragma HLS UNROLL factor=8  // Matches partition
    data[i] = process(data[i]);
}
// Result: 8 elements processed per cycle

Multi-Dimensional Arrays

Specify dimension to partition:

int matrix[64][64];

// Partition columns (dim=2)
#pragma HLS ARRAY_PARTITION variable=matrix cyclic factor=4 dim=2

// Partition rows (dim=1)
#pragma HLS ARRAY_PARTITION variable=matrix cyclic factor=4 dim=1

// Partition both dimensions
#pragma HLS ARRAY_PARTITION variable=matrix cyclic factor=4 dim=0

Resource Impact

Partition Type Memory Resources
None 1 BRAM (2 ports)
factor=4 4 BRAMs (8 ports)
complete (N=64) 64 registers

Warning: Complete partition of large arrays causes resource explosion!

Decision Flowchart

Is the loop unrolled?
├── Yes → Partition with matching factor
│         └── cyclic for interleaved, block for contiguous
├── No, but need parallel access?
│   └── Yes → Add partition + unroll together
└── No, sequential access?
    └── Don't partition (waste of resources)

Is array small (< 32)?
├── Yes → Consider complete partition
└── No → Use cyclic or block with factor
