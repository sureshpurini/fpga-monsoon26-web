Optimization Priority

Question: In what order should I apply optimizations?

Category: Strategy

Source: decision-guides.yaml → optimization-priority

Priority Order

Apply optimizations in this order for best results:

Priority Optimization Impact
1 Algorithm Highest - choose efficient algorithm first
2 Dataflow High - enable task-level parallelism
3 Interface High - select appropriate interfaces
4 Memory Medium - optimize access and storage
5 Loops Medium - pipeline and/or unroll
6 Fine-tuning Low - adjust pragma parameters

1. Algorithm Selection (Highest Priority)

Choose the right algorithm before optimizing the wrong one.

  • Select algorithms with inherent parallelism
  • Prefer streaming over batch processing
  • Consider data access patterns
❌ Optimizing O(n²) algorithm
✓ Switching to O(n log n) algorithm

2. Dataflow (Task-Level Parallelism)

Enable concurrent execution of stages.

void kernel(...) {
#pragma HLS DATAFLOW
    stage1(in, c1);     // These run
    stage2(c1, c2);     // in parallel
    stage3(c2, out);    // (pipelined)
}
  • Identify independent processing stages
  • Choose appropriate topology
  • Select channel types (FIFO vs PIPO)

See: Dataflow Topology

3. Interface Selection

Match interfaces to data access patterns.

Data Type Interface
Large arrays (DDR/HBM) m_axi
Streaming data axis
Scalar parameters s_axilite

See: Interface Selection

4. Memory Optimization

Optimize memory access and storage.

  • Partition arrays for parallel access
  • Choose appropriate storage (BRAM/URAM/LUTRAM)
  • Optimize burst transfers
int arr[1024];
#pragma HLS ARRAY_PARTITION variable=arr cyclic factor=4
#pragma HLS BIND_STORAGE variable=arr impl=BRAM

See: When to Partition, Storage Selection

5. Loop Optimization

Pipeline and unroll loops for throughput.

outer: for (int i = 0; i < M; i++) {
    inner: for (int j = 0; j < N; j++) {
#pragma HLS PIPELINE II=1
#pragma HLS UNROLL factor=4
        // Process elements
    }
}

See: Pipeline vs Unroll

6. Fine-Tuning

Adjust parameters based on synthesis reports.

  • Tune II targets
  • Adjust FIFO depths
  • Balance resource usage

Iterative Process

1. Synthesize baseline
       ↓
2. Check reports for bottlenecks
       ↓
3. Apply targeted optimization
       ↓
4. Re-synthesize and compare
       ↓
5. Repeat until goals met

What to Check in Reports

Report Section What to Look For
Latency Total cycles, per-function latency
II Achieved vs target initiation interval
Resources LUT, FF, BRAM, DSP usage
Timing Clock frequency achieved

Common Bottlenecks and Fixes

Bottleneck Symptom Fix
Memory bandwidth High latency, low throughput Partition arrays, widen ports, use HBM
Loop II II > 1 Check dependencies, add DEPENDENCE pragma
Resource usage Over 80% utilization Reduce unroll factor, share resources
Latency High cycle count Pipeline more, reduce loop overhead

Bottleneck Decision Tree

What's limiting performance?
├── Throughput (elements/sec)?
│   ├── Memory bound → Partition, widen, more banks
│   └── Compute bound → Pipeline, unroll
├── Latency (total cycles)?
│   ├── Loop overhead → Flatten, merge loops
│   └── Stage latency → Pipeline deeper
├── Resources (utilization)?
│   ├── BRAM → Use URAM, reduce arrays
│   ├── DSP → Use fabric impl
│   └── LUT/FF → Reduce unroll factor
└── Timing (frequency)?
    └── Add pipeline stages, reduce logic depth

Example Optimization Flow

// Step 1: Baseline
void kernel(int* in, int* out, int n) {
    for (int i = 0; i < n; i++) {
        out[i] = process(in[i]);
    }
}

// Step 2: Add dataflow structure
void kernel(int* in, int* out, int n) {
#pragma HLS DATAFLOW
    int c1[N];
    load(in, c1, n);
    compute(c1, c2, n);
    store(c2, out, n);
}

// Step 3: Add interfaces
#pragma HLS INTERFACE m_axi port=in
#pragma HLS INTERFACE m_axi port=out

// Step 4: Optimize memory
#pragma HLS ARRAY_PARTITION variable=c1 cyclic factor=4

// Step 5: Pipeline loops
for (int i = 0; i < n; i++) {
#pragma HLS PIPELINE II=1
    // ...
}

// Step 6: Fine-tune based on reports
