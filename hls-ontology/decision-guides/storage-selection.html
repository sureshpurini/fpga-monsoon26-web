Storage Selection

Question: Which storage type should I use for this array?

Category: Memory Optimization

Source: decision-guides.yaml → storage-selection

Decision Tree

Array size?
├── Very small (< 64 elements)
│   └── LUTRAM or Registers
├── Medium (64 - 4K elements)
│   └── BRAM
└── Large (> 4K elements)
    └── URAM (if available) or multiple BRAM

Storage Comparison

Storage Capacity Ports Best For
Registers Very small Unlimited Tiny arrays, full partition
LUTRAM 64 bits/LUT Distributed Small arrays, many ports
BRAM 18Kb or 36Kb Up to 2 Medium arrays
URAM 288Kb Up to 2 Large arrays (Versal/UltraScale+)

Registers

Individual flip-flops, unlimited parallel access.

When to Use

  • Very small arrays (< 16 elements)
  • Need full parallel access
  • Array is completely partitioned

Characteristics

  • Capacity: Very small (one element per register)
  • Ports: Unlimited (all elements accessible simultaneously)
  • Latency: 0 cycles (combinational access)

Example

int small_arr[8];
#pragma HLS ARRAY_PARTITION variable=small_arr complete
// Becomes 8 individual registers

LUTRAM (Distributed RAM)

Small memories distributed across LUTs.

When to Use

  • Small arrays (< 64 elements)
  • Need more than 2 ports
  • Low latency required

Characteristics

  • Capacity: ~64 bits per LUT
  • Ports: Distributed (can have many read ports)
  • Latency: 0-1 cycles

Example

int lookup_table[32];
#pragma HLS BIND_STORAGE variable=lookup_table type=RAM_1P impl=LUTRAM

BRAM (Block RAM)

Dedicated memory blocks on FPGA.

When to Use

  • Medium arrays (64 - 4K elements)
  • Frequent access patterns
  • Standard dual-port access sufficient

Characteristics

  • Capacity: 18Kb (RAMB18) or 36Kb (RAMB36)
  • Ports: Up to 2 (true dual-port)
  • Latency: 1-2 cycles

Example

int buffer[1024];
#pragma HLS BIND_STORAGE variable=buffer type=RAM_2P impl=BRAM

Port Configurations

Type Read Ports Write Ports
RAM_1P 1 1 (shared)
RAM_2P 2 2 (shared)
RAM_S2P 1 1 (separate)
RAM_T2P 2 2 (true dual-port)

URAM (Ultra RAM)

Large memory blocks on Versal/UltraScale+ devices.

When to Use

  • Large arrays (> 4K elements)
  • Versal or UltraScale+ FPGAs
  • Need to conserve BRAM

Characteristics

  • Capacity: 288Kb (4K × 72 bits)
  • Ports: Up to 2
  • Latency: 1-2 cycles
  • Availability: Versal, UltraScale+ only

Example

int large_buffer[8192];
#pragma HLS BIND_STORAGE variable=large_buffer type=RAM_2P impl=URAM

Capacity Reference

Storage Typical Capacity Example Array Size
LUTRAM 64 bits/LUT 16 × int (32-bit)
BRAM (18Kb) 18,432 bits 576 × int (32-bit)
BRAM (36Kb) 36,864 bits 1,152 × int (32-bit)
URAM 294,912 bits 9,216 × int (32-bit)

Selection Guide

// Let HLS decide (default)
int arr[N];  // AUTO selection

// Force LUTRAM for small array
int small[32];
#pragma HLS BIND_STORAGE variable=small impl=LUTRAM

// Force BRAM for medium array
int medium[1024];
#pragma HLS BIND_STORAGE variable=medium impl=BRAM

// Force URAM for large array (Versal/UltraScale+)
int large[8192];
#pragma HLS BIND_STORAGE variable=large impl=URAM

// Complete partition to registers
int tiny[8];
#pragma HLS ARRAY_PARTITION variable=tiny complete

ECC Support

For error correction (critical applications):

int critical_data[1024];
#pragma HLS BIND_STORAGE variable=critical_data impl=uram_ecc
