When to Unroll

Question: Should I unroll this loop?

Category: Loop Optimization

Source: decision-guides.yaml → when-to-unroll

Quick Decision

Condition Decision
Small fixed iteration count, need max parallelism Full unroll
Large loop, want some parallelism Partial unroll
Very large iteration count Don't unroll
Sequential dependencies Don't unroll

Unroll Options

Full Unroll

Completely unroll all iterations into parallel hardware.

for (int i = 0; i < 8; i++) {
#pragma HLS UNROLL  // Full unroll (no factor)
    out[i] = in[i] * 2;
}

Use when: - Small fixed iteration count (< 16 typically) - Need maximum parallelism - Array is fully partitioned

Resources: 8 multipliers created (one per iteration)

Partial Unroll

Unroll by a factor, keeping some loop structure.

for (int i = 0; i < 1024; i++) {
#pragma HLS UNROLL factor=4
    out[i] = in[i] * 2;
}

Use when: - Large loop, want some parallelism - Limited resources - Partial array partition

Resources: 4 multipliers, loop runs 256 iterations

No Unroll

Keep loop sequential.

for (int i = 0; i < N; i++) {
    // No unroll pragma - sequential execution
    out[i] = in[i] * 2;
}

Use when: - Very large iteration count - Sequential dependencies - Memory bandwidth limited

Resource Warning

Unrolling multiplies resources by unroll factor!

  • N iterations fully unrolled = N× logic
  • Consider partial unroll with factor to balance resources
Loop Size Full Unroll Partial (factor=4) No Unroll
8 iterations 8× resources 4× resources 1× resources
1024 iterations 1024× resources ❌ 4× resources 1× resources

Matching Array Partition

Critical: Unroll factor should match array partition factor!

int arr[1024];
#pragma HLS ARRAY_PARTITION variable=arr cyclic factor=4

for (int i = 0; i < 1024; i++) {
#pragma HLS UNROLL factor=4  // Matches partition factor
    arr[i] = process(arr[i]);
}
Unroll Factor Partition Factor Result
4 4 ✓ Optimal - 4 parallel accesses
4 2 ⚠ Memory bottleneck
4 8 ⚠ Wasted memory ports

Decision Flowchart

How many loop iterations?
├── Small & fixed (< 16)
│   └── Need max parallelism?
│       ├── Yes → Full unroll + complete partition
│       └── No → Partial unroll or pipeline
├── Medium (16-256)
│   └── Partial unroll (factor=4 or 8)
│       └── Match array partition factor
└── Large (> 256)
    └── Don't unroll, use pipeline instead
        └── Or partial unroll with small factor

Unroll vs Pipeline

Aspect Unroll Pipeline
Parallelism Spatial (replicate hardware) Temporal (overlap iterations)
Resources factor × loop body Single loop body
Throughput factor results/cycle 1 result/II cycles
Best for Inner loops Outer loops

Common pattern: Pipeline outer loop, unroll inner loop.

outer: for (int i = 0; i < M; i++) {
#pragma HLS PIPELINE II=1
    inner: for (int j = 0; j < 4; j++) {
#pragma HLS UNROLL  // Full unroll inner
        // Process 4 elements per outer iteration
    }
}
