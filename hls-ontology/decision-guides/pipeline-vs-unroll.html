Pipeline vs Unroll

Question: Should I pipeline or unroll this loop?

Category: Loop Optimization

Source: decision-guides.yaml → pipeline-vs-unroll

Quick Answer

Scenario Recommendation
Outer loops Pipeline
Inner loops Unroll (or both)
Large iteration count Pipeline
Small iteration count Unroll
Resource constrained Pipeline
Throughput critical Combine both

Fundamental Difference

Aspect Pipeline Unroll
Type of parallelism Temporal (time) Spatial (space)
Effect Overlap iterations Replicate hardware
Resources Single loop body factor × loop body
Throughput 1 result per II cycles factor results per cycle
Latency N × II cycles N / factor cycles

Visual Comparison

Pipeline (Temporal Parallelism)

Overlaps iterations in time:

Cycle:  1    2    3    4    5    6    7
Iter 0: [===]
Iter 1:      [===]
Iter 2:           [===]
Iter 3:                [===]

One hardware instance, multiple iterations in flight.

Unroll (Spatial Parallelism)

Replicates hardware in space:

Cycle:  1    2
HW 0:   [i=0][i=4]
HW 1:   [i=1][i=5]
HW 2:   [i=2][i=6]
HW 3:   [i=3][i=7]

Multiple hardware instances, each handles one iteration.

Comparison Table

Metric Pipeline (II=1) Unroll (factor=4)
Throughput 1 result/cycle 4 results/cycle
Latency (N=100) 100 cycles 25 cycles
Resources 1× 4×
Memory ports needed 1 4

Best Practice: Combine Both

For nested loops, the common pattern is:

outer: for (int i = 0; i < M; i++) {
#pragma HLS PIPELINE off  // Don't pipeline outer (optional)
    inner: for (int j = 0; j < N; j++) {
#pragma HLS PIPELINE II=1  // Pipeline inner
#pragma HLS UNROLL factor=4  // Also unroll inner
        // Process 4 elements per cycle
    }
}

Or let HLS flatten and pipeline everything:

outer: for (int i = 0; i < M; i++) {
    inner: for (int j = 0; j < N; j++) {
#pragma HLS PIPELINE II=1  // Flattens and pipelines both loops
        out[i][j] = process(in[i][j]);
    }
}

Decision Guide

Is this a nested loop?
├── Yes
│   ├── Outer loop → Pipeline (or let inner pipeline flatten it)
│   └── Inner loop → Unroll + Pipeline
└── No (single loop)
    ├── Large iteration count?
    │   ├── Yes → Pipeline
    │   └── No → Consider full unroll
    ├── Resource constrained?
    │   ├── Yes → Pipeline (single instance)
    │   └── No → Can unroll more
    └── Need maximum throughput?
        └── Yes → Partial unroll + Pipeline

Code Examples

Pipeline Only

// Good for large loops, resource efficient
for (int i = 0; i < 1024; i++) {
#pragma HLS PIPELINE II=1
    out[i] = in[i] * 2;
}
// Throughput: 1 element/cycle
// Resources: 1 multiplier

Unroll Only

// Good for small loops needing parallelism
for (int i = 0; i < 8; i++) {
#pragma HLS UNROLL
    out[i] = in[i] * 2;
}
// Throughput: 8 elements/cycle (all at once)
// Resources: 8 multipliers

Pipeline + Partial Unroll

// Best of both worlds
for (int i = 0; i < 1024; i++) {
#pragma HLS PIPELINE II=1
#pragma HLS UNROLL factor=4
    out[i] = in[i] * 2;
}
// Throughput: 4 elements/cycle
// Resources: 4 multipliers

Resource vs Throughput Trade-off

Configuration Throughput Resources
No optimization 1 elem / N cycles 1×
Pipeline II=1 1 elem / cycle 1×
Unroll factor=4 4 elem / cycle 4×
Pipeline + Unroll 4 4 elem / cycle 4×
Full unroll (N=8) 8 elem / cycle 8×
