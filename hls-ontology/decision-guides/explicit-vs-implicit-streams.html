Explicit vs Implicit Streams

Question: Should I use explicit hls::stream or implicit array channels?

Category: Dataflow

Decision Summary

Approach Use When
Explicit hls::stream<T> Need fine-grained control, variable sizes, complex patterns
Implicit arrays Simple dataflow, fixed sizes, simpler code preferred

When to Use Explicit hls::stream

Use hls::stream<T> when you need:

  • Fine-grained control over FIFO depth - Set exact buffer sizes
  • Variable data sizes - Runtime-determined element counts
  • Complex streaming patterns - Multiple reads/writes per iteration
  • Non-blocking operations - Use read_nb() / write_nb()
hls::stream<data_t> c1, c2;
#pragma HLS STREAM variable=c1 depth=16  // Control depth
#pragma HLS dataflow
funcA(in, c1);
funcB(c1, c2);
funcC(c2, out);

When to Use Implicit Arrays

Use simple arrays when:

  • Simple dataflow with fixed sizes - Known at compile time
  • Want HLS to infer channel type - Let tool decide FIFO vs PIPO
  • Simpler code preferred - Less boilerplate
data_t c1[N], c2[N];  // Arrays become channels automatically
#pragma HLS dataflow
funcA(in, c1);
funcB(c1, c2);
funcC(c2, out);

Code Comparison

Implicit (Array-based)

void top(data_t in[N], data_t out[N]) {
    data_t c1[N], c2[N];  // Arrays become PIPO channels

#pragma HLS dataflow

    funcA(in, c1);   // Writes to c1
    funcB(c1, c2);   // Reads c1, writes c2
    funcC(c2, out);  // Reads c2
}

Pros: - Simpler syntax - Familiar array semantics - HLS infers channel type

Cons: - Less control over implementation - Default is PIPO (2× memory)

Explicit (hls::stream)

void top(hls::stream<data_t>& in, hls::stream<data_t>& out) {
    hls::stream<data_t> c1, c2;

#pragma HLS dataflow

    funcA(in, c1);   // Writes to c1
    funcB(c1, c2);   // Reads c1, writes c2
    funcC(c2, out);  // Reads c2
}

Pros: - Explicit FIFO semantics - Control over depth - Non-blocking operations available - Clearer intent

Cons: - More verbose - Must use stream API (read/write)

Key Differences

Aspect Implicit Arrays Explicit hls::stream
Default channel type PIPO (ping-pong) FIFO
Memory usage 2× array size Configurable depth
Access pattern Array indexing read()/write() API
Non-blocking Not available read_nb()/write_nb()
Depth control Via STREAM pragma Via STREAM pragma or template

Converting Between Styles

Array to Stream

// Before (implicit)
data_t channel[N];

// After (explicit)
hls::stream<data_t> channel;
#pragma HLS STREAM variable=channel depth=N

Making Arrays Act Like FIFOs

data_t channel[N];
#pragma HLS STREAM variable=channel type=fifo depth=2
