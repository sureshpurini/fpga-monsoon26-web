Dataflow Topology

Question: What dataflow topology should I use?

Category: Dataflow

Source: decision-guides.yaml → dataflow-topology

Available Topologies

Topology Pattern Use Case
Linear A → B → C → D Simple pipeline processing
Diamond Fork and join Parallel independent paths
Multi-consumer One to many Broadcast to processors
Multi-producer Many to one Collect from processors

Linear (Sequential Chain)

A → B → C → D

When to Use

  • Simple pipeline processing
  • Each stage has single input/output
  • No parallel processing needed

Example

void top(data_t in[N], data_t out[N]) {
#pragma HLS DATAFLOW
    data_t c1[N], c2[N], c3[N];

    stageA(in, c1);   // Read input
    stageB(c1, c2);   // Process
    stageC(c2, c3);   // Transform
    stageD(c3, out);  // Write output
}

Diamond (Fork-Join)

    ┌─→ B ─→┐
A ─→│       │─→ D
    └─→ C ─→┘

When to Use

  • Parallel independent processing paths
  • Input needs different transformations
  • Results combined at end

Example

void top(data_t in[N], data_t out[N]) {
#pragma HLS DATAFLOW
    data_t c1[N], c2[N], c3[N], c4[N];

    funcA(in, c1, c2);     // Fork: split to two paths
    funcB(c1, c3);         // Path 1
    funcC(c2, c4);         // Path 2 (parallel with B)
    funcD(c3, c4, out);    // Join: combine results
}

Related Pattern

See Dataflow Diamond Pattern for implementation details.

Multi-Consumer (One to Many)

    ┌─→ B
A ─→├─→ C
    └─→ D

When to Use

  • Broadcast data to multiple processors
  • Same input, different processing
  • Parallel analysis paths

Implementation Options

Option 1: Explicit duplication in A

void funcA(data_t* in, data_t* out1, data_t* out2, data_t* out3) {
    for (int i = 0; i < N; i++) {
        data_t val = in[i];
        out1[i] = val;  // Copy to all outputs
        out2[i] = val;
        out3[i] = val;
    }
}

Option 2: Use hls::split

#include "hls_np_channel.h"

void top(...) {
#pragma HLS DATAFLOW
    hls::split::round_robin<data_t, 3, 1, DEPTH> s;

    producer(s.in, input);
    consumer1(s.out[0], out1);
    consumer2(s.out[1], out2);
    consumer3(s.out[2], out3);
}

Multi-Producer (Many to One)

A ─→┐
B ─→├─→ D
C ─→┘

When to Use

  • Collect results from parallel processors
  • Multiple inputs, single output
  • Aggregation patterns

Implementation Options

Option 1: Explicit collection in D

void funcD(data_t* in1, data_t* in2, data_t* in3, data_t* out) {
    for (int i = 0; i < N; i++) {
        out[i] = combine(in1[i], in2[i], in3[i]);
    }
}

Option 2: Use hls::merge

#include "hls_np_channel.h"

void top(...) {
#pragma HLS DATAFLOW
    hls::merge::round_robin<data_t, 3, 1, DEPTH> m;

    producer1(m.in[0], in1);
    producer2(m.in[1], in2);
    producer3(m.in[2], in3);
    consumer(m.out, output);
}

Split/Merge Strategies

For multi-consumer and multi-producer topologies:

Strategy Description Use When
round_robin Fixed rotation Equal processing time, predictable order
load_balance Dynamic assignment Variable processing time, max throughput

See Merge-Split Pattern for details.

Topology Selection Guide

How does data flow?
├── Single path through stages?
│   └── Linear topology
├── Input splits to parallel paths?
│   ├── Paths rejoin later?
│   │   └── Diamond topology
│   └── Paths stay separate?
│       └── Multi-consumer (split)
├── Multiple inputs combine?
│   └── Multi-producer (merge)
└── Complex mix?
    └── Combine topologies as needed

Combining Topologies

You can combine patterns for complex dataflows:

        ┌─→ B ─→┐
In → A ─│       │─→ E → Out
        └─→ C ─→ D ─┘

void top(...) {
#pragma HLS DATAFLOW
    funcA(in, c1, c2);      // Fork
    funcB(c1, c3);          // Path 1
    funcC(c2, c4);          // Path 2 start
    funcD(c4, c5);          // Path 2 continue
    funcE(c3, c5, out);     // Join
}
