When to Pipeline

Question: Should I pipeline this loop?

Category: Loop Optimization

Source: decision-guides.yaml → when-to-pipeline

Quick Decision

Condition Decision
No loop-carried dependencies Pipeline with II=1
Simple dependencies Pipeline with II>1
Heavy dependencies Don't pipeline
Memory bandwidth limited Don't pipeline (won't help)

When to Pipeline

Pipeline your loop when:

  • Loop body has no/minimal loop-carried dependencies
  • Want high throughput - Process elements continuously
  • Iteration latency > 1 cycle - Overlap provides benefit
  • Sequential data access - Streaming patterns
for (int i = 0; i < N; i++) {
#pragma HLS PIPELINE II=1
    out[i] = process(in[i]);  // Independent iterations
}

When NOT to Pipeline

Don't pipeline when:

  • Heavy loop-carried dependencies - Each iteration depends on previous
  • Very small loop body - Already executes in ~1 cycle
  • Memory bandwidth is bottleneck - Pipelining won't help
// BAD: Loop-carried dependency prevents pipelining benefit
int acc = 0;
for (int i = 0; i < N; i++) {
    acc += in[i];  // Depends on previous iteration
}

Initiation Interval (II) Guidance

Target II When to Use
II=1 No dependencies, maximum throughput
II=N When dependencies force higher II
II=auto Let HLS find achievable II

Always Check Reports!

After synthesis, verify achieved II in reports: - If achieved II > target II, check for dependencies - Use #pragma HLS DEPENDENCE if you know access is safe

Pipelining with Dependencies

Acceptable Dependencies

Some dependencies allow pipelining with higher II:

// Accumulator with II=1 using ap_int operations
ap_int<32> acc = 0;
for (int i = 0; i < N; i++) {
#pragma HLS PIPELINE II=1
    acc += in[i];  // HLS can schedule this with II=1
}

Breaking False Dependencies

If HLS reports a dependency that doesn't exist:

for (int i = 0; i < N; i++) {
#pragma HLS PIPELINE II=1
#pragma HLS DEPENDENCE variable=arr type=inter false
    arr[i] = process(arr[i-1]);  // Tell HLS there's no real dependency
}

Caution: Only use DEPENDENCE false when you're certain the access pattern is safe!

Pipeline Rewind

For continuous streaming with autorestart kernels:

void stage(data_t* in, data_t* out) {
#pragma HLS INLINE OFF
Loop:
    for (int i = 0; i < N; i++) {
#pragma HLS PIPELINE rewind  // No flush between invocations
        out[i] = process(in[i]);
    }
}
Mode Behavior
Without rewind Pipeline drains between invocations
With rewind Pipeline immediately restarts

Decision Flowchart

Does loop have dependencies?
├── No dependencies
│   └── Pipeline with II=1 ✓
├── Simple dependencies (e.g., accumulator)
│   └── Pipeline, accept higher II ✓
├── Complex dependencies
│   └── Consider restructuring code
└── Memory bandwidth limited?
    ├── Yes → Pipelining won't help much
    └── No → Pipeline for compute throughput
