FFT Usage

Use the Vitis HLS FFT IP (hls::fft) for optimized Fast Fourier Transform operations. The FFT IP is a pre-built, highly optimized implementation that supports configurable architectures, data widths, and scaling modes.

Overview

The FFT IP transforms time-domain samples to frequency-domain bins (or vice versa for IFFT). It supports multiple architectures trading off throughput vs. resources.

Time Domain                           Frequency Domain
┌─────────────────┐                  ┌─────────────────┐
│ xn[0..N-1]      │ ─────► FFT ─────►│ xk[0..N-1]      │
│ (complex)       │       IP        │ (complex)       │
└─────────────────┘                  └─────────────────┘

Two variants available: - Basic FFT: 1 sample/cycle, fixed-point or float, full runtime control - SSR FFT: 2 or 4 samples/cycle (Super Sample Rate), native float, simplified API

Key Constructs

Construct Basic FFT SSR FFT
Header #include "hls_fft.h" #include "hls_fft.h" + #include "hls_vector.h"
Base class hls::ip_fft::params_t hls::ip_fft::ssr_params_t
Function call hls::fft<config>(xn, xk, dir, scaling, nfft, status) hls::fft<config>(in, out)
Throughput 1 sample/cycle 2 or 4 samples/cycle

Part 1: Basic FFT

Basic FFT Syntax

hls::fft<CONFIG>(xn, xk, direction, scaling, nfft, status);
Parameter Type Description
xn array or stream Input samples (complex)
xk array or stream Output bins (complex)
direction ap_uint<1> 1=FFT, 0=IFFT
scaling ap_uint<15> Scaling schedule per stage
nfft int Runtime size (-1 for fixed)
status bool* Overflow flag output

Basic FFT Configuration

Step 1: Define Parameters

const int  FFT_LENGTH = 1024;
const char FFT_NFFT_MAX = 10;        // log2(1024)
const char FFT_INPUT_WIDTH = 16;
const char FFT_OUTPUT_WIDTH = 16;

Step 2: Define Data Types

typedef ap_fixed<FFT_INPUT_WIDTH,1> data_in_t;
typedef ap_fixed<FFT_OUTPUT_WIDTH,2> data_out_t;
typedef std::complex<data_in_t> cmpxDataIn;
typedef std::complex<data_out_t> cmpxDataOut;

Step 3: Create Config Struct

struct fft_config : hls::ip_fft::params_t {
    OVERRIDE(max_nfft) = FFT_NFFT_MAX;
    OVERRIDE(config_width) = 16;
    OVERRIDE(arch) = hls::ip_fft::pipelined_streaming_io;
    OVERRIDE(scaling) = hls::ip_fft::scaled;
    OVERRIDE(output_ordering) = hls::ip_fft::natural_order;
};

Basic FFT Interface Variants

Array Interface

Arrays with #pragma HLS stream are converted to streaming internally. Simpler for testbenches.

void fft_top(ap_uint<1> dir, ap_uint<15> scaling,
             cmpxDataIn xn[FFT_LENGTH],
             cmpxDataOut xk[FFT_LENGTH],
             bool* status) {
#pragma HLS interface ap_fifo depth=1 port=status
#pragma HLS interface ap_fifo depth=1024 port=xn,xk
#pragma HLS stream variable=xn
#pragma HLS stream variable=xk
#pragma HLS dataflow

    hls::fft<fft_config>(xn, xk, dir, scaling, -1, status);
}

Stream Interface

Native hls::stream for direct integration with other streaming modules.

void fft_top(ap_uint<1> dir, ap_uint<15> scaling,
             hls::stream<cmpxDataIn>& xn,
             hls::stream<cmpxDataOut>& xk,
             bool* status) {
#pragma HLS interface ap_fifo depth=1 port=status
#pragma HLS interface ap_fifo depth=1024 port=xn,xk
#pragma HLS dataflow

    hls::fft<fft_config>(xn, xk, dir, scaling, -1, status);
}

Part 2: SSR FFT (Super Sample Rate)

SSR FFT processes 2 or 4 samples per clock cycle for higher throughput. It uses a different base class and simplified API.

SSR FFT Syntax

hls::fft<CONFIG>(in, out);  // Simplified: no direction, scaling, nfft, status params
Parameter Type Description
in array or hls::stream<hls::vector<T, SSR>> Input samples (SSR per transfer)
out array or hls::stream<hls::vector<T, SSR>> Output bins (SSR per transfer)

Note: Direction is controlled via port or config (systolicfft_inv), not function parameter.

SSR FFT Configuration

Step 1: Define Parameters

const int  FFT_LENGTH = 1024;
const char FFT_NFFT_MAX = 10;        // log2(1024)
const char FFT_CONFIG_WIDTH = 16;
const int  FFT_SSR = 2;              // 2 or 4 samples/cycle

Step 2: Define Data Types

SSR requires native 32-bit float:

typedef std::complex<float> cmpxDataIn;
typedef std::complex<float> cmpxDataOut;

// Vector types for SSR streaming
typedef hls::vector<cmpxDataIn, FFT_SSR> vec_in_t;
typedef hls::vector<cmpxDataOut, FFT_SSR> vec_out_t;

Step 3: Create SSR Config Struct

struct ssr_fft_config : hls::ip_fft::ssr_params_t {
    static const unsigned super_sample_rate = FFT_SSR;  // 2 or 4
    static const bool use_native_float = true;          // Required for SSR
    OVERRIDE(systolicfft_inv) = false;                  // false=FFT, true=IFFT
    static const unsigned config_width = FFT_CONFIG_WIDTH;
    static const unsigned max_nfft = FFT_NFFT_MAX;
};

SSR Configuration Parameters

Parameter Type Values Description
super_sample_rate unsigned 2 or 4 Samples per clock cycle
use_native_float bool true Required - must be true for SSR
systolicfft_inv bool true/false false=FFT, true=IFFT

SSR FFT Interface Variants

SSR Array Interface

void fft_top(bool direction, cmpxDataIn in[FFT_LENGTH],
             cmpxDataOut out[FFT_LENGTH], bool* ovflo) {
#pragma HLS interface ap_hs port=direction
#pragma HLS dataflow
    hls::fft<ssr_fft_config>(in, out);  // Simplified call
}

SSR Stream Interface

Uses hls::stream<hls::vector<complex, SSR>> for SSR samples per transfer:

void fft_top(bool direction,
             hls::stream<vec_in_t>& in,
             hls::stream<vec_out_t>& out,
             bool* ovflo) {
#pragma HLS interface ap_hs port=direction
#pragma HLS interface ap_fifo depth=1 port=ovflo
#pragma HLS interface ap_fifo depth=1024 port=in,out
#pragma HLS dataflow

    hls::fft<ssr_fft_config>(in, out);  // 2 or 4 samples per cycle
}

Architecture Options (Basic FFT)

Architecture Throughput Resources Use When
pipelined_streaming_io 1 sample/cycle Higher Continuous streaming (recommended)
radix_4_burst_io Frame-based Lower Resource-constrained, batch processing
radix_2_burst_io Frame-based Medium Moderate constraints
radix_2_lite_burst_io Slowest Lowest Minimum resources

Architecture Selection

Need continuous streaming?
├── Yes → pipelined_streaming_io
└── No → Need minimum resources?
          ├── Yes → radix_2_lite_burst_io
          └── No → radix_4_burst_io (good balance)

Scaling Options (Basic FFT)

Mode Description Use When
scaled Divide by 2 at each stage Fixed-point (prevents overflow)
unscaled No scaling Floating-point or wide output
block_floating_point Dynamic scaling Variable signal levels

Code Generation Guidelines

Basic FFT Header Template

#include "ap_fixed.h"
#include "hls_fft.h"
#include <complex>

// FFT parameters
const int  FFT_LENGTH = 1024;
const char FFT_NFFT_MAX = 10;        // log2(1024)
const char FFT_INPUT_WIDTH = 16;
const char FFT_OUTPUT_WIDTH = 16;
const char FFT_CONFIG_WIDTH = 16;

// Data types
typedef ap_fixed<FFT_INPUT_WIDTH,1> data_in_t;
typedef ap_fixed<FFT_OUTPUT_WIDTH,2> data_out_t;
typedef std::complex<data_in_t> cmpxDataIn;
typedef std::complex<data_out_t> cmpxDataOut;

// FFT configuration
struct fft_config : hls::ip_fft::params_t {
    OVERRIDE(max_nfft) = FFT_NFFT_MAX;
    OVERRIDE(config_width) = FFT_CONFIG_WIDTH;
    OVERRIDE(arch) = hls::ip_fft::pipelined_streaming_io;
    OVERRIDE(scaling) = hls::ip_fft::scaled;
    OVERRIDE(output_ordering) = hls::ip_fft::natural_order;
};

void fft_top(ap_uint<1> dir, ap_uint<15> scaling,
             cmpxDataIn xn[FFT_LENGTH], cmpxDataOut xk[FFT_LENGTH],
             bool* status);

SSR FFT Header Template

#include "hls_fft.h"
#include "hls_vector.h"
#include <complex>

// FFT parameters
const int  FFT_LENGTH = 1024;
const char FFT_NFFT_MAX = 10;
const char FFT_CONFIG_WIDTH = 16;
const int  FFT_SSR = 2;              // 2 or 4 samples/cycle

// Data types - SSR requires native float
typedef std::complex<float> cmpxDataIn;
typedef std::complex<float> cmpxDataOut;
typedef hls::vector<cmpxDataIn, FFT_SSR> vec_in_t;
typedef hls::vector<cmpxDataOut, FFT_SSR> vec_out_t;

// SSR FFT configuration
struct ssr_fft_config : hls::ip_fft::ssr_params_t {
    static const unsigned super_sample_rate = FFT_SSR;
    static const bool use_native_float = true;
    OVERRIDE(systolicfft_inv) = false;
    static const unsigned config_width = FFT_CONFIG_WIDTH;
    static const unsigned max_nfft = FFT_NFFT_MAX;
};

void fft_top(bool direction,
             hls::stream<vec_in_t>& in,
             hls::stream<vec_out_t>& out,
             bool* ovflo);

Test Bench Generation Guidelines

Basic FFT Test Bench (Stream)

#include "fft_top.h"
#include <iostream>
#include <cmath>
using namespace std;

int main() {
    hls::stream<cmpxDataIn> xn_input;
    hls::stream<cmpxDataOut> xk_output;
    bool status;

    // Generate test signal (e.g., sine wave)
    for (int i = 0; i < FFT_LENGTH; i++) {
        double angle = 2 * M_PI * i * 10 / FFT_LENGTH;  // 10 Hz
        data_in_t re = cos(angle);
        data_in_t im = 0;
        xn_input.write(cmpxDataIn(re, im));
    }

    // Run FFT (forward, typical scaling)
    fft_top(1, 0x5555, xn_input, xk_output, &status);

    // Read and verify output
    bool pass = true;
    for (int i = 0; i < FFT_LENGTH; i++) {
        cmpxDataOut out = xk_output.read();
        // Verify magnitude at expected frequency bin
        if (i == 10 || i == FFT_LENGTH - 10) {
            // Should have significant magnitude
        }
    }

    cout << (pass ? "Test PASSED" : "Test FAILED") << endl;
    return pass ? 0 : 1;
}

SSR FFT Test Bench (Stream)

#include "fft_top.h"
#include <iostream>
#include <cmath>
using namespace std;

int main() {
    hls::stream<vec_in_t> in_stream;
    hls::stream<vec_out_t> out_stream;
    bool ovflo;

    // Generate test signal
    float input_re[FFT_LENGTH], input_im[FFT_LENGTH];
    for (int i = 0; i < FFT_LENGTH; i++) {
        double angle = 2 * M_PI * i * 10 / FFT_LENGTH;
        input_re[i] = cos(angle);
        input_im[i] = 0;
    }

    // Feed input (FFT_SSR samples per write)
    for (int i = 0; i < FFT_LENGTH / FFT_SSR; i++) {
        vec_in_t vec;
        for (int j = 0; j < FFT_SSR; j++) {
            vec[j] = cmpxDataIn(input_re[i*FFT_SSR + j], input_im[i*FFT_SSR + j]);
        }
        in_stream.write(vec);
    }

    // Run SSR FFT (direction: true=forward)
    fft_top(true, in_stream, out_stream, &ovflo);

    // Read output (FFT_SSR samples per read)
    for (int i = 0; i < FFT_LENGTH / FFT_SSR; i++) {
        vec_out_t vec = out_stream.read();
        for (int j = 0; j < FFT_SSR; j++) {
            cout << "out[" << i*FFT_SSR+j << "] = "
                 << vec[j].real() << " + j" << vec[j].imag() << endl;
        }
    }

    return 0;
}

Optimization Guidance for Agents

When to Apply This Pattern

Decision tree:
├── Need FFT/IFFT?
│   ├── Yes → Is size power of 2?
│   │         ├── Yes → Need >1 sample/cycle throughput?
│   │         │         ├── Yes → Use SSR FFT (2x or 4x)
│   │         │         │         └── Float acceptable? → SSR
│   │         │         │         └── Need fixed-point? → Use multiple Basic FFT instances
│   │         │         └── No → Use Basic FFT
│   │         │                   ├── Continuous streaming? → pipelined_streaming_io
│   │         │                   └── Batch processing? → radix_4_burst_io
│   │         └── No → Implement custom DFT or pad to power of 2
│   └── No → Don't use FFT pattern

Performance Comparison

Variant Throughput Latency Resources
Basic (pipelined) 1 sample/cycle ~N cycles Baseline
Basic (radix_4) Frame-based ~4N cycles Lower
SSR=2 2 samples/cycle ~N/2 cycles ~2x
SSR=4 4 samples/cycle ~N/4 cycles ~4x

Common Pitfalls

Pitfall Symptom Solution
Missing DATAFLOW Poor throughput Add #pragma HLS DATAFLOW
FIFO depth too small Deadlock in simulation Set depth=FFT_LENGTH
Unscaled with fixed-point Overflow, wrong results Use scaled mode
Missing STREAM pragma Not synthesized as streaming Add #pragma HLS stream for arrays
Wrong max_nfft Synthesis error Set to log2(FFT_LENGTH)
SSR: Wrong base class Compilation error Use ssr_params_t not params_t
SSR: Missing use_native_float Synthesis error Add use_native_float = true
SSR: Wrong stream type Data rate mismatch Use hls::stream<hls::vector<T, SSR>>
SSR: Passing runtime params Function signature error SSR uses simplified call
