M-AXI Memory Interface with Data-Driven Tasks

How to use M-AXI memory interface (pointer to DDR/HBM) with data-driven tasks (hls::task).

Overview

Data-driven tasks can access external memory (DDR/HBM) through M-AXI interface by marking the memory pointer as stable. This enables memory-accessing tasks that persist across kernel invocations.

Key Requirement

#pragma HLS stable variable=mem  // CRITICAL for task usage

This pragma tells HLS that the pointer address doesn't change during kernel operation, enabling safe use with persistent tasks.

When to Use

Use Case Why M-AXI with Tasks
Large lookup tables Data too large for on-chip storage
Persistent state in memory State needs to survive power cycles
Memory-based buffers Circular buffers, FIFOs in DDR
Data logging Write results to memory for host

When NOT to Use

Scenario Use Instead
Small data that fits in streams hls::stream
Random access in small blocks hls::stream_of_blocks
No memory access needed Pure stream-based tasks
High-bandwidth streaming AXI-Stream interface

Architecture

in ─→ [process_23] ─→ int_fifo ─→ [process_11] ─→ int_fifo2 ─→ [write_process] ─→ out
                                                                      │
                                                                      ▼
                                                                    mem[]
                                                                 (DDR/HBM)

Implementation

Task Functions

#include "hls_task.h"
#include "hls_stream.h"

// Pure stream-based processing tasks
void process_23(hls::stream<int>& in, hls::stream<int>& out) {
#pragma HLS INLINE off
    static int val;
    in.read(val);
    val = val * 23;
    out.write(val);
}

void process_11(hls::stream<int>& in, hls::stream<int>& out) {
#pragma HLS INLINE off
    static int val;
    in.read(val);
    val = val * 11;
    out.write(val);
}

// Memory-accessing task
void write_process(hls::stream<int>& in, hls::stream<int>& out, int* mem) {
    int val;
    static int addr = 0;  // Persistent address counter

    in.read(val);
    if (addr >= 32)
        addr = 0;
    mem[addr] = val;       // Write to DDR/HBM
    addr++;
    val = mem[addr - 1];   // Read back from DDR/HBM
    out.write(val);
}

Key points: - Use static variables for persistent state (address counters) - Memory pointer passed as regular parameter to task function - #pragma HLS INLINE off prevents inlining of task functions

Top Function

extern "C" {

void stable_pointer(int* mem, hls::stream<int>& in, hls::stream<int>& out) {
#pragma HLS DATAFLOW
#pragma HLS INTERFACE mode = m_axi bundle = gmem depth = 256 \
    max_read_burst_length = 16 max_widen_bitwidth = 512 \
    max_write_burst_length = 16 num_read_outstanding = 16 \
    num_write_outstanding = 16 port = mem
#pragma HLS stable variable = mem   // CRITICAL for task usage

    hls_thread_local hls::stream<int> int_fifo("int_fifo");
#pragma HLS STREAM depth = 512 type = fifo variable = int_fifo
    hls_thread_local hls::stream<int> int_fifo2("int_fifo2");
#pragma HLS STREAM depth = 512 type = fifo variable = int_fifo2

    hls_thread_local hls::task t1(process_23, in, int_fifo);
    hls_thread_local hls::task t2(process_11, int_fifo, int_fifo2);
    hls_thread_local hls::task t3(write_process, int_fifo2, out, mem);
}

} // extern "C"

M-AXI Interface Parameters

#pragma HLS INTERFACE mode=m_axi bundle=gmem port=mem \
    depth=256 \
    max_read_burst_length=16 \
    max_write_burst_length=16 \
    max_widen_bitwidth=512 \
    num_read_outstanding=16 \
    num_write_outstanding=16
Parameter Description Typical Value
bundle Memory bundle name gmem, gmem0
depth Array depth hint (for sim) Actual array size
max_read_burst_length Max elements per read burst 16, 32, 64
max_write_burst_length Max elements per write burst 16, 32, 64
max_widen_bitwidth Max bus width for vectorization 512
num_read_outstanding Outstanding read transactions 16
num_write_outstanding Outstanding write transactions 16

The #pragma HLS stable Pragma

Why It's Required

  • Data-driven tasks (hls::task) run persistently across kernel invocations
  • Without stable, HLS assumes the pointer might change each invocation
  • With stable, HLS knows the pointer is constant for the task lifetime

What It Enables

  • Pointer value can be cached in task hardware
  • Safe memory access from persistent task
  • Correct synthesis of memory-accessing tasks

Test Bench

#include "hls_stream.h"

extern "C" void stable_pointer(int* mem, hls::stream<int>&, hls::stream<int>&);

int main() {
    int memory[512];
    hls::stream<int> in, out;
    int val;

    // Initialize
    for (int i = 0; i < 100; i++) {
        in.write(i);
        memory[i] = 0;
    }

    // Execute
    stable_pointer(memory, in, out);

    // Verify: output = input × 23 × 11
    for (int i = 0; i < 100; i++) {
        out.read(val);
        if (val != i * 23 * 11) {
            printf("%d != %d\n", val, i * 23 * 11);
            return 1;
        }
    }

    return 0;
}

Code Generation Guidelines

Template for M-AXI with Tasks

#include "hls_task.h"
#include "hls_stream.h"

// Memory-accessing task
void mem_task(hls::stream<DATA_T>& in, hls::stream<DATA_T>& out,
              DATA_T* mem) {
    DATA_T val;
    static int addr = 0;  // Persistent address

    in.read(val);
    if (addr >= MEM_SIZE)
        addr = 0;
    mem[addr] = val;
    addr++;
    out.write(mem[addr-1]);
}

// Top function
extern "C" {
void top(DATA_T* mem, hls::stream<DATA_T>& in, hls::stream<DATA_T>& out) {
#pragma HLS DATAFLOW
#pragma HLS INTERFACE mode=m_axi bundle=gmem port=mem depth=DEPTH
#pragma HLS stable variable=mem

    hls_thread_local hls::stream<DATA_T> internal;
#pragma HLS STREAM depth=FIFO_DEPTH variable=internal

    hls_thread_local hls::task t1(process_task, in, internal);
    hls_thread_local hls::task t2(mem_task, internal, out, mem);
}
}

Common Pitfalls

Pitfall 1: Missing #pragma HLS stable

Problem:

void top(int* mem, ...) {
#pragma HLS INTERFACE mode=m_axi port=mem
    // Missing: #pragma HLS stable variable=mem
    hls_thread_local hls::task t(mem_task, ..., mem);  // ERROR
}

Solution: Add #pragma HLS stable variable=mem.

Pitfall 2: Multiple Tasks Accessing Same Memory

Problem:

hls_thread_local hls::task t1(task_a, ..., mem);  // Writes to mem
hls_thread_local hls::task t2(task_b, ..., mem);  // Also writes to mem - CONFLICT!

Solution: Pass memory pointer to only ONE task, or use separate bundles:

#pragma HLS INTERFACE mode=m_axi bundle=gmem0 port=mem_a
#pragma HLS INTERFACE mode=m_axi bundle=gmem1 port=mem_b

Pitfall 3: Non-Static Address Counter

Problem:

void mem_task(..., int* mem) {
    int addr = 0;  // Resets every invocation!
    mem[addr] = val;
}

Solution: Use static for persistent state:

void mem_task(..., int* mem) {
    static int addr = 0;  // Persists across invocations
    mem[addr] = val;
}

Performance Considerations

Aspect Recommendation
Burst efficiency Use sequential memory access patterns
Bus width Set max_widen_bitwidth=512 for full bandwidth
Outstanding transactions Increase for latency hiding
FIFO depth Sufficient depth between tasks to decouple

Decision Tree

Need external memory access in data-driven task?
├── Yes → Is memory accessed by single task?
│         ├── Yes → Use M-AXI + #pragma HLS stable
│         │         └── Pass pointer to that task only
│         └── No → Consider:
│                  ├── Separate memory bundles for each task
│                  └── Or redesign to single memory task
└── No → Use pure stream-based tasks
