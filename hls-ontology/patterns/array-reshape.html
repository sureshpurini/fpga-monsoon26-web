Array Reshape

Recombine an array's elements into fewer, wider words in a single memory, so several elements are delivered per access through one port. The sibling of ARRAY_PARTITION: partition buys ports by making more memories; reshape buys width by making wider words — using fewer block RAMs.

Overview

ARRAY_PARTITION increases bandwidth by splitting one array into N separate memories (N ports). ARRAY_RESHAPE instead keeps one memory and makes each word wider, packing factor elements side-by-side so a single read returns all of them. UG1399: the directive "combines array partitioning with vertical array mapping to create a single new array with fewer elements but wider words," which "reduces the number of block RAM consumed while providing parallel access to the data."

ARRAY_PARTITION (more ports)          ARRAY_RESHAPE (wider word)
A[8] → 2 banks, 1 elem each           A[8] → 1 memory, 2 elems per word
┌──────┐ ┌──────┐                     ┌───────────────┐
│bank0 │ │bank1 │                     │  A1 │ A0       │  ← one wide word
│ A0   │ │ A1   │                     │  A3 │ A2       │
│ A2   │ │ A3   │                     │  A5 │ A4       │
│ ...  │ │ ...  │                     │  A7 │ A6       │
└──────┘ └──────┘                     └───────────────┘
 2 independent ports                   1 port, 2 elements/access
 (any address per bank)                (the pair is a fixed group)

Key Constructs

Construct Purpose
#pragma HLS ARRAY_RESHAPE variable=A type=complete Collapse the whole (named) dimension into one wide word
#pragma HLS ARRAY_RESHAPE variable=A type=cyclic factor=N Pack consecutive elements factor at a time into each word
#pragma HLS ARRAY_RESHAPE variable=A type=block factor=N Pack strided elements (stride = size/N) into each word
dim=N Which dimension to reshape (0 = all dimensions)
off=true Disable an inherited reshape directive

Syntax

#pragma HLS ARRAY_RESHAPE variable=<name> type=<cyclic|block|complete> [factor=<N>] [dim=<N>]
Parameter Description
variable Array to reshape
type=complete Recombine all elements of the dimension into one very wide word (default type; no factor)
type=cyclic Interleave, then concatenate → consecutive elements share a word
type=block Split into contiguous blocks, then concatenate → strided elements share a word
factor Number of elements packed per word (block/cyclic)
dim Dimension to reshape (1, 2, … or 0 for all)

The word width becomes factor × element_width and the depth drops to size/factor. The total bit count is unchanged — the array is reshaped, not enlarged.

Reshape Types

Reshape performs the same grouping step as partition (cyclic interleave / block chunks / complete), then vertically concatenates the resulting sub-arrays into one memory: word[k] = { sub0[k], sub1[k], …, sub(factor-1)[k] }. That concatenation is why the per-word contents are the mirror of partition's per-bank contents.

Cyclic Reshape — consecutive elements per word

type=cyclic factor=N: interleave (like cyclic partition), then concatenate. The elements that end up together in one word are consecutive in the original array.

Word layout: word[k] = { A[N·k], A[N·k+1], …, A[N·k+N-1] }

A[16], reshape cyclic factor=4  →  4 words × 4-wide:

word 0: [ A0  | A1  | A2  | A3  ]
word 1: [ A4  | A5  | A6  | A7  ]
word 2: [ A8  | A9  | A10 | A11 ]
word 3: [ A12 | A13 | A14 | A15 ]

Use when: you read a consecutive run every cycle — a sliding window A[i..i+N-1], or an unrolled inner loop over adjacent elements.

Note the mirror: cyclic partition scatters consecutive elements across banks; cyclic reshape packs them into one word. Both serve consecutive-access, by opposite mechanisms.

Block Reshape — strided elements per word

type=block factor=N: split into N contiguous blocks, then concatenate. The paired elements are one stride apart (stride = size/N).

Word layout: word[k] = { A[k], A[k + size/N], A[k + 2·size/N], … }

A[16], reshape block factor=4  →  4 words × 4-wide:

word 0: [ A0  | A4  | A8  | A12 ]
word 1: [ A1  | A5  | A9  | A13 ]
word 2: [ A2  | A6  | A10 | A14 ]
word 3: [ A3  | A7  | A11 | A15 ]

Use when: you co-access elements that are a fixed stride (= size/factor) apart.

Complete Reshape — one very wide word

type=complete (the default): recombine the entire named dimension into a single word. For a 1-D array this is one register of N × element_width bits — every element available at once, widest possible.

A[16], reshape complete  →  1 word × 16-wide:
word 0: [ A0 | A1 | A2 | … | A15 ]

Partition vs Reshape

Both deliver N elements per cycle. They differ in how, and in cost and freedom.

ARRAY_PARTITION ARRAY_RESHAPE
Result N separate memories (banks) 1 memory, word × N wide
Ports N independent 1 (wide)
Address freedom any element per bank the N are a fixed group
Resource cost N BRAM/register instances ~1 wide BRAM (fewer BRAMs)
Delivers N when lanes need arbitrary access you read a regular group each cycle

Decision: need N accesses to unrelated / arbitrary addresses in one cycle (e.g. N accumulators independently read-modify-written) → partition. Co-access a regular, known group each cycle (consecutive window, unrolled-over-consecutive) → reshape — it is cheaper because it uses one wide memory instead of N banks.

Hard ceiling worth remembering. A dual-port BRAM serves at most 2 accesses per cycle regardless of word width. If you need more than 2 reads/cycle to independent addresses, reshape alone cannot deliver them — you need partitioning (separate banks). Reshape widens the word, not the number of addresses.

Code Generation Guidelines

Sliding-window (cyclic) template

void window_sum(uint8_t A[16], uint16_t out[13]) {
#pragma HLS ARRAY_RESHAPE variable=A type=cyclic factor=4 dim=1
    // each word holds A[i..i+3] — a 4-wide read feeds one tap group
    for (int i = 0; i < 13; i++) {
#pragma HLS PIPELINE II=1
        out[i] = A[i] + A[i+1] + A[i+2] + A[i+3];
    }
}

Wide-register (complete) template

void reduce_all(uint8_t A[16], uint16_t *sum) {
#pragma HLS ARRAY_RESHAPE variable=A type=complete dim=0   // one 128-bit register
    uint16_t s = 0;
    for (int i = 0; i < 16; i++) {
#pragma HLS UNROLL           // all 16 available the same cycle
        s += A[i];
    }
    *sum = s;
}

2-D reshape (pick the dimension the inner loop sweeps)

// Inner loop over columns of each row → reshape dim=2 so a row-word is wide
void row_op(uint8_t M[ROWS][COLS], uint16_t out[ROWS]) {
#pragma HLS ARRAY_RESHAPE variable=M type=complete dim=2
    for (int i = 0; i < ROWS; i++) {
        uint16_t s = 0;
        for (int j = 0; j < COLS; j++) {
#pragma HLS UNROLL
            s += M[i][j];      // whole row delivered in one wide word
        }
        out[i] = s;
    }
}

Key Constraints

Constraint Requirement
Match width to consumption factor = elements consumed per cycle (often = the unroll factor)
Grouping must fit the access cyclic for a consecutive group; block for a stride = size/factor group
Not for arbitrary N-address reads Use ARRAY_PARTITION — reshape gives 1 (wide) port, not N ports
Interface arrays Reshape widens an on-chip (ap_memory/BRAM) port; not supported on M_AXI top-level ports (use hls::vector)
Mutually exclusive AGGREGATE, ARRAY_PARTITION, and ARRAY_RESHAPE cannot all apply to the same array

Optimization Guidance for Agents

When to Apply This Pattern

Pipeline/unroll needs several elements of ONE array each cycle?
├── The elements are a regular, fixed group (consecutive run, or stride=size/F)?
│   ├── Yes → ARRAY_RESHAPE   (one wide memory — cheaper than N banks)
│   │         ├── consecutive group      → type=cyclic factor=F
│   │         ├── strided (size/F) group → type=block  factor=F
│   │         └── the whole (small) array → type=complete
│   └── No → the addresses are arbitrary/independent
│            → ARRAY_PARTITION (N banks = N independent ports)
└── Only need ≤2 accesses/cycle → neither may be required (dual-port BRAM suffices)

Performance Trade-offs

Choice Benefit Cost
reshape cyclic/block factor=N N elements/access, fewer BRAMs than partition one wide port only; the N move as a fixed group
reshape complete Whole array in one cycle very wide word; only for small arrays
partition factor=N N independent ports (any address) N memory instances

Common Pitfalls

Pitfall Symptom Solution
Used reshape but need independent addresses II still limited — one wide port ≠ N ports Switch to ARRAY_PARTITION
Wrong grouping mode Reshaped, but the pair you need isn't in one word cyclic ↔ consecutive, block ↔ stride=size/factor
Reshaped an M_AXI top-level array Pragma ignored / unsupported Reshape a local buffer, or pass hls::vector
complete on a large array Enormous word / routing pressure Use cyclic/block with a modest factor
Expecting more than 2 independent reads from one reshaped BRAM Port conflict remains Dual-port BRAM caps at 2 addresses/cycle — partition for more

Related Patterns

  • array-partition - The sibling directive: N separate memories (N independent ports) instead of one wide word. Use when co-accessed addresses are arbitrary.
  • perfect-loop-restructuring - Loop shaping that exposes the per-cycle access pattern reshape/partition must match.
