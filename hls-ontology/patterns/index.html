Quick Reference

When to Use Each Pattern

Implementing parallel processing?
├── Fork-join topology → dataflow-diamond
├── Fan-out/fan-in → merge-split
├── Conditional routing → data-driven-splitter
└── Continuous execution → autorestart

Working with M-AXI?
├── Burst not inferred → manual-burst
├── Struct causes II violation → struct-alignment
├── Two ports same memory → port-aliasing
├── Need more bandwidth → port-widening
└── With hls::task → maxi-with-tasks

Working with AXI-Stream?
├── Stream to memory → axis-to-maxi
├── Multiple channels → array-of-streams
└── Need side channels → axis-side-channels

Working with pointer parameters?
├── Need streaming interface → pointer-streaming (ap_fifo or ap_hs)
├── Buffered transfers → ap_fifo mode with depth
└── Per-element handshake → ap_hs mode

Optimizing memory access?
├── Need parallel array access → array-partition (complete/cyclic/block)
├── 2D image stencil with II=1 throughput → streaming-image-stencil (DATAFLOW + line buffer + hls::stream)
├── Sliding window on non-streaming nested-loop code → array-stencil-pragma (ARRAY_STENCIL)
├── Multiple adjacent reads → memory-bottleneck-fix (shift register)
├── Lookup table → rom-inference
└── Want 2x throughput → bram-dual-port

Optimizing loop pipelining?
├── Code between loop levels → perfect-loop-restructuring
├── Want to flatten nested loops → perfect loop + LOOP_FLATTEN
├── Pipeline inner vs outer? → See when-to-pipeline decision guide
└── Continuous streaming pipeline? → free-running-pipeline (FRP mode)

Optimizing function calls?
├── Function called with different constants → function-instantiate
└── Want specialized hardware per call site → FUNCTION_INSTANTIATE + INLINE OFF

Using DSP IP blocks?
├── FFT/IFFT needed → fft-usage (hls::fft IP)
├── FIR filter → fir-usage (hls::FIR IP)
├── Decimation/interpolation → fir-usage with filter_type
├── Custom cascade architecture? → dsp-intrinsics (systolic, transposed)
└── Auto-inference sufficient? → Let HLS infer DSP usage automatically

Integrating existing RTL IP?
└── Have RTL module to integrate → rtl-blackbox (JSON config + C stub)

Pattern Documentation Structure

Each pattern in schema/patterns.yaml follows this structure:

- id: pattern-name
  question: "How do I...?"
  category: dataflow|interface|memory-optimization

  description: |
    What this pattern does and when to use it.

  detection:
    check: "Question to identify if pattern applies"
    indicators: [...]
    anti_indicators: [...]

  design_guidance:
    principle: "Core rule"
    rules: [...]

  code_template: |
    // Ready-to-use code template

  violations:
    problem_name:
      problem_code: |
        // Code with issue
      solution_code: |
        // Fixed code

  examples:
    example_name:
      path: Vitis-HLS-Introductory-Examples/...
      key_files: [file1.cpp, file2.h]
      description: "What this example shows"
