Pointer Streaming Interfaces

Map C pointers to streaming hardware interfaces using volatile and INTERFACE pragma modes (ap_fifo or ap_hs).

Overview

In HLS, pointer parameters can be mapped to streaming interfaces where each dereference becomes a hardware read/write operation. The volatile keyword is critical to prevent HLS from optimizing away multiple accesses.

C Code:                          Hardware:

volatile din_t *d_i  ────────►  ┌─────────┐
    *d_i (read)                 │ ap_fifo │◄── Input FIFO
    *d_i (read)                 │   or    │
                                │  ap_hs  │
volatile dout_t *d_o ────────►  └─────────┘──► Output FIFO/HS
    *d_o (write)

Key Constructs

Construct Purpose
volatile keyword Prevents optimization of multiple pointer accesses
#pragma HLS INTERFACE ap_fifo Buffered FIFO with configurable depth
#pragma HLS INTERFACE ap_hs Per-element handshake (valid/ack)
depth=N FIFO buffer depth (ap_fifo only)

Interface Mode Comparison

Mode Buffering Protocol Use Case
ap_fifo Yes (configurable depth) Ready/valid with FIFO Burst transfers, buffered streaming
ap_hs No Valid/ack per element Fine-grained control, each access is one transaction

Complete Example

ap_fifo Mode (Buffered)

From Vitis-HLS-Introductory-Examples/Modeling/Pointers/stream_good/:

#include "pointer_stream_good.h"

void pointer_stream_good(volatile dout_t *d_o, volatile din_t *d_i) {
#pragma HLS INTERFACE ap_fifo port=d_i depth=4
#pragma HLS INTERFACE ap_fifo port=d_o depth=2

    din_t acc = 0;

    acc += *d_i;        // Read 1 from FIFO
    acc += *(d_i + 1);  // Read 2 (pointer arithmetic ignored for FIFO)
    *d_o = acc;         // Write 1 to FIFO

    acc += *(d_i + 2);  // Read 3
    acc += *(d_i + 3);  // Read 4
    *(d_o + 1) = acc;   // Write 2
}

Note: With ap_fifo, pointer arithmetic offsets are ignored - each dereference reads the next element from the FIFO sequentially.

ap_hs Mode (Per-Element Handshake)

From Vitis-HLS-Introductory-Examples/Modeling/Pointers/stream_better/:

#include "pointer_stream_better.h"

void pointer_stream_better(volatile dout_t *d_o, volatile din_t *d_i) {
#pragma HLS INTERFACE ap_hs port=d_i
#pragma HLS INTERFACE ap_hs port=d_o

    din_t acc = 0;

    acc += *d_i;    // Handshake transaction 1
    acc += *d_i;    // Handshake transaction 2
    *d_o = acc;     // Handshake write

    acc += *d_i;    // Handshake transaction 3
    acc += *d_i;    // Handshake transaction 4
    *(d_o) = acc;   // Handshake write
}

Note: With ap_hs, each dereference is a separate valid/ack transaction. No buffering occurs.

Code Generation Guidelines

Kernel Template

#include <stdint.h>

typedef int32_t din_t;
typedef int32_t dout_t;

void streaming_kernel(volatile dout_t *out, volatile din_t *in) {
    // Choose ONE interface mode:
    // Option A: Buffered FIFO
#pragma HLS INTERFACE ap_fifo port=in depth=8
#pragma HLS INTERFACE ap_fifo port=out depth=4

    // Option B: Per-element handshake
    // #pragma HLS INTERFACE ap_hs port=in
    // #pragma HLS INTERFACE ap_hs port=out

    din_t acc = 0;

    // Each dereference = one stream operation
    for (int i = 0; i < 4; i++) {
        acc += *in;   // Read from stream
    }
    *out = acc;       // Write to stream
}

Key Constraints

Constraint Requirement
volatile keyword Mandatory - prevents HLS from caching/optimizing accesses
Pointer arithmetic Ignored for ap_fifo - reads are sequential
FIFO depth Must accommodate producer-consumer rate mismatch
No random access Streaming interfaces are sequential only

Required Pragmas

Pragma Required? Purpose
#pragma HLS INTERFACE ap_fifo Yes (if FIFO) Map pointer to buffered FIFO
#pragma HLS INTERFACE ap_hs Yes (if handshake) Map pointer to valid/ack protocol
depth=N For ap_fifo Set FIFO buffer size

Test Bench Generation Guidelines

Test Bench Template

#include "streaming_kernel.h"
#include <stdio.h>

int main() {
    // 1. Declare test data
    din_t input[8] = {1, 2, 3, 4, 5, 6, 7, 8};
    dout_t output[2];

    // 2. For FIFO: use arrays that match depth
    // For ap_hs: single elements work too

    // 3. Execute DUT
    streaming_kernel(output, input);

    // 4. Verify results
    printf("Output[0] = %d (expected 10)\n", output[0]);
    printf("Output[1] = %d (expected 26)\n", output[1]);

    // 5. Return 0 on success
    int errors = 0;
    if (output[0] != 10) errors++;
    if (output[1] != 26) errors++;

    if (errors) {
        printf("Test FAILED with %d errors\n", errors);
        return 1;
    }
    printf("Test PASSED\n");
    return 0;
}

Interface-Specific Notes

Interface Test Bench Consideration
ap_fifo Use arrays sized to FIFO depth; simulation reads sequentially
ap_hs Each call to kernel performs one set of transactions

Optimization Guidance for Agents

When to Apply This Pattern

Need streaming interface for pointer parameter?
├── Need buffering between producer/consumer?
│   ├── Yes → Use ap_fifo with appropriate depth
│   └── No → Use ap_hs for tighter control
├── Multiple accesses to same pointer?
│   └── Must use volatile to prevent optimization
└── Need random access?
    └── No → Streaming pointers don't support random access
            Use arrays with M-AXI instead

Decision: ap_fifo vs ap_hs

Factor Choose ap_fifo Choose ap_hs
Buffering needed Yes No
Producer/consumer rate mismatch Yes No
Per-element flow control No Yes
Simpler protocol No Yes
Burst-like behavior Yes No

Parameter Tuning

Parameter Low Value High Value Guidance
depth (ap_fifo) 2 256+ Match producer-consumer rate mismatch

Common Pitfalls

Pitfall Symptom Solution
Missing volatile HLS optimizes away multiple reads Add volatile to pointer declaration
Using pointer arithmetic with ap_fifo Unexpected data ordering Pointer offsets ignored - reads are sequential
FIFO depth too small Deadlock or stalls Increase depth to match data rate
Expecting random access Wrong data read Use arrays with M-AXI for random access
