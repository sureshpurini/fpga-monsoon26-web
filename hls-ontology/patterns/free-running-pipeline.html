Free-Running Pipeline

Create continuously running streaming pipelines that process data without explicit start/stop control signals. Combines FRP mode with DATAFLOW and function-level pipelining.

Overview

Normal Pipeline: Waits for ap_start, processes batch, signals ap_done, returns to idle. Free-Running Pipeline (FRP): Always active, continuously processes streaming data.

NORMAL PIPELINE (control-driven):
┌─────────────────────────────────────────┐
│  ap_start ──► IDLE → RUN → DONE → IDLE │
│                       ▲          │      │
│                       └──────────┘      │
└─────────────────────────────────────────┘

FREE-RUNNING PIPELINE:
┌─────────────────────────────────────────┐
│  Data In ═══► [always running] ═══► Out │
│           (no start/stop needed)        │
└─────────────────────────────────────────┘

Key Constructs

Construct Purpose
syn.compile.pipeline_style=frp Enable Free-Running Pipeline mode
#pragma HLS DATAFLOW Concurrent execution of stages
#pragma HLS pipeline (on function) Function-level pipelining
#pragma HLS ARRAY_PARTITION complete Parallel array access
syn.dataflow.default_channel=fifo Arrays become FIFO channels

Configuration

In hls_config.cfg:

syn.compile.pipeline_style=frp
syn.dataflow.default_channel=fifo
syn.dataflow.fifo_depth=16
Setting Value Description
pipeline_style frp Free-Running Pipeline mode
default_channel fifo Arrays between stages become FIFOs
fifo_depth 16 Default FIFO depth

Complete Example

From Pipelining/Loops/using_free_running_pipeline/free_pipe_mult.cpp:

#include "free_pipe_mult.h"

int accumulate(data_t A[]) {
#pragma HLS inline off              // Keep as separate sub-function
    data_t acc = 0.0;
    for (int i = 0; i < SZ; i++)
        acc += A[i];
    return acc;
}

void process(hls::stream<data_t>& strm_in, hls::stream<data_t>& strm_out) {
#pragma HLS inline off              // Separate DATAFLOW stage
    for (int i = 0; i < SZ; i++) {
        data_t tmp = strm_in.read();
        strm_out.write(tmp);
    }
}

void inner(data_t A[SZ], hls::stream<data_t>& stream_in, data_t* out) {
#pragma HLS pipeline                // Function-level pipeline!

    data_t regA[SZ];
#pragma HLS ARRAY_PARTITION variable=regA complete  // Parallel access

    for (int i = 0; i < SZ; i++) {
        data_t tmp = stream_in.read();
        regA[i] = A[i] + tmp;
    }

    *out = accumulate(regA);        // Sub-function call
}

void free_pipe_mult(data_t A[SZ], hls::stream<data_t>& strm, data_t& out) {
#pragma HLS DATAFLOW                // Enable concurrent stages
#pragma HLS INTERFACE ap_fifo port=strm

    data_t B[SZ];                   // Becomes FIFO channel!

    for (int i = 0; i < SZ; i++)    // Stage 1: Producer
        B[i] = A[i] + i;

    hls::stream<data_t> strm_out;
    process(strm, strm_out);        // Stage 2: Pass-through
    inner(B, strm_out, &out);       // Stage 3: Pipelined consumer
}

Key Concepts

Function-Level vs Loop-Level Pipeline

Aspect Loop-Level Function-Level
Pragma location Inside loop At function start
Effect Overlaps loop iterations Entire function is one pipeline stage
Inner loops Remain as loops Typically unrolled
Use case General optimization DATAFLOW stages, streaming 
// Loop-level pipeline
for (int i = 0; i < N; i++) {
#pragma HLS pipeline II=1
    // iterations overlap
}

// Function-level pipeline
void func(...) {
#pragma HLS pipeline          // Function is pipeline stage
    for (int i = 0; i < N; i++)
        // loop is unrolled
}

DATAFLOW Array Transformation

Under #pragma HLS DATAFLOW, arrays between stages become streaming channels:

void top(...) {
#pragma HLS DATAFLOW
    data_t B[SZ];           // B is NOT a regular array!
                            // B becomes FIFO channel

    stage1(A, B);           // Producer writes to FIFO
    stage2(B, out);         // Consumer reads from FIFO (sequential only!)
}

Critical: Access must be sequential (B[0], B[1], B[2]...). Random access not allowed!

Sub-Function Behavior with inline off

void inner(...) {
#pragma HLS pipeline              // Parent is pipelined

    // ...
    *out = accumulate(regA);      // Sub-function call
}

int accumulate(data_t A[]) {
#pragma HLS inline off            // Stays separate!
    // This loop is NOT affected by inner()'s pipeline pragma
    for (int i = 0; i < SZ; i++)
        acc += A[i];
}
  • inline off keeps sub-function separate
  • Parent's pipeline pragma does NOT propagate
  • Sub-function adds latency to parent's pipeline

Code Generation Guidelines

Top Function Template

void top(data_t A[SZ], hls::stream<data_t>& strm, data_t& out) {
#pragma HLS DATAFLOW
#pragma HLS INTERFACE ap_fifo port=strm

    data_t B[SZ];                   // Becomes FIFO channel
    hls::stream<data_t> internal;

    producer(A, B);                 // Stage 1
    transformer(B, internal);       // Stage 2
    consumer(internal, &out);       // Stage 3 (pipelined function)
}

Pipelined Stage Template

void pipelined_stage(data_t in[SZ], hls::stream<data_t>& strm_in, data_t* out) {
#pragma HLS inline off
#pragma HLS pipeline                // Function-level!

    data_t buf[SZ];
#pragma HLS ARRAY_PARTITION variable=buf complete

    for (int i = 0; i < SZ; i++)
        buf[i] = in[i] + strm_in.read();

    *out = reduce(buf);
}

Config Template (hls_config.cfg)

syn.compile.pipeline_style=frp
syn.dataflow.default_channel=fifo
syn.dataflow.fifo_depth=16

Key Constraints

Constraint Requirement
FRP mode Enable syn.compile.pipeline_style=frp
DATAFLOW stages Use #pragma HLS inline off on stage functions
Array access Sequential only (arrays become FIFOs)
Function-level pipeline Requires ARRAY_PARTITION complete
Sub-functions Don't inherit parent's pipeline pragma

Test Bench Generation Guidelines

Test Bench Template

#include "free_pipe_mult.h"
#include <fstream>
#include <iostream>
using namespace std;

int main() {
    data_t A[SZ];
    data_t result;
    hls::stream<data_t> strm;

    // Initialize inputs
    for (int i = 0; i < SZ; i++) {
        A[i] = i;
        strm.write(i);              // Feed stream
    }

    // Execute DUT
    free_pipe_mult(A, strm, result);

    // Verify
    cout << "Result: " << result << endl;

    // Compare with golden
    ofstream FILE("result.dat");
    FILE << result << endl;
    FILE.close();

    int retval = system("diff --brief -w result.dat result.golden.dat");
    return (retval != 0) ? 1 : 0;
}

Optimization Guidance for Agents

When to Apply This Pattern

Decision tree:
├── Need continuous streaming (no per-batch control)?
│   ├── Yes → Is data flow sequential?
│   │         ├── Yes → Use FRP mode
│   │         │         ├── syn.compile.pipeline_style=frp
│   │         │         ├── #pragma HLS DATAFLOW
│   │         │         └── Function-level pipeline + ARRAY_PARTITION
│   │         └── No → Use normal pipeline with control
│   └── No → Use normal pipeline
│             └── Batch processing with ap_start/ap_done

Normal vs Free-Running Pipeline

Aspect Normal Pipeline Free-Running Pipeline
Control Needs ap_start Always active
State IDLE → RUN → DONE Always RUNNING
Data flow Batch-oriented Stream-oriented
Use case One-shot compute Video/audio/sensors

Performance Optimization

Optimization How to Apply Expected Impact
FRP mode pipeline_style=frp No control overhead
DATAFLOW Concurrent stages Parallel execution
Function-level pipeline #pragma HLS pipeline on function Streaming throughput
ARRAY_PARTITION complete partitioning Parallel array access

Common Pitfalls

Pitfall Symptom Solution
Missing FRP config Normal start/stop behavior Add syn.compile.pipeline_style=frp
Random array access under DATAFLOW Incorrect results Use sequential access or PIPO
Sub-function not pipelined Unexpected latency Add pipeline pragma or remove inline off
Missing ARRAY_PARTITION Cannot achieve II Add ARRAY_PARTITION complete
