DATAFLOW Bypass Patterns

This document covers common DATAFLOW feed-forward violations and their solutions. These patterns help agents detect and fix issues that degrade pipeline performance.

The Feed-Forward Constraint

HLS DATAFLOW requires data to flow forward through stages in a linear chain:

CORRECT (Feed-Forward):
input ──► Stage1 ──► Stage2 ──► Stage3 ──► output
              │          │          │
              └──────────┴──────────┘
              Each stage reads only from previous stage

INCORRECT (Bypass):
input ──► Stage1 ──► Stage2 ──► Stage3 ──► output
   │                    ▲
   └────────────────────┘
   Input bypasses Stage1 - breaks feed-forward!

Why bypasses cause problems: - DATAFLOW can't pipeline stages efficiently when data arrives from multiple sources - The bypassed stage must wait for both its predecessor AND the bypassing data - Results in sequential execution instead of parallel pipelining

Key Constructs

Pragma Purpose
#pragma HLS DATAFLOW Enable concurrent function execution
#pragma HLS INLINE OFF Keep functions as separate hardware modules
#pragma HLS PIPELINE Pipeline loops within stages

Required Pragmas

Pragma Required? Purpose
#pragma HLS DATAFLOW Yes Enable concurrent function execution
#pragma HLS INLINE OFF Yes Keep functions as separate hardware modules
#pragma HLS PIPELINE Recommended Pipeline loops for throughput

Pattern 1: Input Bypass

Problem

An input argument bypasses the first function, going directly to a later stage.

PROBLEM:
   a ──► pass ──► tmp1 ──► double_pass ──► tmp4 ──► add_kernel ──► output
   b ─────────────────────────┘                          │
       BYPASSES pass!        └──► tmp2 ──────────────────┘

Problem Code

void pass(int a[128], int tmp1[128]) {
    for (int i = 0; i < 128; i++) {
        tmp1[i] = a[i];
    }
}

void double_pass(int b[128], int tmp2[128], int tmp1[128], int tmp4[128]) {
    for (int i = 0; i < 128; i++) {
        tmp2[i] = b[i];      // b comes directly from top-level input!
        tmp4[i] = tmp1[i];
    }
}

void add_kernel(int tmp1[128], int tmp2[128], int tmp3[128]) {
    for (int i = 0; i < 128; i++) {
        tmp3[i] = tmp1[i] + tmp2[i];
    }
}

void dut(int a[128], int b[128], int tmp3[128]) {
#pragma HLS DATAFLOW
    int tmp1[128], tmp2[128], tmp4[128];

    pass(a, tmp1);                      // Stage 1: only processes 'a'
    double_pass(b, tmp2, tmp1, tmp4);   // Stage 2: 'b' BYPASSES Stage 1!
    add_kernel(tmp4, tmp2, tmp3);       // Stage 3
}

Solution

Route ALL inputs through the first stage.

SOLUTION:
   a ──► pass ──► tmp1 ──► Double_pass ──► tmp4 ──► add_kernel ──► output
   b ──►      ──► tmp2 ──►             ──► tmp5 ──►
        Stage 1          Stage 2            Stage 3
        (both inputs)    (reads from S1)    (reads from S2)

Solution Code

void pass(int a[128], int b[128], int tmp1[128], int tmp2[128]) {
    for (int i = 0; i < 128; i++) {
        tmp1[i] = a[i];
        tmp2[i] = b[i];   // Now b goes through pass too!
    }
}

void Double_pass(int tmp2[128], int tmp1[128], int tmp4[128], int tmp5[128]) {
    for (int i = 0; i < 128; i++) {
        tmp4[i] = tmp1[i];
        tmp5[i] = tmp2[i];   // Reads from pass output, not top-level input
    }
}

void add_kernel(int tmp1[128], int tmp2[128], int tmp3[128]) {
    for (int i = 0; i < 128; i++) {
        tmp3[i] = tmp1[i] + tmp2[i];
    }
}

void dut(int a[128], int b[128], int tmp3[128]) {
#pragma HLS DATAFLOW
    int tmp1[128], tmp2[128], tmp4[128], tmp5[128];

    pass(a, b, tmp1, tmp2);              // Stage 1: BOTH inputs enter here
    Double_pass(tmp2, tmp1, tmp4, tmp5); // Stage 2: only reads from Stage 1
    add_kernel(tmp4, tmp5, tmp3);        // Stage 3: only reads from Stage 2
}

Source: Vitis-HLS-Introductory-Examples/Task_level_Parallelism/Control_driven/Patterns/input_bypass/

How to Fix Input Bypass

  1. Add bypassing input as parameter to first stage function
  2. Add corresponding output channel from first stage
  3. Update second stage to read from channel instead of top-level input

Pattern 2: Middle Bypass

Problem

A channel skips an intermediate task, breaking the feed-forward chain.

PROBLEM:
   double_pass ──► tmp1 ─────────────────────────► bypass ──► output
               ──► tmp2 ──► pass ──► tmp4 ────────►
                            tmp1 SKIPS pass!

Problem Code

void double_pass(int a[128], int b[128], int tmp1[128], int tmp2[128]) {
    for (int i = 0; i < 128; i++) {
        tmp1[i] = a[i];
        tmp2[i] = b[i];
    }
}

void pass(int tmp2[128], int tmp4[128]) {
    for (int i = 0; i < 128; i++) {
        tmp4[i] = tmp2[i];
    }
}

void bypass(int tmp1[128], int tmp2[128], int tmp3[128]) {
    for (int i = 0; i < 128; i++) {
        tmp3[i] = tmp1[i] + tmp2[i];
    }
}

void dut(int a[128], int b[128], int tmp3[128]) {
#pragma HLS DATAFLOW
    int tmp1[128], tmp2[128], tmp4[128];

    double_pass(a, b, tmp1, tmp2);  // Stage 1
    pass(tmp2, tmp4);               // Stage 2: only processes tmp2
    bypass(tmp1, tmp4, tmp3);       // Stage 3: tmp1 BYPASSES Stage 2!
}

Solution

Route all data through the intermediate stage.

SOLUTION:
   double_pass ──► tmp1 ──► pass ──► tmp5 ──► bypass ──► output
               ──► tmp2 ──►      ──► tmp4 ──►
                   Stage 1      Stage 2      Stage 3

Solution Code

void double_pass(int a[128], int b[128], int tmp1[128], int tmp2[128]) {
    for (int i = 0; i < 128; i++) {
        tmp1[i] = a[i];
        tmp2[i] = b[i];
    }
}

void pass(int tmp2[128], int tmp4[128], int tmp1[128], int tmp5[128]) {
    for (int i = 0; i < 128; i++) {
        tmp4[i] = tmp2[i];
        tmp5[i] = tmp1[i];   // Now tmp1 passes through this stage
    }
}

void bypass(int tmp1[128], int tmp2[128], int tmp3[128]) {
    for (int i = 0; i < 128; i++) {
        tmp3[i] = tmp1[i] + tmp2[i];
    }
}

void dut(int a[128], int b[128], int tmp3[128]) {
#pragma HLS DATAFLOW
    int tmp1[128], tmp2[128], tmp4[128], tmp5[128];

    double_pass(a, b, tmp1, tmp2);       // Stage 1
    pass(tmp2, tmp4, tmp1, tmp5);        // Stage 2: processes BOTH channels
    bypass(tmp5, tmp4, tmp3);            // Stage 3: reads only from Stage 2
}

How to Fix Middle Bypass

  1. Add bypassing channel as input to skipped stage
  2. Add corresponding output channel from skipped stage
  3. Update consumer stage to read from new output

Pattern 3: Output Bypass

Problem

An output goes directly from an early stage, bypassing later stages.

PROBLEM:
   split ──► tmp1 ──► pass ──► b (output)
         ──► tmp2 ────────────► output
             tmp2 BYPASSES pass directly to output!

Problem Code

void split(int a[128], int tmp1[128], int tmp2[128]) {
    for (int i = 0; i < 128; i++) {
        tmp1[i] = a[i];
        tmp2[i] = a[i];
    }
}

void pass(int tmp1[128], int b[128]) {
    for (int i = 0; i < 128; i++) {
        b[i] = tmp1[i];
    }
}

void dut(int a[128], int b[128], int tmp2[128]) {
#pragma HLS DATAFLOW
    int tmp1[128], tmp3[128];

    split(a, tmp1, tmp2);   // Stage 1: tmp2 goes directly to output!
    pass(tmp1, b);          // Stage 2: only processes tmp1
}

Solution

Route all outputs through the final stage.

SOLUTION:
   split ──► tmp1 ──► pass ──► b (output)
         ──► tmp3 ──►      ──► tmp2 (output)
        Stage 1      Stage 2
                     (produces BOTH outputs)

Solution Code

void split(int a[128], int tmp1[128], int tmp2[128]) {
    for (int i = 0; i < 128; i++) {
        tmp1[i] = a[i];
        tmp2[i] = a[i];
    }
}

void pass(int tmp3[128], int tmp2[128], int tmp1[128], int b[128]) {
    for (int i = 0; i < 128; i++) {
        b[i] = tmp1[i];
        tmp2[i] = tmp3[i];   // Output now comes from pass, not split
    }
}

void dut(int a[128], int b[128], int tmp2[128]) {
#pragma HLS DATAFLOW
    int tmp1[128], tmp3[128];

    split(a, tmp1, tmp3);          // Stage 1: internal channel tmp3
    pass(tmp3, tmp2, tmp1, b);     // Stage 2: produces BOTH outputs
}

Source: Vitis-HLS-Introductory-Examples/Task_level_Parallelism/Control_driven/Patterns/output_bypass/

How to Fix Output Bypass

  1. Replace top-level output with internal channel in early stage
  2. Add channel as input to final stage
  3. Add top-level output as parameter to final stage

Pattern 4: Stream as Synchronization

Problem

Two stages share external memory (DDR) but have no direct channel - the reader may start before the writer finishes.

PROBLEM:
   write ──► A[N][N] (DDR) ──► read
                 │
        Race condition! Reader may read garbage
        because there's no channel to synchronize.

Problem Description

When a writer and reader process exchange data through external memory: - Both processes start as soon as possible (no channel dependency) - Reader may read rows before writer has written them - Results in reading garbage data

Solution

Use an hls::stream as a synchronization barrier between writer and reader.

SOLUTION:
   write ──► A[N][N] (DDR) ──► read
        │                       ▲
        └──► line (stream) ─────┘
             Sync signal: "row i is ready"

Solution Code

#include "hls_stream.h"
#include "etc/ap_utils.h"

void write(hls::stream<int> &inputStream, int A[N][N], hls::stream<int> &line) {
#pragma HLS INLINE OFF

    for (unsigned int i = 0; i < N; ++i) {
#pragma HLS PIPELINE II=3
        for (unsigned int j = 0; j < N; ++j) {
            int temp = inputStream.read();
            A[i][j] = temp;
        }

        ap_wait();          // Ensure write completes
        line.write(i);      // Signal: "row i is ready to read"
    }
}

void read(int A[N][N], hls::stream<int> &outputStream, hls::stream<int> &line) {
#pragma HLS INLINE OFF
    int row;
    do {
#pragma HLS PIPELINE II=3
        row = line.read();  // Block until writer signals row is ready
        for (unsigned j = 0; j < N; ++j) {
            outputStream << A[row][j];
        }
    } while (row < N-1);
}

void dut(hls::stream<int> &inputStream, int A[N][N], hls::stream<int> &outputStream) {
#pragma HLS INTERFACE axis  port=inputStream
#pragma HLS INTERFACE m_axi port=A
#pragma HLS INTERFACE axis  port=outputStream
#pragma HLS DATAFLOW

    hls::stream<int> line;  // Synchronization stream

    write(inputStream, A, line);
    read(A, outputStream, line);
}

Key Points

Aspect Description
line.write(i) Writer signals "row i is complete"
line.read() Reader blocks until signal received
ap_wait() Ensures memory write completes before signaling
Row-by-row sync Allows overlap - reader processes row i while writer writes row i+1

Source: Vitis-HLS-Introductory-Examples/Task_level_Parallelism/Control_driven/Patterns/using_stream_as_sync/

How to Fix Missing Sync

  1. Declare hls::stream<int> for synchronization
  2. Writer signals after completing each unit (e.g., row)
  3. Reader blocks on stream.read() before accessing memory

Code Generation Guidelines

Proper Feed-Forward Kernel Template

void kernel(input_t* in1, input_t* in2, output_t* out1, output_t* out2) {
#pragma HLS DATAFLOW

    // Internal channels
    channel_t c1, c2, c3, c4;

    // Stage 1: ALL inputs enter here
    first_stage(in1, in2, c1, c2);

    // Middle stages: read from previous, write to next
    middle_stage(c1, c2, c3, c4);

    // Last stage: ALL outputs exit here
    last_stage(c3, c4, out1, out2);
}

Stage Function Template

void stage_func(input_t* in1, input_t* in2, output_t* out1, output_t* out2) {
#pragma HLS INLINE OFF          // Required for DATAFLOW
Loop:
    for (int i = 0; i < N; i++) {
#pragma HLS PIPELINE
        out1[i] = process1(in1[i]);
        out2[i] = process2(in2[i]);
    }
}

Sync Stream Template (for shared memory)

void writer(data_t* input, mem_t mem[N], hls::stream<int>& sync) {
#pragma HLS INLINE OFF
    for (int i = 0; i < N; i++) {
        mem[i] = input[i];
        sync.write(i);      // Signal completion
    }
}

void reader(mem_t mem[N], data_t* output, hls::stream<int>& sync) {
#pragma HLS INLINE OFF
    for (int i = 0; i < N; i++) {
        int idx = sync.read();  // Wait for signal
        output[i] = mem[idx];
    }
}

Key Constraints

Constraint Requirement
Feed-forward Each stage reads only from previous stage outputs
Single producer/consumer Each channel has exactly 1 writer and 1 reader
No input bypass Top-level inputs only go to first stage
No output bypass Top-level outputs only come from last stage
Shared memory sync Use stream as barrier when stages share external memory

Test Bench Generation Guidelines

Basic Dataflow Test Bench Template

#include "dut.h"
#include <iostream>

int main() {
    int a[128], b[128], result[128];
    int expected[128];
    int errors = 0;

    // Initialize inputs
    for (int i = 0; i < 128; i++) {
        a[i] = i;
        b[i] = i * 2;
        expected[i] = compute_expected(a[i], b[i]);
    }

    // Run multiple iterations to expose timing issues
    for (int iter = 0; iter < 3; iter++) {
        dut(a, b, result);

        // Verify results
        for (int i = 0; i < 128; i++) {
            if (result[i] != expected[i]) {
                std::cout << "Mismatch at [" << i << "]: "
                          << result[i] << " != " << expected[i] << std::endl;
                errors++;
            }
        }
    }

    if (errors == 0) {
        std::cout << "Test PASSED" << std::endl;
        return 0;
    } else {
        std::cout << "Test FAILED with " << errors << " errors" << std::endl;
        return 1;
    }
}

Test Bench Requirements

Requirement Details
Multiple iterations Run 3+ times to expose synchronization issues
Golden reference Pre-compute expected outputs for verification
Return code Return 0 for PASS, non-zero for FAIL
Error reporting Print specific mismatches for debugging

Optimization Guidance for Agents

Detection Decision Tree

Is data flowing directly from input to a non-first stage?
├── Yes → INPUT BYPASS - route input through first stage
└── No → Continue

Is data skipping an intermediate stage?
├── Yes → MIDDLE BYPASS - add pass-through in skipped stage
└── No → Continue

Is data going directly to output from a non-last stage?
├── Yes → OUTPUT BYPASS - route output through last stage
└── No → Feed-forward OK

Do two stages share external memory with no channel?
├── Yes → SYNC NEEDED - add synchronization stream
└── No → No sync needed

Common Pitfalls

Pitfall Symptom Solution
Input bypass Input argument goes to stage 2+ Route all inputs through stage 1
Middle bypass Channel skips a stage Add pass-through in skipped stage
Output bypass Output comes from early stage Route all outputs through last stage
Missing sync Race condition with shared memory Add sync stream between writer/reader
Missing INLINE OFF Functions merged, no parallelism Add #pragma HLS INLINE OFF

Performance Impact

Issue Without Fix With Fix
Bypass violations Sequential execution, no pipelining Full pipeline overlap
Missing sync Data corruption, non-deterministic Correct results, row-level overlap

Resource vs Performance Trade-offs

Choice Performance Impact Resource Impact
Fix bypass violations Enables parallel pipelining (Nx speedup) Adds pass-through logic
Leave bypass Sequential execution No additional logic
Add sync stream Enables overlap with correct data Small FIFO overhead
Higher sync granularity More overlap (row vs block) More sync overhead

Parameter Tuning

Parameter Low Value High Value Guidance
Sync stream depth 1-2 N rows Match writer-reader latency difference
PIPELINE II 1 Higher Trade throughput for resources
Pass-through unroll 1 Full Balance throughput vs area
