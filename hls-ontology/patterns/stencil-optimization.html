Stencil Optimization Pattern

Optimize sliding window operations (stencils) for image and signal processing using the #pragma HLS ARRAY_STENCIL pragma to enable data reuse and reduce memory bandwidth.

Overview

A stencil is a computation pattern where each output element depends on a fixed-size neighborhood of input elements. As the computation slides across the input, neighboring windows overlap, creating opportunities for data reuse.

1D Stencil (window size 3):
┌─────────────────────────────────────────────────┐
│ Input:   [0]  [1]  [2]  [3]  [4]  [5]  [6] ...  │
│           └────┴────┘                            │
│              Window j                            │
│                └────┴────┘                       │
│                   Window j+1                     │
│                                                  │
│ Overlap: Elements [1] and [2] are read by BOTH  │
│          Window j and Window j+1                 │
└─────────────────────────────────────────────────┘

2D Stencil (3x3 window):
┌─────────────────────────────────┐
│     [0,0] [0,1] [0,2] [0,3]     │
│     [1,0] [1,1] [1,2] [1,3]     │
│     [2,0] [2,1] [2,2] [2,3]     │
│     [3,0] [3,1] [3,2] [3,3]     │
│                                  │
│     ┌─────────┐                  │
│     │ Window  │ moves right →    │
│     │ (x,y)   │ then down ↓      │
│     └─────────┘                  │
└─────────────────────────────────┘

Without optimization: Each output reads all window elements from memory. With ARRAY_STENCIL: HLS buffers overlapping elements, reducing memory reads.

Key Constructs

Construct Purpose
#pragma HLS ARRAY_STENCIL variable=arr Tell HLS about stencil access pattern
#pragma HLS PIPELINE II=1 Enable single-cycle throughput
Line buffer (2D) Cache rows for vertical reuse
Window buffer Cache current window elements

1D Stencil Pattern

Use Cases

  • Moving average filters
  • FIR filters
  • 1D convolution
  • Signal smoothing

Data Reuse Analysis

For a window of size W, sliding by 1 element: - Elements read per window: W - New elements per slide: 1 - Reused elements: W-1 - Bandwidth reduction: (W-1)/W = 66% for W=3, 93% for W=15

Complete Example

From Vitis-HLS-Introductory-Examples/Modeling/using_array_stencil_1d/:

#define HS 100    // Height
#define WS 100    // Width
#define FW 3      // Filter window size

void stencil_1d(float in[HS][WS], float out[HS][WS-FW+1], float bias) {
#pragma HLS INTERFACE m_axi port=in offset=slave bundle=gmem
#pragma HLS INTERFACE m_axi port=out offset=slave bundle=gmem
#pragma HLS INTERFACE s_axilite port=bias bundle=control
#pragma HLS INTERFACE s_axilite port=return bundle=control

    for (int i = 0; i < HS; i++) {
        for (int j = 0; j < WS - FW + 1; j++) {
#pragma HLS PIPELINE II=1
#pragma HLS ARRAY_STENCIL variable=in
            // 3-element sliding window sum
            out[i][j] = in[i][j] + in[i][j+1] + in[i][j+2] + bias;
        }
    }
}

How It Works

Without ARRAY_STENCIL (naive):
  Iteration j=0: Read in[0], in[1], in[2]  → 3 reads
  Iteration j=1: Read in[1], in[2], in[3]  → 3 reads
  Iteration j=2: Read in[2], in[3], in[4]  → 3 reads
  Total: 3 reads per iteration

With ARRAY_STENCIL (optimized):
  Iteration j=0: Read in[0], in[1], in[2]  → 3 reads (cold start)
  Iteration j=1: Shift buffer, Read in[3]  → 1 read (reuse in[1], in[2])
  Iteration j=2: Shift buffer, Read in[4]  → 1 read (reuse in[2], in[3])
  Total: 1 read per iteration (after warm-up)

Internal buffer (shift register):

┌──────┬──────┬──────┐
│ [j]  │[j+1] │[j+2] │  ← Window buffer
└──────┴──────┴──────┘
   ↑       ↑       ↑
   └───────┴───────┴── Shift left, new element enters from right

2D Stencil Pattern

Use Cases

  • Image convolution (blur, sharpen, edge detection)
  • 2D filtering
  • Feature extraction
  • Image processing pipelines

Data Reuse Analysis

For an HxW window on an image of width IMG_W: - Horizontal reuse: W-1 elements per pixel (same as 1D) - Vertical reuse: (H-1) × W elements from previous rows - Line buffers needed: H-1 rows cached

Complete Example

From Vitis-HLS-Introductory-Examples/Modeling/using_array_stencil_2d/:

#define FILTER_H_SIZE 15
#define FILTER_V_SIZE 15
#define MAX_IMAGE_WIDTH 1000
#define MAX_IMAGE_HEIGHT 30

void filter2d(const char coeff[256],
              const unsigned char src[MAX_IMAGE_HEIGHT][MAX_IMAGE_WIDTH],
              unsigned char dst[MAX_IMAGE_HEIGHT][MAX_IMAGE_WIDTH]) {
#pragma HLS INTERFACE m_axi port=src bundle=gmem1 depth=MAX_IMAGE_WIDTH*MAX_IMAGE_HEIGHT
#pragma HLS INTERFACE m_axi port=dst bundle=gmem1 depth=MAX_IMAGE_WIDTH*MAX_IMAGE_HEIGHT
#pragma HLS INTERFACE m_axi port=coeff bundle=gmem1
#pragma HLS INTERFACE s_axilite port=return bundle=control

    // Load coefficients to local BRAM (accessed repeatedly)
    char coeffs[FILTER_V_SIZE][FILTER_H_SIZE];
    for (int i = 0; i < FILTER_V_SIZE; i++) {
        for (int j = 0; j < FILTER_H_SIZE; j++) {
#pragma HLS PIPELINE II=1
            coeffs[i][j] = coeff[i * FILTER_H_SIZE + j];
        }
    }

    // Main processing loop
    for (int y = 0; y < MAX_IMAGE_HEIGHT; y++) {
        for (int x = 0; x < MAX_IMAGE_WIDTH; x++) {
#pragma HLS PIPELINE II=1
#pragma HLS ARRAY_STENCIL variable=src

            int sum = 0;

            // Apply filter kernel
            for (int row = 0; row < FILTER_V_SIZE; row++) {
                for (int col = 0; col < FILTER_H_SIZE; col++) {
                    int xoff = x + col - (FILTER_H_SIZE / 2);
                    int yoff = y + row - (FILTER_V_SIZE / 2);

                    // Boundary handling: zero-padding
                    unsigned char pixel;
                    if (xoff < 0 || xoff >= MAX_IMAGE_WIDTH ||
                        yoff < 0 || yoff >= MAX_IMAGE_HEIGHT) {
                        pixel = 0;
                    } else {
                        pixel = src[yoff][xoff];
                    }

                    sum += pixel * coeffs[row][col];
                }
            }

            // Normalize and saturate to 8-bit
            int result = (sum >> 8) + 128;  // Example normalization
            dst[y][x] = (result < 0) ? 0 : (result > 255) ? 255 : result;
        }
    }
}

2D Buffer Architecture

Line Buffers (H-1 rows cached):
┌────────────────────────────────────────────────┐
│ Line Buffer 0: [row y-14] ─────────────────────│
│ Line Buffer 1: [row y-13] ─────────────────────│
│ ...                                            │
│ Line Buffer 13: [row y-1] ─────────────────────│
│ Current Row:    [row y]   ─────────────────────│
└────────────────────────────────────────────────┘
         ↓
Window Buffer (15x15):
┌───┬───┬───┬───┬───┐
│   │   │   │   │   │  ← From line buffer 0
├───┼───┼───┼───┼───┤
│   │   │ * │   │   │  ← Current pixel at center
├───┼───┼───┼───┼───┤
│   │   │   │   │   │  ← From current row
└───┴───┴───┴───┴───┘

Boundary Handling Strategies

Strategy Description When to Use
Zero-padding Treat out-of-bounds as 0 Most common, simple
Clamp/Replicate Use nearest edge pixel Avoid dark borders
Mirror Reflect at boundaries Symmetric filters
Wrap Circular indexing Periodic signals

Zero-Padding Example

unsigned char pixel;
if (x < 0 || x >= WIDTH || y < 0 || y >= HEIGHT) {
    pixel = 0;  // Zero for out-of-bounds
} else {
    pixel = src[y][x];
}

Clamp/Replicate Example

int cx = (x < 0) ? 0 : (x >= WIDTH) ? WIDTH-1 : x;
int cy = (y < 0) ? 0 : (y >= HEIGHT) ? HEIGHT-1 : y;
unsigned char pixel = src[cy][cx];

Code Generation Guidelines

1D Stencil Template

#define N 1024      // Input size
#define W 5         // Window size

void stencil_1d(data_t in[N], data_t out[N-W+1], coeff_t coeffs[W]) {
#pragma HLS INTERFACE m_axi port=in bundle=gmem
#pragma HLS INTERFACE m_axi port=out bundle=gmem

    for (int i = 0; i < N - W + 1; i++) {
#pragma HLS PIPELINE II=1
#pragma HLS ARRAY_STENCIL variable=in

        acc_t sum = 0;
        for (int k = 0; k < W; k++) {
            sum += in[i + k] * coeffs[k];
        }
        out[i] = sum;
    }
}

2D Stencil Template

#define IMG_H 480
#define IMG_W 640
#define KH 3        // Kernel height
#define KW 3        // Kernel width

void stencil_2d(pixel_t src[IMG_H][IMG_W],
                pixel_t dst[IMG_H][IMG_W],
                coeff_t kernel[KH][KW]) {
#pragma HLS INTERFACE m_axi port=src bundle=gmem
#pragma HLS INTERFACE m_axi port=dst bundle=gmem

    for (int y = 0; y < IMG_H; y++) {
        for (int x = 0; x < IMG_W; x++) {
#pragma HLS PIPELINE II=1
#pragma HLS ARRAY_STENCIL variable=src

            acc_t sum = 0;
            for (int ky = 0; ky < KH; ky++) {
                for (int kx = 0; kx < KW; kx++) {
                    int yy = y + ky - KH/2;
                    int xx = x + kx - KW/2;

                    // Boundary handling (zero-pad)
                    pixel_t p = (yy < 0 || yy >= IMG_H ||
                                 xx < 0 || xx >= IMG_W) ? 0 : src[yy][xx];
                    sum += p * kernel[ky][kx];
                }
            }
            dst[y][x] = normalize(sum);
        }
    }
}

Key Constraints

Constraint Requirement
Regular access pattern Stencil offsets must be compile-time constants
Inner loops fully unrolled Kernel loops must unroll for II=1
Coefficient caching Pre-load coefficients to BRAM
Output size N - W + 1 for 1D, or handle boundaries

Test Bench Generation Guidelines

Test Bench Template

#include "stencil.h"
#include <iostream>
#include <cmath>

// Software reference
void stencil_ref(data_t in[N], data_t out[N-W+1], coeff_t coeffs[W]) {
    for (int i = 0; i < N - W + 1; i++) {
        data_t sum = 0;
        for (int k = 0; k < W; k++) {
            sum += in[i + k] * coeffs[k];
        }
        out[i] = sum;
    }
}

int main() {
    data_t in[N], out_hw[N-W+1], out_ref[N-W+1];
    coeff_t coeffs[W] = {1, 2, 1};  // Example: smoothing kernel

    // Initialize input
    for (int i = 0; i < N; i++) {
        in[i] = i % 256;
    }

    // Run HW and reference
    stencil_1d(in, out_hw, coeffs);
    stencil_ref(in, out_ref, coeffs);

    // Compare
    int errors = 0;
    for (int i = 0; i < N - W + 1; i++) {
        if (out_hw[i] != out_ref[i]) {
            std::cout << "Mismatch at " << i << ": "
                      << out_hw[i] << " vs " << out_ref[i] << std::endl;
            errors++;
        }
    }

    return errors ? 1 : 0;
}

Optimization Guidance for Agents

When to Apply This Pattern

Processing array/image data?
├── Fixed-size sliding window?
│   ├── Yes → Use ARRAY_STENCIL
│   └── No → Not a stencil pattern
├── Regular access offsets (compile-time)?
│   ├── Yes → ARRAY_STENCIL will work
│   └── No → Manual buffering needed
└── Need II=1 throughput?
    └── Yes → Combine with PIPELINE pragma

Performance Impact

Optimization Effect
ARRAY_STENCIL Enables automatic line/window buffering
PIPELINE II=1 One output per cycle
Coefficient caching Avoid repeated memory reads
Unroll kernel loops Enable parallel multiplies

Resource vs Performance Trade-offs

Choice Performance Resources
Larger window More computation/output More BRAM for buffers
Full kernel unroll II=1 possible More DSPs, LUTs
Partial unroll Higher II Fewer resources

Common Pitfalls

Pitfall Symptom Solution
Variable window size ARRAY_STENCIL ignored Use compile-time constants
Missing PIPELINE High II, low throughput Add #pragma HLS PIPELINE II=1
Coefficients in DDR Memory bottleneck Pre-load to local BRAM array
Kernel loops not unrolled II > 1 Unroll inner loops or let HLS do it
Wrong output size Array overflow Output is N - W + 1 elements
