DirectIO with Data-Driven Tasks

How to use DirectIO scalar types (hls::ap_none, hls::ap_hs) with data-driven tasks (hls::task).

Overview

DirectIO types provide scalar wire interfaces for data-driven tasks. Unlike hls::stream which is for high-throughput data, DirectIO is for scalar values like configuration parameters, status signals, or synchronized scalar inputs.

Key Types

Type Protocol Signals Behavior
hls::ap_none<T> No handshake data only read() always returns current wire value
hls::ap_hs<T> Valid/Ack data + valid + ack read() blocks until valid

When to Use Each Type

Use hls::ap_none When:

  • Static configuration values that don't change during operation
  • Host-programmable registers (combine with s_axilite pragma)
  • Always-valid signals synchronized externally
  • Simple wire-level control signals

Use hls::ap_hs When:

  • Scalar values need flow control
  • Each stream element needs a corresponding scalar value
  • Dynamic values that change during operation
  • Need to know when new value arrives (use valid())

Pattern 1: ap_hs in Tasks (Synchronized Scalar)

Use ap_hs when the task needs a synchronized scalar input per data element.

Architecture

in -> [sub_task1] -> s1 -> [sub_task2] -> s2 -> [task2] -> out
                                                    ^
                                                    n (ap_hs)

Implementation

#include "hls_task.h"
#include "hls_directio.h"

void sub_task1(hls::stream<int>& in, hls::stream<int>& out) {
    int c = in.read();
    out.write(c + 2);
}

void sub_task2(hls::stream<int>& in, hls::stream<int>& out) {
    int c = in.read();
    out.write(c - 2);
}

void task2(hls::stream<int>& in, hls::stream<int>& out,
           hls::ap_hs<int>& n) {
    int c = in.read();
    int var = n.read();  // Blocks until scalar valid
    out.write(c + var);
}

void test(hls::stream<int>& in, hls::stream<int>& out,
          hls::ap_hs<int>& n) {
    hls_thread_local hls::stream<int> s1;
    hls_thread_local hls::stream<int> s2;
    hls_thread_local hls::task t(task2, s2, out, n);
    hls_thread_local hls::task t1(sub_task1, in, s1);
    hls_thread_local hls::task t2(sub_task2, s1, s2);
}

Test Bench

int main() {
    hls::stream<int> in, out;
    hls::ap_hs<int> n;
    int golden = 0;

    for (int i = 0; i < N; i++) {
        n.write(i);      // Provide scalar for each element
        in.write(i);
        golden += 2*i;   // (i+2-2) + i = 2*i
    }

    test(in, out, n);

    int sum = 0;
    for (int i = 0; i < N; i++)
        sum += out.read();

    return (sum == golden) ? 0 : 1;
}

Key advantage: Task automatically synchronizes - waits for both stream data AND scalar value.

Pattern 2: ap_none with s_axilite (Host-Programmable Register)

Use ap_none with s_axilite pragma for host-configurable parameters.

Implementation

#include "hls_task.h"
#include "hls_directio.h"

void task_func(hls::stream<int>& in, hls::stream<int>& out,
               hls::ap_none<int>& bias) {
    int c = in.read();
    int b = bias.read();  // Read current register value
    out.write(c + b);
}

void top(hls::stream<int>& in, hls::stream<int>& out,
         hls::ap_none<int>& bias) {
#pragma HLS interface s_axilite port=bias
    hls_thread_local hls::stream<int> s1, s2;
    hls_thread_local hls::task t(task_func, s2, out, bias);
    hls_thread_local hls::task t1(sub_task1, in, s1);
    hls_thread_local hls::task t2(sub_task2, s1, s2);
}

Use case: Runtime-configurable parameters (bias, threshold, mode) that host sets before or during operation.

Pattern 3: ap_none with Manual Validity

When flow control is needed with ap_none, implement validity signaling manually.

Implementation

#include "hls_task.h"
#include "hls_directio.h"

typedef hls::ap_none<int> wire_t;

void addInputs(wire_t& data_A, wire_t& data_B,
               wire_t& valid_in, wire_t& data_out, wire_t& valid_out) {
    #pragma HLS pipeline II=1
    int vld = valid_in.read();
    if (vld == 0) {
        valid_out.write(0);  // Propagate invalid
        return;
    }
    int tmp1 = data_A.read();
    int tmp2 = data_B.read();
    data_out.write(tmp1 + tmp2);
    valid_out.write(1);
}

void adder_top(wire_t& din_A, wire_t& din_B,
               wire_t& dout, wire_t& vldIn, wire_t& vldOut) {
    hls_thread_local hls::task t1(addInputs, din_A, din_B,
                                  vldIn, dout, vldOut);
}

Test Bench

int main() {
    wire_t in1, in2, out, vld_in, vld_out;

    // Feed valid data
    for (int i = 0; i < N; i++) {
        in1.write(i);
        in2.write(i);
        vld_in.write(1);  // Mark as valid
    }

    // Termination signals (multiple for safety)
    vld_in.write(0);
    vld_in.write(0);
    vld_in.write(0);

    adder_top(in1, in2, out, vld_in, vld_out);

    for (int i = 0; i < N; i++) {
        if (vld_out.read() == 1) {
            if (out.read() != 2*i) return 1;
        }
    }
    return 0;
}

Important: Since ap_none has no backpressure, multiple termination signals may be needed.

Decision Tree

Need scalar input/output for data-driven task?
├── Yes → Does value change per data element?
│         ├── Yes → Use hls::ap_hs
│         │         └── Provides automatic synchronization
│         └── No → Is it host-configurable at runtime?
│                  ├── Yes → Use hls::ap_none + s_axilite pragma
│                  │         └── Host writes register, task reads
│                  └── No → Use hls::ap_none
│                           └── Static wire, consider manual validity
└── No → Use hls::stream for data

Code Generation Guidelines

For ap_hs in Tasks

// Template for ap_hs with hls::task
void task_with_scalar(hls::stream<DATA_T>& in,
                      hls::stream<DATA_T>& out,
                      hls::ap_hs<SCALAR_T>& scalar) {
    DATA_T data = in.read();
    SCALAR_T s = scalar.read();  // Blocks until valid
    out.write(process(data, s));
}

For ap_none with s_axilite

// Template for host-programmable register
void top(..., hls::ap_none<CONFIG_T>& config) {
#pragma HLS interface s_axilite port=config
    // config.read() returns current host-written value
}

For Manual Validity

// Template for manual validity pattern
typedef hls::ap_none<DATA_T> wire_t;

void task_with_validity(wire_t& data_in, wire_t& valid_in,
                        wire_t& data_out, wire_t& valid_out) {
    #pragma HLS pipeline II=1
    if (valid_in.read() == 0) {
        valid_out.write(0);
        return;
    }
    data_out.write(process(data_in.read()));
    valid_out.write(1);
}

for (int i = 0; i < N; i++) {
    data_in.write(input_data[i]);
    valid_in.write(1);
}
valid_in.write(0);  // Termination

valid_in.write(0);

DUT(data_in, valid_in, data_out, valid_out);

for (int i = 0; i < N; i++) {
    if (valid_out.read() == 1) {
        VERIFY(data_out.read(), expected[i]);
    }
}

Common Pitfalls

Pitfall 1: Using ap_none without flow control

Problem: Task reads stale or changing values unpredictably.

Solution: Use ap_hs for synchronized values, or ap_none + s_axilite for stable config.

Pitfall 2: Forgetting termination signals

Problem: Simulation hangs because task keeps waiting.

Solution: For manual validity, send multiple valid=0 signals to ensure task sees them.

Pitfall 3: ap_hs stream imbalance

Problem: Deadlock because scalar count doesn't match data count.

Solution: Write exactly one scalar per data element.

Performance Characteristics

Type Latency Overhead Flow Control
ap_none Lowest (direct wire) None Manual (if needed)
ap_hs Low (simple handshake) Valid + Ack signals Automatic
hls::stream Higher (FIFO) Buffer storage Automatic
