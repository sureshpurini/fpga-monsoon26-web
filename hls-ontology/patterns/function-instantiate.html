Function Instantiate

Create separate optimized hardware instances of a function for each unique constant parameter value. Enables constant propagation and per-call-site optimization.

Overview

When a function is called multiple times with different constant arguments, FUNCTION_INSTANTIATE creates a specialized hardware instance for each unique value, enabling compile-time optimization.

WITHOUT FUNCTION_INSTANTIATE:           WITH FUNCTION_INSTANTIATE:
┌────────────────────────────────┐      ┌────────────────────────────────┐
│  foo(inval, incr)              │      │  foo_0()   { return inval; }   │
│  {                             │      │  foo_1()   { return inval+1; } │
│    return inval + incr;        │      │  foo_100() { return inval+100;}│
│  }                             │      │                                │
│                                │      │  THREE separate instances      │
│  ONE shared instance           │      │  Each optimized for its value  │
│  incr is runtime variable      │      │  Can run in parallel           │
└────────────────────────────────┘      └────────────────────────────────┘

Key Constructs

Construct Purpose
#pragma HLS FUNCTION_INSTANTIATE variable=<param> Create instance per unique value
#pragma HLS INLINE OFF Required - keeps function separate

Syntax

ReturnType func(InputType inval, ConstType param) {
#pragma HLS INLINE OFF                          // Required!
#pragma HLS FUNCTION_INSTANTIATE variable=param // Instantiate on param
    return compute(inval, param);
}
Parameter Description
variable Parameter to instantiate on (must be constant at each call site)

Complete Example

From Pipelining/Functions/function_instantiate/example.cpp:

char foo(char inval, char incr) {
#pragma HLS INLINE OFF                      // Keep as separate function
#pragma HLS FUNCTION_INSTANTIATE variable=incr  // Instantiate per incr value
    return inval + incr;
}

void top(char inval1, char inval2, char inval3,
         char* outval1, char* outval2, char* outval3) {
    *outval1 = foo(inval1, 0);      // Creates foo_0: return inval (no add!)
    *outval2 = foo(inval2, 1);      // Creates foo_1: return inval + 1
    *outval3 = foo(inval3, 100);    // Creates foo_100: return inval + 100
}

What Happens

Call Site Instance Created Optimization
foo(inval1, 0) foo_0 return inval + 0 → return inval (no adder)
foo(inval2, 1) foo_1 return inval + 1 (simple increment)
foo(inval3, 100) foo_100 return inval + 100 (constant add)

Why INLINE OFF is Required

// WITHOUT INLINE OFF - function is merged into caller
char foo(char inval, char incr) {
#pragma HLS FUNCTION_INSTANTIATE variable=incr  // NO EFFECT!
    return inval + incr;
}
// foo() is inlined → no separate function exists → nothing to instantiate

// WITH INLINE OFF - function stays separate
char foo(char inval, char incr) {
#pragma HLS INLINE OFF                          // Keeps foo() separate
#pragma HLS FUNCTION_INSTANTIATE variable=incr  // Now works!
    return inval + incr;
}

Optimization Benefits

1. Constant Propagation

Each instance knows its parameter at compile time:

// Original: return x + incr;

// foo_0:   return x + 0;  → return x;      // No adder needed!
// foo_1:   return x + 1;  → return x + 1;  // Simple increment
// foo_100: return x + 100; → return x + 100; // Constant adder

2. Parallel Execution

Separate instances can run concurrently:

void top(...) {
    *out1 = foo(in1, 0);    // Instance 1 ─┐
    *out2 = foo(in2, 1);    // Instance 2 ─┼─► Can execute in parallel
    *out3 = foo(in3, 100);  // Instance 3 ─┘
}

3. Dead Code Elimination

Mode flags enable branch removal:

data_t compute(data_t x, int mode) {
#pragma HLS INLINE OFF
#pragma HLS FUNCTION_INSTANTIATE variable=mode
    if (mode == 0) return x;
    else if (mode == 1) return x + 1;
    else return x * 2;
}

// compute_0: only "return x" remains (other branches eliminated)
// compute_1: only "return x + 1" remains
// compute_2: only "return x * 2" remains

Code Generation Guidelines

Function Template

ReturnType func(InputType inval, ConstType param) {
#pragma HLS INLINE OFF
#pragma HLS FUNCTION_INSTANTIATE variable=param
    // param is compile-time constant in each instance
    return compute(inval, param);
}

Caller Template

void top(...) {
    *out1 = func(in1, CONST_A);  // Instance for CONST_A
    *out2 = func(in2, CONST_B);  // Instance for CONST_B
    *out3 = func(in3, CONST_C);  // Instance for CONST_C
}

Key Constraints

Constraint Requirement
INLINE OFF Must be specified (otherwise pragma has no effect)
Constant parameter Must be compile-time constant at each call site
Resource cost N unique values = N hardware instances

Good Candidates for FUNCTION_INSTANTIATE

Shift Amounts

data_t shift_func(data_t x, int amount) {
#pragma HLS INLINE OFF
#pragma HLS FUNCTION_INSTANTIATE variable=amount
    return x >> amount;
}
// Compile-time shift → fixed wiring, no barrel shifter

Array Sizes

void process(data_t* in, data_t* out, int size) {
#pragma HLS INLINE OFF
#pragma HLS FUNCTION_INSTANTIATE variable=size
    for (int i = 0; i < size; i++)
#pragma HLS UNROLL
        out[i] = in[i] * 2;
}
// Compile-time size → loop can be fully unrolled

Mode Flags

data_t compute(data_t x, int mode) {
#pragma HLS INLINE OFF
#pragma HLS FUNCTION_INSTANTIATE variable=mode
    switch(mode) {
        case 0: return x;
        case 1: return x + 1;
        case 2: return x * 2;
    }
}
// Compile-time mode → dead code elimination

Test Bench Generation Guidelines

Test Bench Template

#include "example.h"
#include <iostream>
using namespace std;

int main() {
    char in1 = 10, in2 = 20, in3 = 30;
    char out1, out2, out3;

    // Call DUT
    top(in1, in2, in3, &out1, &out2, &out3);

    // Verify
    bool pass = true;
    if (out1 != in1 + 0) { cout << "out1 mismatch" << endl; pass = false; }
    if (out2 != in2 + 1) { cout << "out2 mismatch" << endl; pass = false; }
    if (out3 != in3 + 100) { cout << "out3 mismatch" << endl; pass = false; }

    cout << (pass ? "Test PASSED" : "Test FAILED") << endl;
    return pass ? 0 : 1;
}

Optimization Guidance for Agents

When to Apply This Pattern

Decision tree:
├── Function called multiple times?
│   ├── Yes → With different constant parameters?
│   │         ├── Yes → Would constant propagation help?
│   │         │         ├── Yes → Can afford N instances?
│   │         │         │         ├── Yes → Use FUNCTION_INSTANTIATE + INLINE OFF
│   │         │         │         └── No → Share single instance
│   │         │         └── No → Don't need FUNCTION_INSTANTIATE
│   │         └── No (same params) → Share single instance
│   └── No → Don't need FUNCTION_INSTANTIATE

Without vs With Comparison

Aspect Without With FUNCTION_INSTANTIATE
Instances 1 shared N separate (per unique value)
Parameter Runtime variable Compile-time constant
Optimization Generic Specialized per value
Resources 1× N× (but each simpler)
Execution Sequential Can be parallel

Performance Trade-offs

Choice Benefit Cost
Use FUNCTION_INSTANTIATE Constant propagation, parallelism More hardware instances
Don't use Resource sharing Generic hardware, sequential

Common Pitfalls

Pitfall Symptom Solution
Missing INLINE OFF Pragma has no effect Add #pragma HLS INLINE OFF
Too many unique values High resource usage Limit values or share some
Runtime parameter No optimization benefit Ensure constants at call sites
