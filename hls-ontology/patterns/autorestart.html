Autorestart Pattern

The autorestart pattern enables a kernel to run continuously without host intervention, automatically restarting after each completion. This is ideal for real-time streaming applications.

Key Pragma

#pragma HLS INTERFACE s_axilite port=return autorestart
Parameter Meaning
s_axilite AXI4-Lite slave interface (register-based control)
port=return Applies to block-level control (start/done/idle signals)
autorestart Kernel restarts automatically after completion

Normal vs Autorestart Execution

Normal Mode (without autorestart)

Host: START=1 → Kernel runs → DONE=1 → IDLE=1 (stops)
                                         ↓
                         Host must write START=1 again

Autorestart Mode

Host: START=1 → Kernel runs → DONE=1 → Kernel restarts → DONE=1 → ...
                                  ↓           ↓              ↓
                            (DONE pulses) (continuous)  (runs forever)

Complete Example

From Vitis-HLS-Introductory-Examples/Task_level_Parallelism/Control_driven/Channels/autorestart/diamond.cpp:

#include "diamond.h"

void diamond(data_t vecIn[N], data_t vecOut[N]) {
    data_t c1[N], c2[N], c3[N], c4[N];

#pragma HLS dataflow
#pragma HLS INTERFACE s_axilite port=return autorestart

    funcA(vecIn, c1, c2);
    funcB(c1, c3);
    funcC(c2, c4);
    funcD(c3, c4, vecOut);
}

void funcA(data_t* in, data_t* out1, data_t* out2) {
Loop0:
    for (int i = 0; i < N; i++) {
#pragma HLS pipeline rewind
#pragma HLS unroll factor = 2
        data_t t = in[i] * 3;
        out1[i] = t;
        out2[i] = t;
    }
}
// ... funcB, funcC, funcD similar

Dataflow Diamond Topology

              ┌────────┐
   vecIn ────►│ funcA  │
              │  (×3)  │
              └───┬────┘
                  │
         ┌───────┴───────┐
         ▼               ▼
    ┌────────┐      ┌────────┐
    │ funcB  │      │ funcC  │
    │ (+25)  │      │  (×2)  │
    └───┬────┘      └───┬────┘
         │               │
         └───────┬───────┘
                 ▼
            ┌────────┐
            │ funcD  │────► vecOut
            │(+, ×2) │
            └────────┘

Pipeline Rewind

#pragma HLS pipeline rewind

Used inside each function's loop. Without rewind, the pipeline drains (flushes) between kernel invocations. With rewind:

  • Pipeline immediately restarts from iteration 0
  • No flush cycles wasted
  • Better throughput for continuous operation

Timing Comparison

Mode Execution Pattern
Without rewind Run → Drain → Run → Drain → ...
With rewind Run → Run → Run → ... (continuous)

Channel Type: PIPO (Default)

The arrays c1[N], c2[N], c3[N], c4[N] become Ping-Pong buffers (PIPOs) because:

  • They are declared as arrays
  • No #pragma HLS STREAM is applied
  • PIPO is the default channel type for arrays in dataflow
Iteration 1:  funcA writes to PING  │  funcB reads from PONG (previous)
Iteration 2:  funcA writes to PONG  │  funcB reads from PING
Iteration 3:  funcA writes to PING  │  funcB reads from PONG
...

When to Use Autorestart

Scenario Use Autorestart?
Continuous data stream (video, audio, sensor) Yes
Real-time processing with strict latency Yes
One-shot batch computation No
Host needs to control each invocation No
Processing finite dataset once No

Block Control Registers

When using s_axilite port=return, the kernel exposes these registers:

Register Normal Mode Autorestart Mode
ap_start Host writes 1 to start Host writes 1 once to start forever
ap_done High when complete, stays high Pulses high after each iteration
ap_idle High when idle Briefly high between iterations
ap_ready High when ready for input Pulses with ap_done

Combining with Other Pragmas

Best results when combined with:

Pragma Purpose
#pragma HLS DATAFLOW Enable parallel function execution
#pragma HLS pipeline rewind Continuous loop execution
#pragma HLS unroll factor=N Parallel processing within loops

Code Generation Guidelines

Autorestart Kernel Template

void kernel_name(input_type* input, output_type* output, int size) {
    // Channel declarations (arrays become PIPOs by default)
    data_t c1[N], c2[N], ...;

#pragma HLS dataflow
#pragma HLS INTERFACE s_axilite port=return autorestart

    // Memory interfaces for input/output
#pragma HLS INTERFACE m_axi port=input depth=<size>
#pragma HLS INTERFACE m_axi port=output depth=<size>

    stage1(input, c1);
    stage2(c1, c2);
    // ... more stages
    stageN(cN, output);
}

Stage Function Template

void stage_func(data_t* in, data_t* out) {
#pragma HLS inline off          // Required for dataflow
Loop:
    for (int i = 0; i < N; i++) {
#pragma HLS pipeline rewind     // Continuous execution
#pragma HLS unroll factor=<F>   // Optional parallelism
        out[i] = process(in[i]);
    }
}

Key Constraints

Constraint Requirement
Block control Must use port=return with autorestart
Dataflow Combine with #pragma HLS dataflow for pipelined stages
Loop pragma Use pipeline rewind in stage loops
Function inlining Use #pragma HLS inline off on stage functions

Test Bench Generation Guidelines

Autorestart Test Bench Template

The autorestart pattern requires a special test bench using hls::autorestart helper:

#include "diamond.h"
#include <iostream>
#include <fstream>
#include "hls_task.h"
using namespace std;

int main() {
    // Allocate N * NUM_ITERATIONS for continuous operation
    data_t test[N * 3];
    data_t outcome[N * 3];
    int retval = 0;
    ofstream FILE;

    // Initialize all iterations' data
    for (int i = 0; i < N * 3; i++) {
        test[i] = (data_t)i;
    }

    FILE.open("result.dat");

    // Use hls::autorestart helper - runs kernel NUM_ITER times
    hls::autorestart run_top(3, diamond, test, outcome);

    // Capture outputs
    for (int i = 0; i < N; i++) {
        FILE << (int)outcome[i] << endl;
    }
    FILE.close();

    // Verify against golden
    retval = system("diff --brief -w result.dat result.golden.dat");
    if (retval != 0) {
        cout << "Test failed!" << endl;
        return 1;
    }
    cout << "Test passed!" << endl;
    return 0;
}

Key Differences from Standard Test Bench

Aspect Standard Autorestart
Header None special #include "hls_task.h"
Buffer size N elements N * NUM_ITER elements
Execution Loop with multiple calls Single hls::autorestart call
Iteration control Explicit for loop Helper manages iterations

hls::autorestart Syntax

hls::autorestart run_top(NUM_ITERATIONS, kernel_function, arg1, arg2, ...);
Parameter Description
NUM_ITERATIONS Number of times to run the kernel
kernel_function The top-level function name
arg1, arg2, ... Kernel arguments (must be pre-allocated for all iterations)

Test Bench Requirements

Requirement Details
Include hls_task.h Required for hls::autorestart helper
Pre-allocate buffers Size = N * NUM_ITERATIONS
Single autorestart call Replaces explicit iteration loop
Continuous data Input data must be ready for all iterations

Optimization Guidance for Agents

When to Apply Autorestart

Decision tree:
├── Is this a streaming/continuous processing application?
│   ├── Yes → Use autorestart
│   └── No → Don't use autorestart
├── Does the kernel need to run indefinitely?
│   ├── Yes → Use autorestart
│   └── No → Standard kernel
└── Is low-latency between iterations important?
    ├── Yes → Use autorestart + pipeline rewind
    └── No → Standard kernel may suffice

Performance Optimization

Optimization How to Apply
Eliminate pipeline flush Add rewind to all stage loops
Increase parallelism Add unroll factor=N to loops
Overlap memory access Use separate m_axi bundles for input/output
Reduce iteration overhead Use PIPO channels (default) for block-level sync

Resource vs Performance Trade-offs

Choice Impact
Higher unroll factor More parallelism, more LUTs/FFs
FIFO vs PIPO channels FIFO: less memory, stricter access; PIPO: more memory, flexible access
Pipeline rewind Slightly more logic, eliminates flush latency

Common Pitfalls

Pitfall Solution
Forgetting inline off Add #pragma HLS inline off to all stage functions
Missing rewind Add to all loops for continuous operation
Deadlock from mismatched counts Ensure producer/consumer element counts match
Blocking on empty input Ensure continuous data source for autorestart
